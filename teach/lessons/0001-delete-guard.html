What it is

Blast Radius watches Claude's Bash calls. When a command is risky, such as rm -rf, git reset --hard, git clean, a force push or a database migration, it holds the call and works out what the command would change. A pane lists that change with two buttons: Proceed runs the command, and Cancel refuses it and tells Claude why.

It matters for your mission because it shows, in one file, three patterns you will need to explain in your README: holding a tool.call until a person answers, drawing in a Pane or the band above the prompt, and measuring with $.process.run.

How it was built

Blast Radius is one plain JavaScript file, hooks/blast-radius.mjs, about 530 lines. It uses two events, tool.call and ui.render. Its calls are $.session.cwd, $.process.run, $.clock.now, $.ui.open, $.ui.close, $.ui.invalidate, $.ui.resolve and $.ui.toast. It does not call a model.

1. Hook Bash and classify the command

The tool.call hook is filtered to the Bash tool. It passes the command text to classify. If that returns null, the call goes on at once with next(e).

export function register(on) {
  on("tool.call", { tool: "Bash" }, async ($, e, next) => {
    const risk = classify(String(e.command ?? ""));
    if (risk === null) {
      return next(e);
    }

classify splits the command line on &&, ||, ;, | and new lines. It returns the first risky part. On the way it follows cd, pushd, popd and git -C, so it knows which folder to measure. A cd inside ( ... ) is dropped when the brackets close. For each part, classifySegment strips a leading VAR=value, sudo and its options, words such as command, env, time and then, and nice. Then it reads the first word. An rm is risky only with a recursive or force flag:

    if (cmd === "rm" || cmd.endsWith("/rm")) {
      const flags = args.filter((a) => a.startsWith("-"));
      const recursive = flags.some((f) => f === "--recursive" || (/^-[^-]/.test(f) && /[rR]/.test(f)));
      const force = flags.some((f) => f === "--force" || (/^-[^-]/.test(f) && f.includes("f")));
      if (recursive || force) {
        const targets = args.filter((a) => !a.startsWith("-") || a === "-");
        return { kind: "rm", label: `rm ${flags.join(" ")}`.trim(), targets, dir };
      }
    }

The same function catches git reset --hard, git clean, git push with --force, -f, --force-with-lease or a +ref, and git checkout or git restore with .. It also catches alembic upgrade, db:migrate, prisma migrate, manage.py migrate, and any other command with a migrate argument that is not on a short read-only list.

It splits text, not shell grammar. The split runs on the raw command line, before quotes are read. So a commit message that contains ; rm -rf is held too. The README lists this as a known harmless false alarm. A backslash in front, as in \rm, is removed, because the code treats it as "still rm".
Why every call is spelled out. The comment at the top of the file says the host reads on(...) and $.noun.method(...) from the source. So they are written literally, and helpers that take $, such as measure, are top-level functions.

2. Hold the call with short sleeps until a button is pressed

A risky call claims the module-level held slot and then waits in a loop. Each turn of the loop checks three things: did the turn get interrupted, has the 10-minute limit passed, and has a button set the decision. Between checks it runs sleep 0.25 as a child process. POLL_SECONDS is "0.25" and HOLD_LIMIT_MS is 10 * 60 * 1000.

      const startedAt = await $.clock.now();
      while (mine.decision === null) {
        if (next.signal.aborted) {
          mine.decision = "interrupted";
          break;
        }
        if ((await $.clock.now()) - startedAt > HOLD_LIMIT_MS) {
          mine.decision = "timeout";
          break;
        }
        await $.process.run(["sleep", POLL_SECONDS], { timeoutMs: 5000 });
      }
Why sleep in a child process? A hook has 10 seconds of its own time per dispatch (HookBudget, ms: 10_000 in the API types). Past that, the hook is treated as absent. The types also say the clock stops while a $ call is in flight, with one exception: a $.clock wait still runs on the budget. So $.clock.sleep would use up the 10 seconds, but $.process.run(["sleep", ...]) costs the hook nothing. That is how it can wait 10 minutes for you.
One hold at a time. If a second risky call arrives, from a subagent for example, it loops on the same short sleep until held is free. The comment says held is claimed with no await between the check and the claim, so two waiting calls can't both get through.

3. Measure the blast radius with scripts that take paths as arguments

Before the pane opens, measure works out the change. It picks one of three helpers: measureRm, measureGit or measureMigrations. For rm, a fixed bash script expands globs and ~, counts files with find, and sums sizes with du -skc. The paths go in as arguments after the script, never as part of it.

// The paths are passed to bash as arguments, never as source, so nothing in
// them runs. compgen -G expands a glob without command substitution.
const RM_SCRIPT = `
shopt -s nullglob dotglob
paths=()
for p in "$@"; do
  case "$p" in "~"|"~/"*) p="$HOME\${p#\\~}";; esac
  if [[ "$p" == *[*?[]* ]]; then
    while IFS= read -r m; do paths+=("$m"); done < <(compgen -G "$p")
  elif [[ -e "$p" || -L "$p" ]]; then
    paths+=("$p")
  fi
done
if (( \${#paths[@]} == 0 )); then echo "0 0 0"; exit 0; fi
# A relative path gets ./ in front, so find never reads a name like -delete as an action.
for i in "\${!paths[@]}"; do case "\${paths[$i]}" in /*) ;; *) paths[$i]="./\${paths[$i]}";; esac; done
files=$(find "\${paths[@]}" \\( -type f -o -type l \\) 2>/dev/null | wc -l | tr -d ' ')
kb=$(du -skc "\${paths[@]}" 2>/dev/null | tail -n1 | cut -f1)
echo "$files $(( \${kb:-0} * 1024 )) \${#paths[@]}"
find "\${paths[@]}" \\( -type f -o -type l \\) 2>/dev/null | head -n ${LIST_MAX}
`;

async function measureRm($, risk, cwd) {
  if (risk.targets.length === 0) {
    return { summary: "rm with no paths", lines: [], note: "No paths to expand." };
  }
  const run = await $.process.run(["bash", "-c", RM_SCRIPT, "blast-radius", ...risk.targets], { cwd, timeoutMs: 15000 });

The git checks only read. git clean is dry-run as git clean -n with the same flags, minus -f, -i and -q. git reset --hard and git checkout -- . read git status --porcelain and git diff --shortstat. A force push reads git log for the commits on the remote branch that your side lacks, as of the last fetch. Migrations run the tool's own status command, such as python3 manage.py showmigrations --plan. The folder comes from $.session.cwd(), moved by any cd the classifier saw. The same arguments-not-source rule is used to resolve that folder.

Found in review. The ./ in front of relative paths was added after an independent review. Without it, a file named like a find action, such as -delete, could be read as that action while measuring. measure never throws: a failed read becomes a note in the pane, and the command is still held.

4. Show the pane, or the band on a narrow terminal

The hook opens a pane with $.ui.open. If the surface does not place it, isPlaced is false, and the mod marks the report for the band above the prompt. Then it asks for a redraw.

      opened = await $.ui.open({ id: PANE_ID, title: "Blast Radius", focus: true, rows: paneRows(mine.report) });
      if (!opened.isPlaced) {
        mine.where = "band";
      }
      $.ui.invalidate("ui.render");

Two ui.render hooks draw the same report with the same draw function. One is for the Pane with id blast-radius. The other is for AbovePrompt, and it only draws when the report is marked for the band:

  on("ui.render", { component: "AbovePrompt" }, ($, e, next) => {
    if (held === null || held.report === null || held.where !== "band") {
      return next(e);
    }
    return draw($.ui.resolve(e), held);
  });

draw shows the command, the summary in red, up to 10 lines from the list, a note, and the two buttons:

      Box({
        key: "buttons",
        marginTop: 1,
        gap: 2,
        children: [
          Button({ key: "proceed", label: "Proceed", hotkey: "1", plain: true, onPress: decide("proceed") }),
          Button({ key: "cancel", label: "Cancel", hotkey: "2", plain: true, autoFocus: true, onPress: decide("cancel") }),
          Text({ key: "hint", dimColor: true, children: "Claude is waiting on your answer" }),
        ],
      }),
Three small choices in the drawing. (1) Cancel has autoFocus, so pressing Enter by reflex refuses the command. (2) decide sets the decision on the state the pane was drawn for, and only if it is still null. The comment says the buttons answer that call, "never whichever one is held now". (3) The API types say a pane opened without your asking is placed from 144 columns. The README says to use a terminal about 144 columns wide for the pane.

5. Refuse with a reason on cancel, timeout or error

After the loop, a finally block closes the pane and frees held. Anything unexpected while holding lands in a catch that sets the decision to "error". Only "proceed" runs the command. Every other outcome returns a deny.

    if (decision === "proceed") {
      $.ui.toast("Blast Radius: running it");
      return next(e);
    }
    const why = {
      cancel: "the user pressed Cancel",
      timeout: "no answer within 10 minutes",
      interrupted: "the turn was interrupted",
      error: "Blast Radius hit an error while holding it",
    }[decision] ?? "no answer was recorded";
    return {
      deny: `Blast Radius held this command and did not run it: ${why}. It would have: ${summary}. Do not retry it unless the user asks you to.`,
    };

The API types say the model receives a deny text as an error result. So Claude learns what was refused, why, and what it would have changed. The last sentence asks it not to try again on its own.

The pane closes before the hold is freed. The comment says this order means the next call's pane can't be the one that gets closed.
Blast Radius and delete-backup. Blast Radius asks before a delete. Delete-backup keeps a copy, so a delete can be undone with /undo-delete. Both hook tool.call on Bash, so both can run together. They also differ in scope. Blast Radius holds an rm only with a recursive or force flag, and it also covers git and migrations. Delete-backup copies the targets of any rm. Blast Radius keeps no copy: after Proceed, the files are gone.

How to use it

Install Anthropic's sample from a local copy of the mods folder. On this Mac the copy is /Users/igorwaraxe/Downloads/claude-code-playground-mods.

claude plugin marketplace add <path to the copied mods folder>
claude plugin install blast-radius@claude-code-playground-mods

The README adds --scope user to the install line. It removes the mod with claude plugin uninstall blast-radius@claude-code-playground-mods --scope user. To check the plugin, run claude plugin validate ./blast-radius from the mods folder.

  • In a throwaway repo, ask Claude to run something risky. The README's example is "delete the build folder with rm -rf build".
  • Claude's Bash call is held. A pane titled Blast Radius shows the command, what it would do (for example, the file count and size), and up to 10 files. On a narrower terminal the same report is in the band above the prompt.
  • Press 1 for Proceed or 2 for Cancel. You can also click a button, or Tab to it and press Enter. In the band, 1 or 2 works while the input is empty.
  • Proceed shows the toast "Blast Radius: running it", and the command runs as written. Cancel refuses it, and Claude reads the reason.
  • If nobody answers within 10 minutes, or you interrupt the turn with Esc, the command is refused.

Cost. No model calls and no tokens. Each risky command costs a few read-only commands: bash with find and du for an rm, or git status, git diff, git clean -n, git rev-parse and git log for git. While a call is held, it starts sleep 0.25 about four times a second. A very large tree can take a few seconds to measure. For migrations it runs the project's own status command, which loads your project's code before you choose.

Limits, from the README.

  • It does not parse shell fully. $(...), aliases, eval, bash -c "...", xargs rm, find -delete, scripts that call rm, and wrappers such as timeout 5 rm or env -i rm are not caught.
  • Only the first risky part of a line is measured. Proceed runs the whole line as written.
  • cd -, and a folder that does not exist, can't be measured. The pane says so and still holds the command.
  • The band can be used by only one mod at a time. If another mod takes it, such as Replay Theater or Token Weather, the buttons may not show, and the command is refused after 10 minutes. Use a wider terminal, or turn the other mod off.
  • It only watches the Bash tool. File edits and other tools are not held.
  • The rm count is approximate, and the list shows the first 10 files. The force-push list uses your last fetch, and assumes origin when no remote is named.
  • It holds a call, but it doesn't sandbox it. It is a safety net, not a permission system. Use permission rules for a hard block.

Check yourself

Why does the hold loop run $.process.run(["sleep", "0.25"]) instead of $.clock.sleep?

A hook has 10 seconds of its own time per dispatch. The clock stops while a $ call is in flight, except for a $.clock wait, which still uses the budget. A sleep in a child process is a $.process.run call, so it is free. That lets the hook wait up to its own 10-minute limit for your answer.

The pane opens and you press Enter by reflex. What happens, and what does Claude read?

Cancel has autoFocus, so Enter presses Cancel. The decision becomes "cancel", and the hook returns a deny: "Blast Radius held this command and did not run it: the user pressed Cancel. It would have: …" followed by the summary and "Do not retry it unless the user asks you to." The model receives it as an error result, and nothing is deleted.
