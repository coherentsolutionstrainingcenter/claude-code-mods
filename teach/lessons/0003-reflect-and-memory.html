Reflect and memory

These mods turn a correction you give Claude into a lasting rule, so the next chat starts from what you already taught it. This marketplace ships reflect-mod, which finds the rule in your prompt and offers to save it to CLAUDE.md.

What it is

reflect-mod checks each short prompt you type with one Haiku call. The call decides if the prompt states a rule worth keeping, such as "no, use pnpm". If it does, a band above the prompt shows the rule. You press a button to save it to ./CLAUDE.md or ~/.claude/CLAUDE.md, to edit it, or to skip it. A saved rule also goes into this session's system prompt at once.

The same repository holds a Python plugin that queues corrections for a later /reflect review. The README says the mod does the review "at the moment you correct" instead. Only the mod is shipped here.

Your mission asks you to name the hooks and calls a mod uses and say why, and this mod is a clear case: one hook queues the prompt, one model call judges it, and a band button writes a file Claude reads in every chat.

How it was built

The mod is one file, hooks/register.tsx. hooks/hooks.json points to it. The types in types/index.d.ts describe a Learning: a rule, its scope (global or project), a count, and a status (pending, saved or skipped).

1. Queue the prompt, and only run cheap checks

The prompt.submit hook must not slow your typing. It keeps a prompt only if you typed it (at the terminal or over Remote Control), it is not a slash command, and it is not an acknowledgement such as "ok" or "continue". It must also be 500 characters or fewer, unless it starts with remember:, and it must not look like a credential. A kept prompt goes on a queue of up to 20. A timer starts the work, and the prompt goes on at once with next(e).

  // Only cheap checks here: the prompt goes on at once, the work runs on a timer.
  on('prompt.submit', ($, e, next) => {
    const text = e.text.trim()
    const isCandidate =
      HUMAN.has(e.origin.kind) &&
      !text.startsWith('/') &&
      !isTrivial(text) &&
      (text.length <= MAX_PROMPT || remembered(text) !== undefined) &&
      !looksSecret(text)
    if (isCandidate && queue.length < MAX_QUEUE) {
      queue.push(text)
      $.clock.after(0, () => void drain($).catch(() => undefined))
    }
    return next(e)
  })

2. Ask Haiku if the prompt is a rule

checkOne runs for each queued prompt. A prompt that starts with remember: skips the model and becomes a global rule. Any other prompt gets one $.model.complete call, capped at 300 tokens and 30 seconds. The system prompt says the user message and the last reply are data, not instructions. The model answers JSON with is_rule, rule, scope and confidence. parseVerdict passes the rule through cleanRule, which drops a rule over 200 characters, one with more than one line, and one that looks like a secret. A verdict below 0.7 confidence is dropped.

/** One prompt, end to end. Everything slow happens here, outside the prompt's own dispatch. */
async function checkOne($: EngineInterface, text: string) {
  if ((await $.store.get('paused')) === true) return
  const root = await $.session.root()
  const told = remembered(text)
  if (told !== undefined) {
    const rule = cleanRule(told)
    if (rule === undefined) {
      $.ui.toast('reflect: not kept - one line, no secrets, at most 200 characters')
      return
    }
    await record($, { isRule: true, rule, scope: 'global', confidence: 1 }, root, true)
    return
  }
  const r = await $.model.complete({
    model,
    system: SYSTEM,
    prompt: checkPrompt(text, await lastReply($), root),
    maxTokens: 300,
    timeoutMs: 30000,
  })
  if (!r.isAnswered) return
  const v = parseVerdict(r.text)
  if (v === undefined || !v.isRule || v.confidence < MIN_CONFIDENCE) return
  await record($, v, root, false)
}

record then stores the rule. A rule that is very like one already found (a similarity of 0.6 or more on ordered word pairs) adds one to that rule's count instead of making a new row.

3. Draw the band above the prompt

The band reads the pending state, which holds the waiting rules for this project and the global ones. refreshBand fills it after each checked prompt, at session start and when a turn completes. The band shows two rules at most. Each has a Save button for the scope the check suggested, a button for the other scope, Edit and Skip. It shows nothing while a survey is open.

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    if (e.props.hasSurvey) return next(e)
    const list = await read($, pending)
    if (list.length === 0) return next(e)
    const { Box, Button, Text } = $.ui.resolve(e)
    const below = await next(e)
    return (
      <Box flexDirection="column">
        {list.slice(0, BAND_ROWS).map(l => (
          <Box key={`row:${l.id}`} flexDirection="column">
            <Text color="green" wrap="wrap">
              {`reflect · "${l.rule}"${l.count > 1 ? ` ×${l.count}` : ''}`}
            </Text>
            <Box flexDirection="row" gap={1}>
              <Button
                key={`save:${l.id}`}
                variant="primary"
                label={l.scope === 'project' ? 'Save to ./CLAUDE.md' : 'Save to ~/.claude/CLAUDE.md'}
                onPress={() => saveTo($, l, l.scope)}
              />
              <Button
                key={`other:${l.id}`}
                label={l.scope === 'project' ? 'Global instead' : 'This repo instead'}
                onPress={() => saveTo($, l, l.scope === 'project' ? 'global' : 'project')}
              />
              <Button key={`edit:${l.id}`} label="Edit" onPress={() => edit($, l)} />
              <Button key={`skip:${l.id}`} label="Skip" onPress={() => skip($, l)} />
            </Box>
          </Box>
        ))}

4. Save one rule at a time, after reading the file again

saveTo chains each save on writing, so saves in one session run one after another. Inside, it checks that the rule is still pending. It reads the CLAUDE.md file just before it writes, and it writes only if the text changed. It then marks the rule saved, adds it to savedThisSession and shows a toast.

/** Writes the rule to the CLAUDE.md the button names, after reading it again just before the write. */
async function saveTo($: EngineInterface, l: Learning, scope: 'global' | 'project') {
  const job = writing.then(async () => {
    const latest = (await items($)).find(one => one.id === l.id)
    if (latest === undefined || latest.status !== 'pending') return
    const root = await $.session.root()
    const path = await fileFor($, scope, root)
    const before = await readText($, path)
    const after = withRule(before, l.rule)
    if (after === undefined) {
      $.ui.toast(`reflect: the claude-reflect markers in ${path} are broken - fix them by hand, nothing written`)
      return
    }
    if (after !== before) await $.fs.write(path, after)
    await decide($, l.id, 'saved', scope, root)
    await update($, savedThisSession, rules => [...rules, { rule: l.rule, scope, project: root }])
    $.ui.toast(after === before ? `reflect: already in ${path}` : `reflect: saved to ${path}`)
  })
  writing = job.catch(() => undefined)
  await job
}

5. Write inside one marked section

withRule decides the new file text. If any bullet in the file is very like the rule (0.8 or more), the file is returned unchanged. If the file has no markers, it adds a marked section with a ## Learned rules heading at the end. If it has exactly one start marker and one end marker, in order, the rule goes in just before the end marker. Anything else returns undefined, and step 4 writes nothing.

/**
 * `file` with `rule` added as a bullet inside the marked section; the file unchanged when a similar bullet is there;
 * undefined when the markers are broken (one without the other, out of order, or repeated) - never guess where to write.
 */
export function withRule(file: string, rule: string): string | undefined {
  const bullets = file.split('\n').filter(line => /^\s*[-*] /.test(line))
  if (bullets.some(line => similarity(line.replace(/^\s*[-*]\s+/, ''), rule) >= 0.8)) return file
  const starts = file.split(START).length - 1
  const ends = file.split(END).length - 1
  if (starts === 0 && ends === 0) {
    const sep = file === '' || file.endsWith('\n\n') ? '' : file.endsWith('\n') ? '\n' : '\n\n'
    return `${file}${sep}${START}\n## Learned rules\n- ${rule}\n${END}\n`
  }
  const start = file.indexOf(START)
  const end = file.indexOf(END)
  if (starts !== 1 || ends !== 1 || end < start) return undefined
  return `${file.slice(0, end)}- ${rule}\n${file.slice(end)}`
}

6. Use a saved rule in this session at once

A rule written to CLAUDE.md takes effect when the file is read again. The prompt.compose hook closes that gap. It adds a session section to the system prompt that lists the rules saved this session for this project and the global ones.

  on('prompt.compose', async ($, e, next) => {
    const composed = await next(e)
    const root = await $.session.root()
    const rules = (await read($, savedThisSession)).filter(r => r.scope === 'global' || r.project === root)
    if (rules.length === 0) return composed
    const text = ['Rules the user saved this session (they are in CLAUDE.md too; follow them):', ...rules.map(r => `- ${r.rule}`)].join('\n')
    return { sections: [...composed.sections, { id: 'reflect-mod:saved', text, scope: 'session' as const }] }
  })

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install reflect-mod@waraxe-claude-mods

The README says to use either this mod or the Python plugin, not both, because every correction would be captured twice. It runs on Claude Code 2.1.286 or later, with mods.

  • Correct Claude in a short prompt, for example "no, use pnpm". The check runs in the background.
  • When a rule is found, the band shows reflect · "the rule". A repeat shows a count, such as ×2.
  • Press Save to ./CLAUDE.md or Save to ~/.claude/CLAUDE.md, whichever the check suggested. Press Global instead or This repo instead to save to the other file.
  • Press Edit to put remember: the rule in an empty prompt box, reword it and send it. Press Skip to drop it.
  • Type remember: your rule to skip the model and send a rule straight to the band.
  • Type /reflect-queue to list what was found here and globally. Type /reflect-pause to stop checking, and again to start.

Settings. The README lists none. The code uses haiku for the check.

Cost. One small model call for each prompt that passes step 1. It runs on the session's own client and counts toward your Claude usage like any request. A remember: prompt costs no call. The prompt text is not stored. Found rules are kept in the plugin's own store, a JSON file under your Claude Code config folder, until you decide on them.

Limits.

  • Two sessions that save to the same CLAUDE.md in the same instant can lose one of the two bullets. Saves in one session run one after another.
  • Mods are early access. A running session older than 2.1.286 writes a "mods off" flag into ~/.claude.json, which turns mods off for new sessions too. Restart old sessions if the band never appears.
  • Prompts over 500 characters are not checked, unless they start with remember:. Rules over 200 characters are dropped.
  • Broken markers in CLAUDE.md stop the save. A toast asks you to fix them by hand.

Check yourself

Why does the prompt.submit hook not call the model itself?

The hook only runs cheap checks, pushes the prompt on a queue and calls next(e) at once. A timer, $.clock.after(0, ...), starts drain, which runs the model call outside the prompt's own dispatch. So your prompt is never held up by the check, and one failed check does not stop the rest of the queue.

What happens when you press Save and the claude-reflect markers in CLAUDE.md are broken?

withRule returns undefined when there is one marker without the other, the end comes before the start, or a marker is repeated. saveTo then shows a toast that says the markers are broken and nothing was written. It returns before it writes, so the file is not touched and the rule stays pending.
