What it is

effort-picker reads each message you type and checks four rules in order, stopping at the first match. A long job you hand off ("overnight", "end to end", "the whole ...") gets xhigh, and "go all out" or a security audit gets max. A message where a hidden mistake could cost you gets high: money, a client, publishing, something hard to undo, or something broken. A short question or a small tweak gets low. Anything else keeps your own level.

The level holds for the model requests that answer that one message. A dim line in the transcript says what was picked and why, for example Effort picker: high for this message, up from medium: money is involved. The model never changes, because a switch in the middle of a chat makes Claude reread the whole chat.

It serves your mission because it shows which event can change a request on its way to the model, and why the obvious one, prompt.submit, cannot do it alone.

How it was built

The mod is one file, hooks/register.ts. The first question was where effort can be set. The input of prompt.submit carries the text, the context, the origin and the command, but no effort. The input of turn.step does: the engine raises it for each model request of a turn, and its doc says a hook rewrites model or effort going down. So the mod picks a level at prompt.submit, ties it to the turn at turn.start, and applies it at turn.step.

1. Pick a level from the words

The rules are one ordered list, and pickFor takes the first that matches. The order is the order of the four rules: long or all-out jobs, then costly mistakes, then quick back-and-forth. No match returns null, which is rule 4: your own level stays.

// Checked in order; the first match wins. No match is rule 4: the person's own level stays.
const RULES: readonly Rule[] = [
  { level: 'max', why: 'you asked to go all out', test: said => ALL_OUT.test(said) },
  { level: 'max', why: 'a security audit', test: said => SECURITY_AUDIT.test(said) },
  { level: 'xhigh', why: 'a long job handed off', test: said => HANDED_OFF.test(said) },
  { level: 'high', why: 'money is involved', test: said => MONEY.test(said) },
  { level: 'high', why: 'a client will see it', test: said => CLIENT.test(said) },
  { level: 'high', why: 'it gets published', test: said => PUBLISHING.test(said) },
  { level: 'high', why: 'it is hard to undo', test: said => HARD_TO_UNDO.test(said) },
  { level: 'high', why: 'something is broken', test: said => BROKEN.test(said) },
  { level: 'low', why: 'a short question', test: said => said.length <= 140 && (said.endsWith('?') || WH_QUESTION.test(said)) },
  { level: 'low', why: 'a small tweak', test: said => said.length <= 200 && TWEAK.test(said) },
]

/** The level a message asks for, and why; null leaves the person's own level. */
export function pickFor(text: string): Pick | null {
  const said = text.trim()
  const rule = said === '' ? undefined : RULES.find(one => one.test(said))

  return rule === undefined ? null : { level: rule.level, why: rule.why }
}

2. Hold the pick while the prompt enters

The prompt.submit hook leaves alone anything you did not type yourself, a slash command, a hidden (meta) prompt, and a message that starts with go:. Any other message with a pick goes into a short waiting list, which keeps the last five. After next(e), a dropped prompt loses its pick, and a prompt a hook beneath rewrote keeps its pick under the new text.

  on('prompt.submit', async ($, e, next) => {
    const isLeftAlone =
      !PERSON.has(e.origin.kind) || e.command !== undefined || e.isMeta === true || /^\s*go:/i.test(e.text)
    const mode = isLeftAlone ? 'off' : await modeOf($)
    const pick = mode === 'off' ? null : pickFor(e.text)
    if (pick === null) return next(e)

    const entry: Waiting = { text: e.text, pick, mode }
    waiting = [...waiting.slice(-4), entry]
    const result = await next(e)
    // A dropped prompt starts no turn; one a hook beneath rewrote starts its turn with the new text.
    waiting =
      result.drop !== undefined
        ? waiting.filter(one => one !== entry)
        : waiting.map(one => (one === entry ? { ...one, text: result.text } : one))

    return result
  })

3. Match the pick to its turn

turn.start gives the turn's id and the text it begins with. The hook looks only at the main chat (no agentId), finds the waiting pick with the same text, and binds it to this turn. A turn with no match binds nothing, so it keeps your level.

  on('turn.start', async ($, e, next) => {
    if (e.agentId === undefined) {
      const match = waiting.find(one => one.text === e.text)
      waiting = waiting.filter(one => one !== match)
      bound = match === undefined ? null : { turnId: e.turnId, pick: match.pick, mode: match.mode }
    }

    return next(e)
  })

4. Never lower xhigh or max

levelFor decides what to send. The same level is no change. A level of xhigh or max that you set yourself is never lowered, but a pick can still raise xhigh to max. Any other level can go up or down.

/** The level to send instead of `from`, or undefined to keep `from`. */
export function levelFor(from: ModelEffort, pick: ModelEffort): ModelEffort | undefined {
  if (pick === from) return undefined
  // A level the person set to xhigh or max is never lowered.
  if (RANK[from] >= RANK.xhigh && RANK[pick] < RANK[from]) return undefined

  return pick
}

5. Send each request of the turn with the level

turn.step streams, so the hook is an async generator and forwards the stream with yield*. It skips subagents, other turns, and an effort that is absent or a number. On the first request of the turn it writes the line with $.ui.log. In on mode it passes on a copy with the new effort. In tip mode it passes the request on unchanged. Nothing writes your saved setting.

  // Each model request of the turn: the main chat's alone, never a subagent's.
  on('turn.step', async function* ($, e, next) {
    const now = bound
    if (e.agentId !== undefined || now === null || now.turnId !== e.turnId || typeof e.effort !== 'string') {
      return yield* next(e)
    }

    const to = levelFor(e.effort, now.pick.level)
    if (to === undefined) return yield* next(e)
    if (e.index === 0) $.ui.log(lineFor(now.mode, e.effort, to, now.pick.why))

    // Only this request carries the new level; the saved setting is never written.
    return yield* next(now.mode === 'on' ? { ...e, effort: to } : e)
  })

6. One command, three modes

session.start registers /effort-picker, and a command.run hook answers it. The mode is kept in $.store, the mod's own store, so it holds across sessions. With nothing after the command, it says which mode is on.

  on('session.start', async ($, e, next) => {
    await $.command.register({
      name: 'effort-picker',
      description: 'Effort for each message: on, off or tip (suggest only)',
      argumentHint: 'on | off | tip',
    })

    return next(e)
  })

  on('command.run', { command: 'effort-picker' }, async ($, e) => {
    const asked = e.args.trim().toLowerCase()
    if (isMode(asked)) {
      await $.store.set('mode', asked)

      return { text: SAID[asked] }
    }

    return { text: `${SAID[await modeOf($)]} Use /effort-picker on, off or tip.` }
  })

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install effort-picker@waraxe-claude-mods
  • Type a message as you normally would. The picker sets the level for that message only, and a dim line says what it picked and why.
  • Type /effort-picker tip to see the picks without applying them.
  • Type /effort-picker off to stop it, and /effort-picker on to start it again. On is the default.
  • Start a message with go: to keep your own level for it.

Cost. The mod makes no model calls. It reads only your words. A higher level makes Claude think longer and uses more of your plan, and a lower level uses less. The mod does not measure how much.

Limits.

  • The rules are English word patterns. A message with none of the words keeps your level, and a word can match by accident. "error" in a short question gets high, because rule 2 comes before rule 3.
  • Only the main chat's requests change. Subagents keep their own effort.
  • A pick is matched to its turn by the message's text. A message typed while Claude works is picked only if it starts a turn of its own. A reload of the mod clears the picks, and the message then keeps your level.
  • A model with no effort setting, or an effort set as a number, is left alone. The engine may lower a level the model does not support.
  • Tip mode only shows the suggestion. It has no button to apply it.

Check yourself

Why does the mod need turn.step? Why can't the prompt.submit hook set the effort itself?

PromptSubmitInput has no effort field: a hook there can change the text and add context, nothing about the request. TurnStepInput carries effort for each model request, and a hook rewrites it with next({ ...e, effort: to }). So prompt.submit picks, turn.start ties the pick to the turn's id, and turn.step applies it.

Your own level is xhigh, and you type "what does this function return?". What effort is sent, and does a line appear?

Rule 3 picks low. levelFor('xhigh', 'low') returns undefined, because a level of xhigh or max is never lowered. The hook then returns yield* next(e) before it reaches $.ui.log, so the request goes at xhigh and no line appears.
