What it is

assumption-check reads Claude's last reply and lists up to five guesses that the reply made and you did not state, such as a default value or a file picked without asking. It checks only replies of 300 characters or more, and it asks Haiku for the list, so each check costs one small model call. You mark each guess Right or Wrong, and Send wrong to Claude submits the wrong ones as a new prompt.

It matters for your mission because it is the one place in this pair where a hook makes a model call, so you must be able to say when that call happens and what it costs.

How it was built

1. Declare the state type

The file types/index.d.ts adds one entry to the engine's PluginState. The manifest points at it with "types". The entry gives the state atom its type, so the list of guesses is typed as Assumption[].

export type Assumption = {
  /** The guess, in one short line. */
  text: string
  /** open until the person presses Right or Wrong. */
  verdict: 'open' | 'right' | 'wrong'
}

declare module 'claude-code' {
  interface PluginState {
    'assumption-check': { items: Assumption[] }
  }
}

2. Set the limits and the state atom

Two constants set the limits: a reply must be at least 300 characters, and at most five guesses are kept. The atom holds the list of guesses under the plugin name and the key items. It starts as an empty list.

import { atom, read, update } from 'claude-code'
import type { Register } from 'claude-code'

import type { Assumption } from '../types'

const PANE = 'assumption-check'
const items = atom({ plugin: 'assumption-check', key: 'items' } as const, [] as Assumption[])

// A reply shorter than this rarely carries a guess, so it skips the model call.
const MIN_REPLY = 300
const MAX_GUESSES = 5
Why 300 characters. The author's comment says a short reply rarely carries a guess. Skipping short replies saves a Haiku call each time. The check is < MIN_REPLY, so a reply of exactly 300 characters is checked.

3. Register the command and the pane

session.start adds /assumptions to the command list for this session. command.run answers that command by opening the pane. The command only opens the pane. It does not run the check.

export const register: Register = on => {
  let asked = ''

  on('session.start', async ($, e, next) => {
    await $.command.register({
      name: 'assumptions',
      description: 'Show the guesses Claude made in the last reply',
    })

    return next(e)
  })

  on('command.run', { command: 'assumptions' }, async $ => {
    await $.ui.open({ id: PANE, title: 'Assumptions' })

    return { text: 'Assumptions pane opened.' }
  })

4. Remember the request and check the reply

prompt.submit stores the text of the last prompt in the plain variable asked, so the model can see what was asked. turn.complete skips subagent replies, interrupted turns and short replies. For the rest, it asks Haiku, writes the guesses into the atom, and opens the pane.

  on('prompt.submit', ($, e, next) => {
    asked = e.text

    return next(e)
  })

  on('turn.complete', async ($, e, next) => {
    if (e.agentId !== undefined || e.isAborted) {
      return next(e)
    }

    // Each finished reply replaces the list, so guesses never carry over from an earlier reply.
    const reply =
      e.answer.length < MIN_REPLY
        ? undefined
        : await $.model
            .complete({ model: 'haiku', prompt: guessPrompt(asked, e.answer), maxTokens: 300, timeoutMs: 20000 })
            .catch(() => undefined)
    const found = reply?.isAnswered ? parseGuesses(reply.text) : []

    await update($, items, () => found.map(text => ({ text, verdict: 'open' as const })))
    if (found.length > 0) {
      void $.ui.open({ id: PANE, title: 'Assumptions' })
    }

    return next(e)
  })
Why the hook waits. It awaits the model call before it calls next(e), so the hooks beneath it wait too, for up to 20 seconds. The types say a hook's own-code budget does not count a model call, so the wait does not break that budget. The pane is opened with void, so the chain does not wait for it to draw.

5. Ask for a JSON list and read the answer safely

guessPrompt builds the prompt from the last request and the reply, each cut to a length cap. parseGuesses takes the first array-like text in the answer, keeps only non-empty strings, and returns an empty list on any error.

// The request and the reply are data here: the model only lists guesses.
function guessPrompt(asked: string, reply: string): string {
  return [
    'A person asked Claude something, and Claude replied. List up to five guesses the reply made that the person did not state: a reading of what they meant, a default value, or a file or name picked without asking.',
    'Answer with only a JSON array of short strings, each under 15 words. Answer [] when there are none.',
    '',
    `Request: ${asked.slice(0, 2000)}`,
    `Reply: ${reply.slice(0, 8000)}`,
  ].join('\n')
}

function parseGuesses(text: string): string[] {
  const json = text.match(/\[[\s\S]*\]/)?.[0] ?? '[]'

  try {
    const list: unknown = JSON.parse(json)
    if (!Array.isArray(list)) {
      return []
    }

    return list
      .filter((g): g is string => typeof g === 'string' && g.trim() !== '')
      .slice(0, MAX_GUESSES)
  } catch {
    return []
  }
}
Why it fails open. The .catch in step 4 turns a rejected model call into undefined. A reply that is not JSON becomes an empty list. In both cases no guesses show, and the reply itself is not held or changed. The types say $.model.complete rejects only when the engine refuses the request, such as a blocked model.

6. Draw the pane

The render hook reads the list with read(). A read inside a render hook subscribes that drawing, so each update() redraws the pane without a separate call. With no guesses, the pane shows one line of text.

  on('ui.render', { component: 'Pane', requestId: PANE }, async ($, e) => {
    const { Box, Button, Text } = $.ui.resolve(e)
    const list = await read($, items)

    if (list.length === 0) {
      return (
        <Box>
          <Text dimColor>No guesses in the last reply.</Text>
        </Box>
      )
    }

7. Send the wrong ones back

When at least one guess is marked Wrong, a button appears. It submits the wrong guesses as a new prompt, then clears the list. The new reply gets its own check, because the same turn.complete hook runs again.

        {wrong.length > 0 && (
          <Button
            key="send"
            label={`Send ${wrong.length} wrong to Claude`}
            onPress={() => {
              void $.prompt.submit({
                text: `These guesses in your last reply were wrong. Redo the affected part without them:\n${wrong.map(a => `- ${a.text}`).join('\n')}`,
              })
              void update($, items, () => [])
            }}
          />
        )}

How to use it

claude plugin marketplace add <owner>/<repo>
claude plugin install assumption-check@waraxe-claude-mods

The placeholder <owner>/<repo> is not filled in yet, for the same reason as in lesson 0016. The README and the code agree on the main rule. Two differences are small: the README leaves out the skips for subagent and interrupted turns, and it calls the button "Send wrong to Claude", while the button adds the count.

  • Run /reload-plugins, or start a new session.
  • Run /assumptions to open the pane at any time. It shows the guesses from the last checked reply.
  • Press Right or Wrong on each guess.
  • Press Send N wrong to Claude to submit the wrong guesses as a new prompt.
  • Cost: one Haiku call for each reply that is 300 characters or more, is not from a subagent, and was not interrupted. The call can use up to 300 output tokens and stops after 20 seconds. Other replies make no call.

Limits

A bug we fixed. Earlier versions wrote to the list only when a reply had guesses, so an old list could stay on screen after a reply with none. Each finished reply now replaces the list, even when it is empty. The fix is found by reading the code. The mod has not been run.
  • The model sees only your last prompt and the reply. It does not see earlier turns, so a guess that depends on earlier context may look wrong.
  • A guess is the model's view of the reply. It can miss a real guess or list one that is fine. Treat the list as a prompt to look, not as proof.
  • If the model call fails or times out, no guesses appear and no message is shown.
  • The list is session state, not stored data. The types say that state is held for the session, so a new session does not show the old list.

Check yourself

Why does the hook skip replies under 300 characters?

The author's comment says a short reply rarely carries a guess. Skipping it saves a Haiku call. The test is e.answer.length < MIN_REPLY, so a reply of exactly 300 characters is checked.

The Haiku call fails. What does the user see?

The .catch(() => undefined) turns the rejection into undefined, so no guesses are found. The hook then leaves the list as it was and does not open the pane. The reply is unaffected, and nothing shows the failure.

What makes the pane redraw after you press Right or Wrong?

The render hook called read() on the atom while it drew. The types say that read subscribes the drawing. Each button press calls update(), which writes the atom, and the pane draws again. The button handlers never call a redraw themselves.
