Secret handling

These mods let Claude use an API key without ever seeing it: keys are swapped for placeholders on the way into the chat and back into real values only when a local tool runs.

What it is

Secret Box lets Claude ask for a key without seeing it. Claude calls request_secret, a masked box opens, and you paste the key. The mod writes it to .env and gives Claude only a placeholder such as [REDACTED-SECRET-3f9a1c2e]. Any key a tool prints later comes back as a placeholder, and a placeholder that Claude writes into a command becomes the real key when that command runs.

This matters for your mission because the transcript is the one thing you cannot undo. A key that reaches the chat stays in the session file, so this family is the clearest example of a hook that guards what enters the record, and it shows how a hook can rewrite a tool's input and output.

How it was built

Secret Box is two layers. The lower layer is redact.ts, the transcript-redactor, which the README says is unchanged. register.jsx calls that layer's register first, then adds the box and the guards. Each step below is one of those additions, with the redactor's code behind it.

1. Give Claude the request_secret tool at session start

The session.start hook registers request_secret with isDeferred: false, so Claude sees it on every turn. The tool is only offered in interactive sessions. Then the hook reads .env so that its secret values are known to the vault before any tool runs.

  on('session.start', async ($, e, next) => {
    // The box needs a person to paste into, so a headless run gets no request_secret tool
    if (e.isInteractive !== false) await $.tool.register({
      name: 'request_secret',
      description:
        'Ask the user for a secret (API key, token, password) without it ever entering the conversation. ' +
        'The user pastes it into a masked box and the mod saves it to the project .env (or the env file named ' +
        'in `file`, such as .env.local). You get back the ' +
        'variable name and a placeholder like [REDACTED-SECRET-1a2b3c4d]. Write that placeholder in a command ' +
        'or file and it becomes the real value when the tool runs. Use this INSTEAD of asking the user to ' +
        'paste a secret into chat.',
      inputSchema: {
        type: 'object',
        properties: {
          name: { type: 'string', description: 'Environment variable name, e.g. STRIPE_SECRET_KEY' },
          reason: { type: 'string', description: 'One short line telling the user why it is needed' },
          file: { type: 'string', description: 'Env file in the project folder to save to, e.g. .env.local. Default .env' },
        },
        required: ['name', 'reason'],
      },
      isDeferred: false,
    })
    await learnDotenv($, ['.env'])
    return next(e)
  })

2. Refuse any Bash command that would commit a .env file

A tool.call hook on Bash runs commitBlockReason first. It refuses git add of a .env file. For a commit, it asks git which files are staged. If the same command also stages files, such as git add before git commit or commit -a, it counts the changed and untracked files too. If the check itself fails, the call is blocked.

  on('tool.call', { tool: 'Bash' }, async ($, e, next) => {
    const why = await commitBlockReason($, String(e.command || ''))
    return why ? { deny: `secret-box: ${why} A pushed key can't be taken back.` } : next(e)
  }).catch(() => ({ deny: 'secret-box: the .env guard failed, so this call is blocked to be safe.' }))

The helper that does the checking is commitBlockReason. Its first lines are these.

async function commitBlockReason($, cmd) {
  if (/\bgit\b[^;&|]*\badd\b/.test(cmd) && /\.env\b(?!\.(example|sample|template|dist))/.test(cmd)) {
    return 'staging a .env file is blocked.'
  }
  if (!/\bgit\b[^;&|]*\bcommit\b/.test(cmd)) return ''

3. Learn the secret values in .env before a tool reads them

Before a tool that can read a file runs, learnDotenv reads the .env files it names. Every value whose name says secret (such as KEY, TOKEN or PASSWORD) and that is six characters or longer goes to the vault with keepSecret. A weak value, like a word password, is then hidden wherever it appears, which the pattern tests alone would miss.

async function learnDotenv($, files) {
  let cwd = ''
  try { cwd = await $.session.cwd() } catch {}
  for (const f of files) {
    try {
      const path = isAbsolute(f) ? f : f.startsWith('~/') ? f : cwd + '/' + f
      if (path.startsWith('~/') || !(await $.fs.exists(path))) continue
      for (const m of (await $.fs.read(path)).matchAll(ASSIGNMENT)) {
        const value = m[3].trim().replace(/^["']|["']$/g, '')
        if (value.length >= 6 && SECRET_NAME.test(m[2])) keepSecret(value)
      }
    } catch {}
  }
}

4. Open the box, and wait for the person in short steps

When Claude calls request_secret, the hook opens a pane with $.ui.open. In a narrow terminal, the box moves to the band above the prompt. The hook then waits for you. A hook's own run time is capped, so the wait is a loop of short sleep processes. The loop ends when you press Enter or Esc, or when the 10-minute deadline passes.

      const deadline = now + WAIT_MS
      while (req.answer === undefined && !next.signal.aborted && (await $.clock.now()) < deadline) {
        await pause($)
      }

The pause function runs one short wait, and it moves to the next command only when the first one is missing.

async function pause($) {
  waits ||= [...((await $.env.get('OS')) === 'Windows_NT' ? WAITS.windows : WAITS.unix)]
  for (;;) {
    try {
      return await $.process.run(waits[0], { timeoutMs: 5000 })
    } catch (err) {
      // Only a command that is not there moves on to the next one
      if (waits.length > 1 && isNotFound(err)) waits.shift()
      else throw err
    }
  }
}

5. Write the .env file, add it to .gitignore first, and answer with a placeholder

saveToDotenv refuses a file that git already tracks. It adds the file to .gitignore before it writes the secret, so a failed write never leaves an un-ignored key on disk. It then writes NAME=value, replacing an old line of the same name. The answer to Claude names the variable and the file and gives a placeholder. It never gives the value.

  // .gitignore first: if that write fails, the secret is never on disk un-ignored
  const gi = cwd + '/.gitignore'
  const ignore = (await $.fs.exists(gi)) ? await $.fs.read(gi) : ''
  const isIgnored = await gitIgnores($, cwd, file, ignore)
  if (!isIgnored) await $.fs.write(gi, ignore + (ignore && !ignore.endsWith('\n') ? '\n' : '') + file + '\n')

  const path = cwd + '/' + file
  const old = (await $.fs.exists(path)) ? await $.fs.read(path) : ''
  const line = `${name}=${quote(value)}`
  const lines = old.split('\n').filter((l, i, all) => !(i === all.length - 1 && l === ''))
  const at = lines.findIndex(l => l.startsWith(name + '='))
  if (at >= 0) lines[at] = line
  else lines.push(line)
  await $.fs.write(path, lines.join('\n') + '\n')

6. Restore real values into local tools, and hide them on the way out

In the redactor's tool.call hook, a placeholder in the input becomes its real value. This happens only for the tools in restoreTools, which are Bash, Write, Edit, MultiEdit and NotebookEdit by default. The hook remembers which values it handed out. A value with shell characters is refused in Bash, so it cannot run as code. After the tool runs, the output is scanned again, and any value the call was given comes back as a placeholder.

    const handed = new Set<string>()
    const restoreTracked = (s: string): string =>
      restore(s) === s
        ? s
        : s.replace(/\[REDACTED-SECRET-[0-9a-f]{8}\]/g, (t) => {
            const v = restore(t)
            if (v !== t) handed.add(v)
            return v
          })
    const rehideHanded = (text: string): string => {
      let out = text
      for (const v of [...handed].sort((a, b) => b.length - a.length)) if (v.length >= 4 && out.includes(v)) out = out.split(v).join(mint('SECRET', v))
      return out
    }
    const input = isLocal ? (walk({ ...e }, restoreTracked) as typeof e) : e
The guard covers what Claude reads. It does not stop what Claude does.
  • Claude can still run a command that transforms a key, such as base64, and then the output is not recognised. The README calls this "not a sandbox against a model that is trying to leak one".
  • A command that publishes text, such as git commit, git tag, gh issue or gh pr, gets no real values. Its placeholder stays a placeholder, so a step that needs the key must be its own command.
  • A placeholder that Claude writes with Write or Edit lands in the file as the real key.

How to use it

claude plugin marketplace add ray-amjad/claude-code-mods
claude plugin install secret-box@claude-code-mods

The marketplace is named claude-code-mods. secret-box already contains the redactor, so you do not need to install transcript-redactor as well. To install only the redactor, use transcript-redactor@claude-code-mods.

  • Ask for something that needs a key, for example "billing.js needs the Stripe secret key, get it set up". Claude calls secret-box - request_secret.
  • Paste the key into the box. It shows dots and a character count. Press Enter to save, or Esc to cancel. A cancel writes nothing.
  • Ask Claude to use it, for example "check the key works". It writes the placeholder into the command, and the real key is used when the command runs.
  • Watch the tool row. It says secret-box: hid 1 value(s) when a value was swapped out of a result.
  • Settings live in /plugin configure secret-box@claude-code-mods. The defaults hide vendor-shaped keys and high-entropy tokens. Emails and IP addresses are off until you turn on pii.

Cost. The mod makes no model calls and no network calls. Its work is pattern matching on your machine, plus a short wait loop while the box is open.

Limits.

  • In auto mode, Claude Code's classifier can block cat .env and source .env before the mod sees them. Using the placeholder from the box still works.
  • In a terminal under 144 columns, the box draws in the band above the prompt. Press Ctrl+X, then Tab, to type in it.
  • The vault lives in memory only. Placeholders from an earlier session mean nothing in a new one, and the mod learns .env again at the start of each session.
  • Only .env in the working directory is learned at session start. Other env files are masked by name when they are read.
  • claude -p and SDK sessions get no request_secret tool, because nobody can type into the box there.
  • A plain word password with no name beside it, such as password=, can look like ordinary text. Only the .env learning step catches it.

Check yourself

Why does the box wait in short sleep processes instead of one long hook?

A hook's own run time is capped at 10 seconds. Time spent inside a mods API call does not count toward that cap. So pause runs a short process, through $.process.run, on each pass of the loop. The loop ends when the answer arrives, or when the 10-minute WAIT_MS deadline passes.

Where does a pasted key go, and what does Claude get back?

The value goes into the .env file, or the file Claude named, as NAME=value. The file is added to .gitignore first. Claude gets a result that names the variable and the file and gives a placeholder, such as [REDACTED-SECRET-…]. Claude never gets the value.
