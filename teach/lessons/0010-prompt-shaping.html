What it is

Prompt Bouncer checks each prompt you type at prompt.submit, the moment you press Enter. If the prompt is vague, the mod drops it, a toast says why, and Claude Code puts the prompt back in the box for you to fix. The README's reason: a vague prompt costs a whole turn of Claude guessing. Quick mode, the default, uses a few patterns and no model. Project mode reads the project's own docs and asks Haiku if the prompt is specific and uses the project's terms. /force sends any prompt past it, and slash commands always pass.

Your mission asks you to name the hooks a mod uses and say why, and this mod is the plainest guard you will meet: one prompt.submit handler that returns { drop } or calls next(e), and lets the prompt through when anything breaks.

How it was built

The mod is one file of plain JavaScript, hooks/register.js. hooks/hooks.json points to it. The settings come from userConfig in plugin.json, and the engine hands them to register(on, options).

1. Show the mode and register two commands

At session.start the hook notes whether the session is headless (claude -p or the SDK). In an interactive session it puts the mode on the status line. It then registers /bouncer and /force. A failure to register is logged, and the session goes on.

  on('session.start', async ($, e, next) => {
    headless = e.isInteractive === false
    if (!headless) $.ui.status((await currentMode($, options)) + ' mode')
    try {
      await $.command.register({ name: 'bouncer', description: 'Show prompt-bouncer, or switch it: /bouncer quick|project|off', argumentHint: '[quick|project|off]' })
      await $.command.register({ name: 'force', description: 'Send a prompt past prompt-bouncer', argumentHint: '<prompt>' })
    } catch (err) {
      $.ui.log('could not register commands: ' + err.message)
    }
    return next(e)
  })

2. Pass what it should not judge

The prompt.submit hook judges only what a person typed. A prompt from another origin, such as a notification or another session, goes straight on. The prompt that /force sent passes once. A prompt that starts with ! passes with the ! removed. Slash commands, empty prompts and the off mode pass too.

  on('prompt.submit', async ($, e, next) => {
    const text = e.text.trim()

    // Only judge what a person typed, never a notification or a peer's message
    const kind = e.origin && e.origin.kind
    if (kind !== 'composer' && kind !== 'sdk' && kind !== 'bridge' && kind !== undefined) return next(e)

    // Escape hatches: /force sent this one, or it starts with !
    if (forceNext !== null && text === forceNext) { forceNext = null; return next(e) }
    if (text.startsWith('!')) return next({ ...e, text: text.slice(1).trim() })
    if (text.startsWith('/')) return next(e)

    const m = await currentMode($, options)
    if (m === 'off' || text === '') return next(e)

3. Quick mode: patterns, no model

quickRules lets a prompt pass if it has more than 15 words, or if it names something concrete. The ANCHOR pattern counts a file, a path, code in backticks, a quoted name, CamelCase, snake_case or a Capitalized Name. Otherwise a vague noun phrase, such as "the thing" or "stuff", bounces it. On the first prompt of a session, a bare "it" or "that" bounces it too, because there is nothing for it to point back to.

// Quick mode: no model, just patterns. Short + vague + nothing named = bounce.
function quickRules(text, isFirst) {
  const words = text.split(/\s+/).length
  if (words > 15 || ANCHOR.test(text)) return { pass: true }
  const noun = text.match(VAGUE_NOUNS)
  if (noun) {
    return { pass: false, reason: '"' + noun[0] + '" doesn\'t say which one. Name the file, feature or component.' }
  }
  const pronoun = text.match(BARE_PRONOUN)
  if (isFirst && pronoun) {
    return { pass: false, reason: '"' + pronoun[0] + '" has nothing to point back to yet. Say what you mean.' }
  }
  return { pass: true }
}

4. Project mode: Haiku reads the project's docs

loadDocs reads the files named in the docs setting with $.fs, fresh on every prompt, and cuts them at maxDocChars. projectGate then makes one Haiku call, capped at 300 tokens and 20 seconds. The docs go first and are marked cache: true, because they are the same on every prompt. The prompt goes after them. Haiku answers JSON: a pass, or a reason and a suggestion. If Haiku does not answer, or the answer is not JSON, the prompt passes.

async function projectGate($, text, isFirst, docs) {
  const r = await $.model.complete({
    model: 'haiku',
    maxTokens: 300,
    timeoutMs: 20000,
    system: 'You are a gatekeeper for a coding agent. Reply with JSON only, no prose.',
    prompt: [
      // The docs are the same every prompt, so they form the cached prefix
      { text: 'PROJECT DOCS (the project\'s own language):\n\n' + docs.text, cache: true },
      {
        text: 'A developer is about to send this prompt to a coding agent' +
          (isFirst ? ' as the FIRST message of a new session (so "it" or "that" points at nothing)' : ' mid-conversation (short follow-ups like "yes" or "do it" are fine)') +
          ':\n\n<prompt>\n' + text + '\n</prompt>\n\n' +
          'Bounce it if EITHER is true: (1) it uses a loose word where the docs define a precise term ' +
          '(any word in the glossary\'s "Not" column, or a close paraphrase of one, always bounces), or ' +
          '(2) the agent would have to guess what it refers to, because it names no file, feature or component. ' +
          'A prompt that already names a project term or a file passes, even if other words in it are casual. ' +
          'Ordinary verbs and words like "switch", "change" or "update" are not loose terms.\n\n' +
          'Reply {"pass": true} or {"pass": false, "reason": "<one short sentence>", "suggestion": "<under 25 words: the prompt rewritten with the project\'s term; if it could mean two things, ask which one, e.g. this project calls that the billing panel, which one did you mean?>"}',
      },
    ],
  })
  // If Haiku is down or answers nonsense, let the prompt through
  if (!r.isAnswered) return { pass: true }
  try {
    const json = JSON.parse(r.text.slice(r.text.indexOf('{'), r.text.lastIndexOf('}') + 1))
    return json.pass === false ? { pass: false, reason: json.reason || 'too vague for this project', suggestion: json.suggestion } : { pass: true }
  } catch {
    return { pass: true }
  }
}

5. Bounce with { drop }, and fail open

A pass calls next(e). A bounce counts itself, shows a toast for eight seconds, and returns { drop } with the reason on one line. The prompt never enters the session, and Claude Code puts it back in the box. The .catch on the hook calls next(e) if the hook throws, so a broken bouncer never locks you out.

    if (verdict.pass) return next(e)

    // Bounce: tell the user why (Claude Code puts the prompt back in the box to fix)
    bounces += 1
    // The toast shows the fix when there is one, else the reason
    if (!headless) $.ui.toast('Bounced. ' + (verdict.suggestion || verdict.reason), { timeoutMs: 8000 })
    // One line: a drop reason with newlines in it is mangled
    return { drop: 'prompt-bouncer: ' + verdict.reason + (verdict.suggestion ? ' Try: ' + verdict.suggestion : '') + ' (Send it anyway: /force <prompt>)' }
  }).catch(($, e, next) => next(e))
  // A bouncer that breaks lets prompts through: it should never lock you out

6. Send a prompt past the bouncer with /force

A command cannot submit a prompt from inside its own run, because it would wait on its own turn. So /force saves the text in forceNext and sets a 50-millisecond timer. The timer submits the text with asUser: true, and step 2 lets that exact text through once.

  // /force <prompt> sends the prompt as your own words, past the bouncer
  on('command.run', { command: 'force' }, async ($, e) => {
    const text = e.args.trim()
    if (!text) return { text: 'Usage: /force <prompt>' }
    forceNext = text
    // A command can't submit a prompt itself (it would wait on its own turn),
    // so a timer submits it a moment later, once the command has finished
    $.clock.after(50, () => $.prompt.submit({ text, asUser: true }).catch((err) => $.ui.log('force failed: ' + err.message)))
    return {}
  })

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install prompt-bouncer@waraxe-claude-mods

A line under the prompt shows the mode, for example ⚠ prompt-bouncer: quick mode. The README says it was tested with Claude Code 2.1.296.

  • Type as usual. A bounced prompt shows a toast and a Prompt dropped by a hook line, and it comes back in the prompt box.
  • Type /force your prompt to send it as your own words, unchecked.
  • Type /bouncer to see the mode, the bounces this session and the docs it found. Type /bouncer quick, /bouncer project or /bouncer off to switch for this session.
  • In claude -p, a prompt that starts with ! passes, and the ! is removed. In the interactive prompt box ! is shell mode, so use /force there.
  • To try project mode, open the plugin's example/ folder (plugins/prompt-bouncer/example in this repository), a tiny invoicing app with a glossary. Run claude, then /bouncer project. Try "the payments page shows the wrong price, fix it", then "The Billing Panel shows the wrong plan price".

The code picks the mode in this order: a /bouncer switch, then PROMPT_BOUNCER_MODE, then the mode setting, then quick.

Cost. Quick mode uses no model and adds nothing. Project mode makes one Haiku call for each judged prompt, which adds a few seconds. A bounced prompt never reaches Claude, so it costs no turn. The mod sends nothing to Claude itself: the reason and the suggestion are for you only.

Limits.

  • Haiku is judging, so expect the odd miss or the odd bounce you disagree with. /force is there for that.
  • Quick mode is English only, and its word lists are short.
  • docs patterns support * inside one folder, such as docs/decisions/*.md, not **.
  • A /bouncer switch lasts for the session and resets if the mod reloads.
  • In -p and SDK sessions the drop still applies, but no status line or toast is drawn.

Check yourself

What happens if Haiku is down, Haiku answers nonsense, or the hook throws?

The prompt goes through each time. projectGate returns a pass when the call is not answered and when the answer does not parse as JSON. The .catch(($, e, next) => next(e)) on the prompt.submit hook passes the prompt on if the hook throws. The README puts it plainly: a broken bouncer should never lock you out.

Why does /force use a timer, and how does its prompt get past the bouncer?

A command cannot submit a prompt from inside its own run, because it would wait on its own turn. So /force stores the text in forceNext and submits it 50 milliseconds later with $.prompt.submit({ text, asUser: true }). When that prompt reaches prompt.submit, its text equals forceNext, so the hook clears forceNext and calls next(e).
