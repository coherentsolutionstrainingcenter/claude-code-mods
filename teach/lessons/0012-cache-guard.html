Cache guard

These mods watch Claude's one-hour prompt cache, warn you when it is about to go cold, and in the best version keep it warm during a break or stop one expensive cold send.

What it is

Cache Tax has two jobs. During a break, /keepwarm sends a short fork of the session every 50 minutes, so the one-hour cache is read rather than written again. When you come back to a cold cache with a large context, it drops your first ordinary message once and shows the estimated rewrite cost. Sending it again pays that cost.

This matters for your mission because this mod spends money on your behalf, so its README states the costs and limits as clearly as the code does. You need both to explain it honestly.

How it was built

The mod is one file, hooks/register.ts. It registers eleven hooks, as the validator output in the README lists. The main ones are command.run for /keepwarm, prompt.submit for the guard, and turn.step and turn.complete for the clock. A cold check and a fork-based ping drive all of it. The README says it runs one fork per keep-warm ping, and that it inspects the first non-blank character of each prompt, for a slash.

1. Set the numbers

The constants hold every timing and size the mod uses. The cache lasts one hour. A ping is sent 50 minutes after the last request. The default keep-warm window is six hours. The guard only applies to a context of 50,000 tokens or more.

const TTL_MS = 60 * 60 * 1000
const PING_AFTER_MS = 50 * 60 * 1000
const MIN_PING_MS = 60 * 1000
const MAX_RETRIES = 3
const AUTO_WARM_MS = 3 * 60 * 60 * 1000
const DEFAULT_WINDOW_MS = 6 * 60 * 60 * 1000
const BIG_TOKENS = 50000
const PING_PROMPT = 'Reply with the single word: warm'
const KEY_DEADLINE = 'deadline'
const KEY_EVERY = 'every'
const KEY_GUARD = 'guard'
const KEY_ALWAYS = 'always'

2. Decide that the cache is cold

The cache is cold when at least one hour has passed since the last request, and the context has not been compacted. The guard message uses the same clock. It says how long ago the cache went cold, and the estimated price of the rewrite.

function isCold(s: State, now: number): boolean {
  return s.lastRequestAt > 0 && !s.compacted && now - s.lastRequestAt >= TTL_MS
}

function guardText(s: State, now: number): string {
  const price = priceOf(s.lastModel, s.ctx)
  const rate = price ? `$${price[1]}/MTok` : 'the cache-write rate'
  const warm = warmUsd(s)
  return `the prompt cache went cold ${fmtDuration(now - s.lastRequestAt - TTL_MS)} ago. Sending this re-writes ` +
    `up to ${s.ctx.toLocaleString('en-US')} tokens at ${rate} = ${fmtUsd(coldUsd(s))}` +
    (warm == null ? '' : ` (a warm turn would have cost ${fmtUsd(warm)})`) + '.'
}

3. Ping the cache with a fork

A ping is a tool-less fork of the session. It asks for one word, so the reply is short, but the request still reads the whole cached prefix. The mod marks the fork as in flight, so only one can run at a time. After the await, it checks that nothing changed in the meantime, such as /clear, a resume, a compaction or a real request. If something changed, the reply is dropped.

  const gen = s.gen
  const sentAt = s.lastRequestAt
  s.inFlight = true
  const sent = await $.model.fork({ prompt: PING_PROMPT }).then(reply => ({ reply }), (err: unknown) => ({ err }))
  // Checked after the last await. A stop, /clear, resume or compaction, or a main request that moved the
  // cache clock, replaced what this fork was sent for: its reply is dropped and the window armed afresh.
  if (gen !== s.gen || s.lastRequestAt !== sentAt) return s.pending ? undefined : arm($, s)

4. Check that the ping really kept the cache warm

The mod does not trust the ping. It reads the usage the fork reports. A warm ping reads from the cache and writes only a small amount. The mod calls the ping warm only when the read is above zero, and the write is less than a tenth of the read. If the ping was not warm, the window stops, and the reason says what was read and written.

  const u = reply.usage
  const price = priceOf(s.lastModel, u.input_tokens + u.cache_read_input_tokens + u.cache_creation_input_tokens)
  // A warm ping reads the prefix and writes only its own message; a write of a tenth of the read or more means the prefix broke.
  const warm = u.cache_read_input_tokens > 0 && u.cache_creation_input_tokens < 0.1 * u.cache_read_input_tokens
  const usd = price ? pingUsd(u, price) : null
  s.last = { at: now, read: u.cache_read_input_tokens, write: u.cache_creation_input_tokens, usd, warm }
  if (!warm) return stop($, s, `the ping read ${fmtTok(u.cache_read_input_tokens)} and wrote ${fmtTok(u.cache_creation_input_tokens)} tokens (${fmtUsd(usd)}), the cache was already gone`)
  s.lastRequestAt = now
  await arm($, s)

5. Refuse one cold send, then let the resend through

The prompt.submit hook runs on each prompt. Slash commands and prompts from plugins pass. A cold cache with a big context gets one drop. The mod records the request time of that refusal in ackedAt. The next prompt that arrives while no request has been sent since then goes through, and it is counted as a cold write. Unattended prompts, such as a background task's notification, are never dropped, because nobody could resend them. They are logged instead.

    if (!isCold(s, now) || s.ctx < BIG_TOKENS) return next(e)
    // A refused prompt that no person sent would be lost: nobody is there to send it again.
    const unattended = UNATTENDED.has(e.origin.kind)
    if (s.guard === 'warn' || unattended) {
      $.ui.log(`${guardText(s, now)} Sending anyway${unattended ? `, since this ${e.origin.kind} prompt cannot be sent again` : ''}; keepwarm will hold the cache for ${fmtDuration(holdMs(s))} once it lands.`)
      s.coldWritePending = true
      return next(e)
    }
    if (s.ackedAt === s.lastRequestAt) {
      s.ackedAt = 0
      s.coldWritePending = true
      return next(e)
    }
    s.ackedAt = s.lastRequestAt
    return { drop: `cache-tax: ${guardText(s, now)} Send it again to pay it, and keepwarm will then hold the cache for ${fmtDuration(holdMs(s))}. Or /clear and start from a note.` }
Read the cost and the TTL before you use it.
  • Every ping costs tokens. The README says a fork takes no output cap, so the model's reply is billed too. The author measured one ping at about $0.02 for a 75k-token read on Sonnet 5.
  • The 50-minute schedule needs a one-hour main cache. Included subscription usage has one by default. API-key, usage-credit and cloud sessions default to five minutes, so set promptCacheTtl to "1h" for those. A 50-minute timer cannot protect a five-minute cache.
  • The dollar figures are a yardstick on a subscription, not the bill. The README says how cache reads count against the plan limits is not documented.

How to use it

claude plugin marketplace add karanb192/claude-code-mods
claude plugin install cache-tax@claude-code-mods

The marketplace is named claude-code-mods. The README needs Claude Code 2.1.287 or later, and says no early-access flag is needed. Restart Claude Code, or run /reload-plugins in an open session.

  • Before a break, type /keepwarm 90m for a 90-minute window, or /keepwarm for six hours. Use /keepwarm status to see the window and the next ping.
  • Watch the row above the prompt. It shows warm, cold or unknown, and the timer.
  • When you come back to a cold cache with a context of 50,000 tokens or more, your first ordinary message is dropped once, with the estimated price. Send it again to pay the price, or type /clear and start from a note.
  • Type /cache-tax to see the cache estimate and this session's cold-write count. Type /cache-tax guard warn to show the price and send the message, with no drop.
  • Type /keepwarm off to stop the window. It also turns always off.

Cost. A ping is a fork. It reads the cached prefix, which is cheap, and it writes a few uncached tokens. It also pays for the model's reply. A cold send of a big context pays the full write price instead. Read the list prices in the README before you choose a window.

Limits.

  • Mods must be allowed to load. Local settings, safe mode or organisation policy can stop them.
  • A warm ping proves the cache was warm at that moment. A change to the prompt prefix can still invalidate it.
  • The token count in the refusal is an upper bound. The engine reports the last response's input and output together.
  • The cold-write count is kept in memory. /clear resets it.
  • The author ran one transcript-verified return. The README says that shows one configuration, not net savings for every setup.

Check yourself

Why does the guard ignore a cold cache when the context is under 50,000 tokens?

The check if (!isCold(s, now) || s.ctx < BIG_TOKENS) return next(e) lets the message through when the cache is warm, or when the context is smaller than BIG_TOKENS (50,000). A rewrite of a small context costs little, so the guard does not interrupt you for it.

How does the mod tell that a ping really kept the cache warm?

It reads the usage the fork reports. A ping is warm only when cache_read_input_tokens is above zero and cache_creation_input_tokens is less than a tenth of the read. If the ping is not warm, stop ends the window and gives the reason, with the read and write counts.
