What it is

Replay Theater records each file edit that Claude makes in a turn: the file, and the text before and after. When the turn ends, a hint appears above the prompt, and /replay opens a pane that shows one edit at a time, with a red and green diff. It only watches: the README says it never blocks, changes or delays an edit.

It matters for your mission because it shows which hook events and API calls a mod uses to record work and draw a pane, so you can point to them and say why.

How it was built

Every snippet below is copied from the best version. The file is JavaScript (.mjs), not TypeScript, but the hook shape matches lesson 0016.

1. Declare the hook module

The file hooks/hooks.json names one module. The engine loads it and calls the exported register function. The types define it as Register = (on: On, options: PluginOptions) => unknown.

{
  "modules": [
    "./replay-theater.mjs"
  ]
}

2. Record each edit, then let it run

The tool.call hook runs for every tool call. For Edit, Write and MultiEdit it stores steps in state.pending. A recording error is caught, so it cannot stop the edit. The hook always returns next(e), so the tool call goes on.

  // Record each edit, then let it run. Never blocks the call.
  on("tool.call", async ($, e, next) => {
    if (EDIT_TOOLS.has(e.tool)) {
      try {
        const steps = await stepsFor($, e);
        state.pending.push(...steps);
      } catch { /* recording must never stop the edit */ }
    }
    return next(e);
  });

3. Group the edits by turn

turn.start clears the pending list, except for a subagent turn, which has an agentId. turn.complete makes the pending list the replay, and returns early for a subagent. So a subagent's edits join the main turn's replay. A turn with no edits keeps the previous replay.

  on("turn.start", ($, e, next) => {
    if (!e.agentId) state.pending = [];
    return next(e);
  });

  // At the end of a main-loop turn, the pending edits become the replay.
  on("turn.complete", async ($, e, next) => {
    const r = await next(e);
    if (e.agentId || !state.pending.length) return r;
    state.replay = state.pending;
    state.pending = [];
    state.index = 0;
    state.turns++;
    $.ui.invalidate("ui.render");
    return r;
  });

4. Register the /replay command

session.start registers the slash command with $.command.register. The command.run hook, filtered to { command: "replay" }, opens the pane and returns a text reply.

export function register(on, options) {
  // Slash command: /replay opens the pane.
  on("session.start", async ($, e, next) => {
    const r = await next(e);
    await $.command.register({ name: "replay", description: "Replay Theater: step through the last turn's file edits" });
    return r;
  });

  on("command.run", { command: "replay" }, async ($, e) => {
    const opened = await openReplay($);
    return { text: opened ? `Replay Theater: ${state.replay.length} edits` : "Replay Theater: no edits in the last turn." };
  });

5. Open the pane, and hide the band first

The pane takes the keyboard only while nothing else holds it. So openReplay sets isOpen and asks for a re-render, which removes the mod's own band. It then waits 200 ms and calls $.ui.open with focus and closeOnEscape. If the result has isPlaced set to false, the replay is drawn in the band instead.

async function openReplay($) {
  if (!state.replay.length) return false;
  state.index = 0;
  state.isOpen = true;
  // The pane only takes the keyboard while nothing else holds it. Hide the
  // band first (it held the keys if its button was pressed), then open.
  $.ui.invalidate("ui.render");
  await $.clock.sleep(200);
  const rows = Math.min(MAX_DIFF_LINES + 8, 22);
  const placed = await $.ui.open({ id: PANE_ID, title: "Replay Theater", focus: true, closeOnEscape: true, rows, columns: 58 });
  // No room for a pane (a narrow terminal): draw the replay in the band.
  state.inBand = placed?.isPlaced === false;
  $.ui.invalidate("ui.render");
  return true;
}

6. Draw the pane with buttons

A ui.render hook for the Pane component draws the replay view when the request id matches. The view takes Box, Text and Button from $.ui.resolve(e). Its buttons are Prev (p), Next (n) and Close (c). A Prev button looks like Button({ key: "prev", label: "◀ Prev", hotkey: "p", onPress: () => go(k - 1) }).

  // The pane.
  on("ui.render", { component: "Pane" }, ($, e, next) => {
    if (e.requestId !== PANE_ID) return next(e);
    return replayView($, e, false);
  });

  • Ask for an edit that changes files. The README example is "rename the function greet to welcome everywhere".
  • When the turn ends, type /replay and press Enter. Or press ctrl+x, then Tab, then r.
  • In the pane, n goes next, p goes back, and c or Escape closes it. Mouse clicks on the buttons also work.
  • Cost: the mod does not call a model. A Write reads the old file from disk once, before the write.

Limits

  • The diff shows up to 12 lines per step, then "… N more lines". Unchanged lines show only next to a change.
  • A Write of a file over 400 lines shows as all removed, then all added, with no matching lines.
  • Edits are recorded when the tool is called. An edit you deny, or one that fails, still shows.
  • The replay lives in memory for the current session. It is lost when Claude Code restarts or the plugin reloads.
  • The MultiEdit path is untested (README). The API types in the 2.1.308 folder do not list a MultiEdit tool.
  • The band above the prompt is shared. If another mod also draws there, only one of them shows (README).

Check yourself

Why does the tool.call hook return next(e) after it records the edit?

The hook only watches. Its comment says it records and then lets the edit run. The types say a hooks module returns next(e), a copy with fields changed, or its own result. Returning next(e) lets the call go on unchanged, and the README says the mod never blocks, changes or delays an edit.

A subagent edits a file during the main turn. Why is that edit in the main turn's replay?

turn.start clears the pending list only when e.agentId is absent. tool.call still adds the subagent's steps to the pending list. turn.complete returns early for a subagent, so only the main turn's end turns the pending list into the replay.
