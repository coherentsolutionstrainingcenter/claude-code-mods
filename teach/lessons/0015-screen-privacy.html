What it is

recording-mode adds /rec. While it is on, in every Claude Code session on the machine, it does four things. It masks keys, .env values, emails, names, phone numbers, addresses, ID and account numbers, money and business figures wherever the transcript draws text. It draws results from mail, chat, task, file, calendar and finance tools as hidden. It refuses private files and finance tools. And it adds a note to each prompt asking Claude to keep names and figures out of its replies.

It matters for your mission because one short mod uses four kinds of hook, for drawing, refusing, telling the model and a command, and you need to say which one does what before you publish it.

How it was built

The hooks are in hooks/register.mjs. The masking rules are pure functions in hooks/privacy.mjs, with no mod API calls.

1. Declare the hook module

hooks/hooks.json names one module. The engine loads it and calls the register function it exports.

{
  "description": "Recording Mode hooks module",
  "modules": ["./register.mjs"]
}

2. Share one switch between all chats

The on or off state lives in one file, ~/.claude/mods-data/recording.json. setFlag writes it when you run /rec. Turning on loads the .env values and the config, builds the masker, and redraws the transcript with $.ui.invalidate. Turning off drops the values from memory.

// Another session may have turned recording on or off
async function syncFlag($) {
  const flag = await readFlag($)
  if (flag.on === rec.on && flag.strict === rec.strict) return
  rec = flag
  if (rec.on) await load($)
  else unload()
  apply()
  $.ui.invalidate('ui.render')
}

async function setFlag($, on, strict) {
  rec = { on, strict: on && strict, since: on ? await $.clock.now() : 0 }
  await $.fs.write(home + FLAG_PATH, JSON.stringify(rec))
  if (rec.on) await load($)
  else unload()
  apply()
  $.ui.invalidate('ui.render')
}

Each session reads the file at start, then every 3 seconds, so /rec in one chat reaches the others. /rec is registered with immediate: true, and falls back to /recording if the name is taken.

  on('session.start', async ($, e, next) => {
    home = (await $.env.get('USERPROFILE')) || (await $.env.get('HOME')) || ''
    cwd = await $.session.cwd()
    commandName = (await registerCommand($)) || commandName
    await loadConfig($)
    await syncFlag($)
    $.clock.every(3000, () => syncFlag($).catch(() => {}))
    return next(e)
  })

3. Mask each row as it is drawn

Prompts, replies and command output go through mask. A tool's input is masked with deepMask, which keeps the data's shape. A business tool's output goes through hideText instead, so the whole result draws as hidden. Each hook passes the changed props to next, which draws them.

  // Text rows: prompts, replies, command output
  on('ui.render', { component: ['UserMessage', 'AssistantMessage', 'CommandOutput'] }, async ($, e, next) => {
    if (!rec.on || typeof e.props.text !== 'string') return next(e)
    return next({ ...e, props: { ...e.props, text: mask(e.props.text) } })
  })

  // Tool rows: the call's input is masked; a business tool's result is hidden whole
  on('ui.render', { component: 'ToolUse' }, async ($, e, next) => {
    if (!rec.on) return next(e)
    const business = businessSource(e.props.tool, e.props.input, config.businessTools) || businessCalls.has(e.props.tool_use_id)
    if (business) businessCalls.add(e.props.tool_use_id)
    const props = { ...e.props, input: deepMask(e.props.input, mask) }
    if (e.props.output !== undefined) props.output = deepMask(e.props.output, business ? hideText : mask)
    return next({ ...e, props })
  })

  on('ui.render', { component: 'ToolResult' }, async ($, e, next) => {
    if (!rec.on) return next(e)
    const business = businessSource(e.props.tool, null, config.businessTools) || businessCalls.has(e.props.tool_use_id)
    return next({ ...e, props: { ...e.props, output: deepMask(e.props.output, business ? hideText : mask) } })
  })

4. Find what to hide

makeMasker returns the mask function. It works in order: .env values and known key shapes first, then people and emails. Names are learned from email addresses, from "Name <email>" pairs and from name fields in JSON, then masked wherever they appear. The text after labels such as From, To and Attendees is masked whole. The rest of the function, not shown, masks cards, ID and account numbers, addresses, phone numbers and public IP addresses, then money and figures near business words.

  return function mask(text) {
    if (typeof text !== 'string' || text.length === 0) return text
    let out = text
    if (valueRe) out = out.replace(valueRe, DOTS)
    for (const re of SECRET_PATTERNS) out = out.replace(re, DOTS)
    out = out.replace(ASSIGNMENT, (_, name, sep) => name + sep + DOTS)

    // people, learned before the emails that name them are masked
    for (const m of out.matchAll(EMAIL)) {
      const n = namesFromEmail(m[0])
      if (n) learn(n)
    }
    out = out.replace(DISPLAY_NAME, (_, q, name, addr) => {
      learn(name)
      return KEEP_NAMES.has(name) ? q + name + q + addr : HIDE + addr
    })
    out = out.replace(PERSON_KEY, (_, head, value, tail) => {
      learn(value)
      return head + (KEEP_NAMES.has(value) ? value : HIDE) + tail
    })
    out = out.replace(PERSON_LINE, (line, label, value) => (KEEP_NAMES.has(value.trim()) ? line : label + HIDE))
    out = out.replace(EMAIL, '•••@•••')
    const re = nameRegex()
    if (re) out = out.replace(re, HIDE)

5. Keep private files closed

Masking changes only what is drawn. Private files get a tool.call hook instead. It checks the call's path, pattern, command and URL fields against the private path rules, and a finance tool against its own list. A match returns { deny }, so the tool never runs, and Claude is told to go on without it.

  // Private files and finance tools stay closed while recording
  on('tool.call', async ($, e, next) => {
    if (!rec.on) return next(e)
    const hit = financeTool(e.tool, config.closedTools) ? 'finance tools' : privatePathHit(toolCallTargets(e).join('\n'), config.privatePaths)
    if (!hit) {
      if (businessSource(e.tool, e, config.businessTools)) businessCalls.add(e.tool_use_id)
      return next(e)
    }
    blocked += 1
    return {
      deny: `Recording mode is on, so "${hit}" stays closed while the screen is being recorded. Continue without it, or ask the user to run /${commandName} off first.`,
    }
  })

6. Tell Claude

While recording, prompt.submit adds a note to the prompt's context. When recording stops, one more note says the earlier one no longer applies.

  // Claude reads a note beside each prompt while recording, and one more when it stops
  on('prompt.submit', async ($, e, next) => {
    const note = rec.on ? noteOn() : noteSent ? NOTE_OFF : null
    if (!note) return next(e)
    noteSent = rec.on
    return next({ ...e, context: [...(e.context ?? []), note] })
  })
function noteOn() {
  const keep = config.keepNames.length ? ` (other than ${config.keepNames.join(', ')})` : ''
  return (
    `Recording mode is on: this screen is being recorded for a public video. In replies and in tool commands, leave out people's names${keep}, emails, phone numbers, addresses, account numbers, dollar amounts, revenue, profit, pricing, compensation, and other business figures, and internal plans, strategy, deals, hiring, and team matters. ` +
    'Write placeholders like [name], [amount], or [internal plan] instead and keep summaries high level. Private files and finance tools stay closed until recording stops.'
  )
}

7. Show that it is on

Above the prompt, the mod adds a red ● REC on top of what is already drawn there, but not while a survey is open. In the terminal it is bold red text. Where the surface can draw an Svg, it is a small image with a pulsing dot. The footer gets the same label through SessionMode, so it shows even when the band is collapsed.

  // Just the indicator: a pulsing red dot and REC
  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const below = await next(e)
    if (e.props && e.props.hasSurvey) return below
    if (!rec.on) return below
    const el = $.ui.resolve(e)
    const line = e.surface === 'terminal' || !el.Svg
      ? el.Text({ color: 'red', bold: true, children: ['● REC'] })
      : el.Svg({ source: REC_SVG, alt: 'REC', width: 54, height: 18 })
    return el.Box({ flexDirection: 'column', children: below ? [line, below] : [line] })
  })

  // The footer label shows even when the band is collapsed
  on('ui.render', { component: 'SessionMode' }, async ($, e, next) => {
    if (!rec.on) return next(e)
    const modes = Array.isArray(e.props && e.props.modes) ? e.props.modes : []
    return next({ ...e, props: { ...e.props, modes: ['● REC', ...modes] } })
  })
Where the secrets go. The .env values are read only when recording turns on, and the source comment says they are "kept in memory only, never written anywhere". Turning off clears them.

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install recording-mode@waraxe-claude-mods

The upstream README asks for Claude Code 2.1.287 or later, with mods turned on for your account. Then open a new chat: a mod loads when a chat starts, and /reload-plugins does not reload it.

  • /rec turns it on, or off if it is on. It applies to every open chat within 3 seconds. A toast says "Recording mode on."
  • /rec strict also masks every large figure and percentage, wherever it appears.
  • /rec off turns it off everywhere. If it kept any private files closed, the toast says how many.
  • /rec config makes ~/.claude/mods-data/recording-mode/config.json the first time, with example values. Edit it, save, and run /rec again.
  • If /rec is taken, the command is /recording.

Settings. The config file has five lists:

  • keepNames: your own name and brand, shown even while recording.
  • names: people whose names are always masked. Names in emails and contact fields are picked up on their own.
  • privatePaths: folders or file names Claude may not open. Any part of a path matches, in any case.
  • businessTools: more tool or command names whose results draw as hidden.
  • closedTools: more tool names Claude may not call.

Cost. No model calls. While it is on, each prompt carries the short note from step 6. Every 3 seconds, each session reads the flag file. The upstream README says the mods make no network calls of their own.

Limits.

  • The README says it changes what is drawn and what Claude may open, not what is stored. Claude still gets the real tool results.
  • The README says pattern masking cannot catch everything written in plain words, so watch your footage before you publish.
  • The README says chat titles in the Desktop app's sidebar cannot be masked by a mod.
  • The hooks mask five components: UserMessage, AssistantMessage, CommandOutput, ToolUse and ToolResult. Text drawn by any other component is not masked.
  • .env values come from .env and .env.local in the session's folder and up to three folders above it, read when recording turns on.

Check yourself

Recording is on, and Claude reads a Gmail thread. What does the screen show, and what does Claude get?

The tool name matches the business tool list, so its result is drawn through hideText: any string over 24 characters, or with a space in it, shows as "••• hidden while recording". The hook changes only the props it passes to next in ui.render. The README says Claude still gets the real result.

Claude tries to read .env while recording. Why is that a deny and not a mask?

A mask changes only what is drawn, so the file would still be read. The tool.call hook returns { deny } instead, so the call never runs. It checks the command field too, so cat .env in Bash is refused the same way.
