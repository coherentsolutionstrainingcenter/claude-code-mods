What it is

collision-guard sits in front of Edit and Write. Before either tool changes a file, it checks whether another chat changed that same file in the last 30 minutes. If one did, it asks you to choose Proceed or Cancel, and Cancel refuses the edit.

It matters for your mission because it shows, in one short hook, the event, the calls and the refusal that you must be able to explain before you publish.

How it was built

1. Declare the hook module

The file hooks/hooks.json names one module, register.ts. The engine loads that module and calls the register function it exports.

{ "modules": ["./register.ts"] }

2. Pick the window and the tool

The 30-minute window is one constant, in milliseconds. The hook answers only for Edit and Write. Every other tool call goes straight to next(e), so it is not changed.

// A file another chat edited less than this long ago is a collision risk.
const WINDOW_MS = 30 * 60 * 1000

type Touch = { session: string; at: number }

export const register: Register = on => {
  on('tool.call', async ($, e, next) => {
    if (e.tool !== 'Edit' && e.tool !== 'Write') {
      return next(e)
    }

3. Ask when another chat touched the file

The store key is touch: followed by the file path. A record from a different session, less than 30 minutes old, triggers the question. Cancel, or a dialog that was dismissed, returns { deny }, and the engine gives that text to the model as an error result.

    const key = `touch:${e.file_path}`
    const session = await $.session.id()
    const last = (await $.store.get(key)) as Touch | undefined
    const now = await $.clock.now()

    if (last !== undefined && last.session !== session && now - last.at < WINDOW_MS) {
      const minutes = Math.max(1, Math.round((now - last.at) / 60000))
      // A dismissed dialog, or a run with no one to ask, rejects: that counts as Cancel.
      const choice = await $.ui
        .ask(`Another chat edited ${e.file_path} ${minutes} min ago. Edit it here too?`, ['Proceed', 'Cancel'])
        .catch(() => 'Cancel')

      if (choice !== 'Proceed') {
        return {
          deny: `Collision guard held this edit: another chat changed ${e.file_path} ${minutes} min ago, and the user chose not to continue. Do not retry unless the user asks you to.`,
        }
      }
    }
Why it waits. The hook awaits the question, so the tool call stays paused until you answer. The types say a hook's time limit counts only its own code, so the wait does not use it up. The .catch is there because the types say $.ui.ask also rejects when the dialog is dismissed and in a -p run, where no one can answer.
Why it fails open. The registration has no .catch of its own. The types say a guard that throws, or goes past its 10-second budget for its own code, is skipped and the tool runs. So a broken store or clock lets the edit through with no question. The README does not mention this.
Why no model call. The check needs only a session id, a time and a stored record. It sends nothing to a model, so it costs no tokens.

4. Record the touch after a good edit

After next(e) returns, the hook writes a new record only if the tool did not deny and did not error. The record holds this session and the current time. A Cancel never reaches this step, so the record keeps the other chat's name.

    const ran = await next(e)
    if (ran.deny === undefined && ran.isError !== true) {
      const touch: Touch = { session, at: await $.clock.now() }
      await $.store.set(key, touch)
    }

    return ran
Why the store, not state. $.store is kept between sessions and hot reloads, so a record written in one chat is still there when a later chat checks. This mod never deletes a record.

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install collision-guard@waraxe-claude-mods

The README and the source agree on the main behaviour. The README does not mention the fail-open case, or that only the latest editor is remembered.

  • Run /reload-plugins, or start a new session.
  • There are no settings. The hook runs for every Edit and Write.
  • When the question appears, choose Proceed to make the edit, or Cancel to refuse it. Closing the question counts as Cancel.
  • Cost: no model calls and no tokens. Each Edit or Write does one store read. A successful one also does one store write.

Limits

  • Only Edit and Write are checked. A shell command that changes a file, such as sed -i or a redirect, is not seen.
  • It keeps one record per file: the last successful edit, from any chat. An earlier chat's record is replaced.
  • The key is the exact file_path text. Edit and Write take absolute paths, so the same file under another name, such as a symlink, is not matched.
  • The check and the record are two separate store calls. Two chats that edit one file at the same moment can both pass the check. Read from the code; not tested.
  • If you choose Other and type exactly Proceed, the hook reads it as Proceed. The types say typed text comes back as it was typed.
  • A -p run has no one to ask, so an edit that would be held is refused.
  • Nothing deletes old records. The types say the store refuses writes that take it past 4 MiB of JSON in total.

Check yourself

Why does the hook return { deny } on Cancel, rather than throwing?

A deny is the documented refusal. The text goes back to the model as an error result, and the mod's message tells the model not to retry. A throw is a failed hook. The engine skips a failed hook and runs the tool, so a throw would let the edit through.

Chat A edits a file at 10:00. Chat B edits it at 10:05 and presses Proceed. Chat A edits it again at 10:10. What happens?

Chat A is asked. B's successful edit at 10:05 replaced A's record, so the record now names chat B. That record is five minutes old, inside the 30-minute window, so the question appears.

Why is the record written after next(e), not before?

Because next(e) runs the permission prompt and then the tool itself. A record written first would mark the file as changed even when the person denied permission or the edit failed. The hook checks ran.deny and ran.isError before it writes.
