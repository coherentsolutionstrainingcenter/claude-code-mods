What it is

where-am-i draws a band above the prompt. The first line is the session's goal. The second says what Claude is doing now and the next step. A yellow third line says what is waiting on you, when something is. After each turn in the main conversation, Haiku rewrites the recap from your last message, the tools Claude used and Claude's reply. /where gives a longer recap in a few bullets.

It covers this session only. The session monitor idea (2c), which would show every open chat as waiting, working or done, is video only, so there is no code to ship for it.

It matters for your mission because it calls a model after every turn, and you must be able to say when it calls, what it sends and what that costs before you tell others to install it.

How it was built

All the hooks are in hooks/register.tsx. hooks/bands.ts is a shared helper that stacks this band with other mods' bands.

1. Declare the hook module

hooks/hooks.json names one module. The engine loads it and calls the register function it exports.

{ "modules": ["./register.tsx"] }

2. Keep the recap in host state

The recap, the live "now" label and the latest turn id are atoms. The comment says the host holds them, so the recap survives a hot reload of the file. types/index.d.ts declares their types. The last line names state that belongs to the next-steps mod.

// Held by the host, so the recap survives a hot reload of this file.
const recap = atom({ plugin: 'where-am-i', key: 'recap' } as const, null as Recap | null)
const live = atom({ plugin: 'where-am-i', key: 'live' } as const, '')
// The turn a summary may still land for. Held by the host too, so a summary from before a hot reload sees a newer turn.
const latest = atom({ plugin: 'where-am-i', key: 'turn' } as const, '')
// True while the next-steps mod shows its list of next prompts: this band leaves out its own next meanwhile.
const nextStepsActive = { plugin: 'next-steps', key: 'active' } as const

3. Watch Claude's tool calls

The tool.call hook only observes: it adds a label to the turn's log and lets the call run untouched. Calls other mods make are skipped, because next.origin names that plugin, not the engine. A subagent's call is logged with (agent) in front, but does not change "now".

  // Observe only: note what is happening, then let the call run untouched.
  // Only Claude's own calls count: one another mod makes in the background (`$.tool.call`,
  // `$.mcp.call`) is raised by that plugin, and `next.origin` names it instead of the engine.
  on('tool.call', async ($, e, next) => {
    if (next.origin.plugin !== 'engine') return next(e)
    const line = describe(e as unknown as Record<string, unknown>)
    log = [...log, e.agentId ? `(agent) ${line}` : line].slice(-MAX_LOG)
    if (!e.agentId) await update($, live, () => line)
    const r = await next(e)
    return r
  })

4. Label a call in plain words

Each tool gets a short phrase. A file shows only its last two path parts.

// A short label for one tool call: what a person would say Claude is doing. A Bash call names
// its program, not the command line: the label is drawn and sent to Haiku.
export function describe(e: Record<string, unknown>): string {
  return clean(labelOf(e)).replace(/\s+/g, ' ')
}

function labelOf(e: Record<string, unknown>): string {
  const tool = String(e.tool)
  const s = (k: string) => (typeof e[k] === 'string' ? (e[k] as string) : '')
  const file = (p: string) => p.split('/').slice(-2).join('/')
  if (tool === 'Bash') return `running ${s('description') || program(s('command'))}`
  if (tool === 'Edit' || tool === 'Write') return `editing ${file(s('file_path'))}`
  if (tool === 'Read') return `reading ${file(s('file_path'))}`
  if (tool === 'Grep' || tool === 'Glob') return `searching for ${s('pattern').slice(0, 40)}`
  if (tool === 'Agent') return `starting an agent: ${s('description')}`
  if (tool === 'AskUserQuestion') return 'asking you a question'
  if (tool.startsWith('mcp__')) return `using ${tool.split('__').slice(1).join(' ')}`
  return `using ${tool}`
}

A Bash call with no description shows only its program, never its arguments. The comment says a token often sits in the arguments, and the label is both drawn and sent to Haiku.

// A command's program, never its arguments (a token often sits there): `curl -H "…" url` is `curl`,
// `cd /x && npm test` is `npm test`. A start that is no plain name (`FOO=1`, a quote, a subshell) says so.
export function program(command: string): string {
  const words = command.replace(/^\s*cd\s+\S+\s*(?:&&|;)\s*/, '').trim().split(/\s+/)
  const name = words[0]!.slice(words[0]!.lastIndexOf('/') + 1)
  if (!/^[\w.+-]{1,30}$/.test(name)) return 'a shell command'
  return SUBCOMMANDS.has(name) && /^[a-z][a-z-]{0,19}$/.test(words[1] ?? '') ? `${name} ${words[1]}` : name
}

5. Summarize when the turn ends

On turn.complete for the main conversation, the hook clears "now", records the turn id, and starts summarize without waiting. The comment says this runs in the background, so the turn ends at once. When you send a message, prompt.submit sets "now" to "reading your message" and clears "waiting on you", since you have just answered.

  on('turn.complete', async ($, e, next) => {
    const r = await next(e)
    if (!e.agentId) {
      await update($, live, () => '')
      const mine = e.turnId ?? ''
      await update($, latest, () => mine) // also for a turn that raised no turn.start, and after a hot reload
      const isCurrent = async () => (await read($, latest)) === mine
      void summarize($, prompt, log, e.answer, isCurrent).catch(() => {}) // in the background, so the turn ends at once
    }
    return r
  })

6. Ask Haiku for the recap

summarize sends the previous recap, your latest message, the tool labels and Claude's reply to $.model.complete on Haiku, and asks for JSON. If a newer turn started while Haiku was writing, the reply is dropped as stale. parseRecap then cuts each field to one sentence of at most 70 characters.

async function summarize($: EngineInterface, prompt: string, log: string[], answer: string, isCurrent: () => Promise<boolean>) {
  const before = await read($, recap)
  const r = await $.model.complete({
    model: MODEL,
    maxTokens: 300,
    system:
      'You keep a one-glance recap of a coding session for someone with ADHD. Plain words, no em dashes, ' +
      'each field at most 70 characters. Reply with JSON only: {"goal","now","waiting","next"}. ' +
      '"goal": the overall aim of the session (keep the previous goal unless it clearly changed). ' +
      '"now": what was just done. "waiting": what the assistant is waiting on from the person, or "". ' +
      '"next": the next step.',
    prompt: [
      `Previous recap: ${before ? JSON.stringify(before) : 'none'}`,
      `The person's latest message: ${prompt}`,
      `Tools used this turn: ${log.join('; ') || 'none'}`,
      `The assistant's reply: ${answer.slice(0, 2500)}`,
    ].join('\n\n'),
  })
  if (!r.isAnswered || !(await isCurrent())) return // a newer turn started while Haiku was writing: this recap is stale
  const parsed = parseRecap(r.text)
  if (parsed) await update($, recap, () => parsed)
}

7. Draw the band

The AbovePrompt hook calls next(e) first, so what other mods and Claude Code draw there stays. With no recap yet, or while a survey is open, it adds nothing. While the next-steps mod shows its list, the band leaves out its own "next". stackBands puts the band above the others, unless a band order file says otherwise.

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const rest = await next(e) // what other mods and Claude Code draw here stays
    const r = await read($, recap)
    if (e.props.hasSurvey || !r) return rest

    const { Box, Text } = $.ui.resolve(e)
    const now = clip((await read($, live)) || r.now)
    const { value: hasNextSteps = false } = await $.state.get(nextStepsActive)
    const nextStep = hasNextSteps ? '' : r.next

    const mine = (
      <Box flexDirection="column" paddingX={1}>
        <Text wrap="truncate-end">
          <Text color="cyan" bold>{'◆ Goal: '}</Text>
          <Text>{clip(r.goal)}</Text>
        </Text>
        <Text wrap="truncate-end">
          <Text dimColor>{'  now: '}</Text>
          <Text>{now}</Text>
          {nextStep !== '' && <Text dimColor>{'  ·  next: '}</Text>}
          {nextStep !== '' && <Text>{clip(nextStep)}</Text>}
        </Text>
        {r.waiting !== '' && (
          <Text color="yellow" wrap="truncate-end">{`  waiting on you: ${clip(r.waiting)}`}</Text>
        )}
      </Box>
    )
    bandOrder ??= readBandOrder($).catch(() => [])
    return stackBands(rest, 'where-am-i', mine, 'above', await bandOrder) // above what other mods draw, unless the band order says otherwise
  })

How to use it

claude plugin marketplace add <org>/waraxe-claude-mods
claude plugin install where-am-i@waraxe-claude-mods

Replace <org> with the GitHub account that hosts this marketplace. The upstream README says its mods need Claude Code 2.1.287 or later. Start a new session so the mod loads.

  • Send a message. When Claude's turn ends, the band appears: ◆ Goal:, then now: and next:, then waiting on you: in yellow when something is.
  • While Claude works, "now" shows the live tool label, such as editing hooks/register.tsx.
  • Type /where for a longer recap. It asks Haiku for at most 6 short bullets, from the last 12 messages. If Claude Code already has a /where, the mod starts without it.
  • There are no settings. One file can change the order of the bands: claude-code-mods/bands.json in CLAUDE_CONFIG_DIR, or in ~/.claude when that is not set. The source reads it once per session, so restart to apply a change. The upstream README says bands not in the file sit on top.
  • The next-steps plugin in this marketplace works with it: while its list of next prompts shows, where-am-i leaves out its own "next".

Cost. The upstream docs say it makes one Haiku call after each turn to write the summary. In the source, that call asks for up to 300 tokens. It sends the previous recap, the first 1,500 characters of your message, up to 20 tool labels, and the first 2,500 characters of Claude's reply. /where makes one more Haiku call, up to 500 tokens, with the last 12 messages at up to 800 characters each.

Limits.

  • It shows this session only, not your other open chats.
  • Each field is one sentence of at most 70 characters, cut at a word.
  • There is no band until the first recap lands, and none while a survey is open.
  • If the Haiku call fails, the band keeps the last recap. If a newer turn starts first, the late recap is dropped.
  • Only Claude's own tool calls change "now". Calls made by other mods are not counted.
  • Your message and Claude's reply go to Haiku as written, only cut to length. Only the tool labels leave out Bash arguments.

Check yourself

Why does turn.complete start summarize with void, and why does summarize call isCurrent?

The void lets the hook return without waiting for Haiku, so the turn ends at once. Because the call runs in the background, a new turn can start before it lands. isCurrent compares the turn id with the latest one, and a stale recap is dropped. The test "a summary that lands after the next turn starts is dropped" checks this.

Claude runs curl -H "Authorization: Bearer …" https://example.com in Bash with no description. What does the band show?

running curl. program keeps only the program's name, so the token in the arguments is neither drawn nor sent to Haiku as part of the label.
