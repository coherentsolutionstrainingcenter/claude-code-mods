What it is

usage-meter draws one line above the prompt. It shows each rate-limit window of your plan as a five-cell bar with a percent, the time until the first window resets, and the session's cost in dollars. The bars turn yellow at 75% and red at 90%, and a toast warns once when a window passes 90%.

It serves your mission because it is short and uses only three hook events, so you can point to each one and say why it is there.

How it was built

The hooks live in hooks/register.tsx. hooks/bands.ts stacks this line with the bands of other mods. The steps follow one reading, from the engine to the drawn line.

1. Declare the module

hooks/hooks.json names one module. The engine loads it and calls the register function it exports.

{ "modules": ["./register.tsx"] }

2. Keep the reading in atoms

An atom is a named value with a starting value. snapshot holds the last reading, tick counts clock ticks, and warned remembers which windows already got a toast. The source comment says the host holds them, so they survive a hot reload. types/index.d.ts gives each key its type.

// Held by the host, so they survive a hot reload of this file.
const snapshot = atom({ plugin: 'usage-meter', key: 'snapshot' } as const, null as UsageMeterSnapshot | null)
const tick = atom({ plugin: 'usage-meter', key: 'tick' } as const, 0)
const warned = atom({ plugin: 'usage-meter', key: 'warned' } as const, {} as Record<string, number>)

3. Take a reading at start and on every measurement

session.start starts a timer that bumps tick once a minute, but only while a window has a reset time. It then reads $.session.usage() once, so the line has numbers before the first reply. After that, session.measure brings each new reading. The types say it fires after each main-thread turn, and when a rate-limit window moves a whole point. Both hooks call next(e) first and return its result, so the event goes on unchanged.

  on('session.start', async ($, e, next) => {
    const result = await next(e)
    // Moves the reset countdown on while a window has a reset time.
    timer?.cancel()
    timer = $.clock.every(TICK_MS, () => {
      void (async () => {
        const snap = await read($, snapshot)
        if (snap?.rateLimits.some(w => w.resetsAt)) await update($, tick, n => n + 1)
      })().catch(() => {})
    })
    const usage = await $.session.usage().catch(() => null)
    if (usage) await take($, usage.rateLimits, usage.cost?.usd).catch(() => {})
    return result
  })

  on('session.measure', async ($, e, next) => {
    const result = await next(e)
    await take($, e.rateLimits, e.cost?.usd).catch(() => {})
    return result
  })

4. Store the windows and warn past 90%

take keeps only windows with a real percent, then writes the snapshot. warn shows one toast per window when it reaches 90% (WARN_AT). It stores the window's reset time. A later reading only warns again when the reset time has moved on by more than half an hour, which the comment calls a new period. A window with no reset time re-arms when it drops back under 90%.

async function take($: EngineInterface, rateLimits: readonly UsageMeterWindow[], costUsd: number | undefined) {
  const windows = rateLimits
    .filter(w => Number.isFinite(w.percentUsed))
    .map(w => ({ kind: w.kind, percentUsed: w.percentUsed, resetsAt: w.resetsAt }))
  await update($, snapshot, () => ({ rateLimits: windows, costUsd }))
  await warn($, windows)
}

// One toast per window per reset period, once it passes WARN_AT.
async function warn($: EngineInterface, windows: UsageMeterWindow[]) {
  const done = await read($, warned)
  const now = await $.clock.now()
  const fresh: Record<string, number> = {}
  const rearm: string[] = []
  for (const w of windows) {
    const resetMs = resetTime(w)
    if (w.percentUsed < WARN_AT) {
      // With no reset time, dropping back under the line is the only sign of a new period.
      if (resetMs === 0 && done[w.kind] !== undefined) rearm.push(w.kind)
      continue
    }
    const last = done[w.kind]
    // A reset time that moved on by more than half an hour is a new period.
    if (last !== undefined && resetMs <= last + 30 * 60_000) continue
    fresh[w.kind] = resetMs
    const when = resetMs > 0 ? `, resets in ${countdown(resetMs - now)}` : ''
    const what = w.kind === 'spend_limit' ? 'Spend limit' : `${label(w.kind)} usage limit`
    $.ui.toast(`${what} at ${Math.round(w.percentUsed)}%${when}`)
  }

5. Turn the snapshot into parts

build drops a window whose reset time has passed, then sorts the rest: 5h, 7d, then spend. Each window becomes a label, a bar and a percent. The first window always says when it resets. The others say so only from 75%. The cost is added last, and only when it is above zero.

export function build(snap: UsageMeterSnapshot, now: number): Part[] {
  const windows = snap.rateLimits
    .filter(w => !isStale(w, now)) // a window past its reset waits for a fresh reading
    .sort((a, b) => rank(a.kind) - rank(b.kind))
  const parts: Part[] = windows.map((w, i) => {
    const color = colorFor(w.percentUsed)
    const segments: Segment[] = [
      { text: `${label(w.kind)} `, dim: true },
      { text: bar(w.percentUsed), color },
      { text: ` ${Math.round(w.percentUsed)}%`, color },
    ]
    const resetMs = resetTime(w)
    // The first window always says when it resets; the others only once they run high.
    if (resetMs > 0 && (i === 0 || w.percentUsed >= 75)) {
      segments.push({ text: ` · resets ${countdown(resetMs - now)}`, dim: true })
    }
    return { kind: 'window', isPrimary: i === 0, segments }
  })
  if (snap.costUsd !== undefined && snap.costUsd > 0) {
    parts.push({ kind: 'cost', isPrimary: false, segments: [{ text: `$${snap.costUsd.toFixed(2)} session`, dim: true }] })
  }
  return parts
}

6. Drop parts until the line fits

fit measures the line in characters. While it is too wide, it removes the last window that is not the first one. If it is still too wide, it removes the cost. So a narrow terminal loses 7d first, then the cost.

// Drops the secondary windows first, then the cost, until the line fits.
export function fit(parts: Part[], columns: number): Part[] {
  let kept = [...parts]
  const tooWide = () => width(kept) > columns
  while (tooWide()) {
    const i = findLastIndex(kept, p => p.kind === 'window' && !p.isPrimary)
    if (i < 0) break
    kept.splice(i, 1)
  }
  if (tooWide() && kept.some(p => p.isPrimary)) kept = kept.filter(p => p.kind !== 'cost')
  return kept
}

7. Draw the line and stack it with other bands

The AbovePrompt hook calls next(e) first, so what other mods and Claude Code draw there is kept in rest. Reading tick makes the line redraw on each tick of the countdown. With a survey open or no reading yet, it returns rest untouched. Otherwise it builds the parts for bodyColumns - 2 cells and draws them as one row of Text. stackBands from bands.ts puts the line above the others, unless a band order file says otherwise.

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const rest = await next(e) // what other mods and Claude Code draw here stays
    await read($, tick) // redraws on each tick of the countdown
    const snap = await read($, snapshot)
    if (e.props.hasSurvey || !snap) return rest

    const parts = fit(build(snap, await $.clock.now()), e.props.bodyColumns - 2)
    if (parts.length === 0) return rest

    const { Box, Text } = $.ui.resolve(e)
    const segments: Segment[] = [{ text: '⏱ ', dim: true }]
    parts.forEach((p, i) => {
      if (i > 0) segments.push({ text: ' · ', dim: true })
      segments.push(...p.segments)
    })

    const mine = (
      <Box flexDirection="row" paddingX={1}>
        {segments.map((s, i) => (
          <Text key={String(i)} color={s.color} dimColor={s.dim} wrap="truncate">
            {s.text}
          </Text>
        ))}
      </Box>
    )
    bandOrder ??= readBandOrder($).catch(() => [])
    return stackBands(rest, 'usage-meter', mine, 'above', await bandOrder) // above what other mods draw, unless the band order says otherwise
  })

How to use it

claude plugin marketplace add <org>/waraxe-claude-mods
claude plugin install usage-meter@waraxe-claude-mods

Replace <org> with the GitHub owner of this marketplace. The marketplace README says to run /reload-plugins or start a new session after the install.

The plugin folder has no README of its own. The notes below come from the upstream repository's docs/mods.md, checked against the source.

  • One line appears above the prompt, starting with ⏱. For example: 5h, a bar, a percent and resets 2h05, then 7d with its bar, then $1.24 session.
  • Colors: green under 75%, yellow from 75%, red from 90%. Each time a window passes 90%, one toast says so, with the time to its reset when the window has one.
  • A window past its reset time hides until the next reading.
  • Without a subscription, the line shows only the cost. The types say rateLimits is empty off a subscription.
  • Commands: none. Settings: none. The manifest declares no userConfig.
  • Band order: the line reads claude-code-mods/bands.json under CLAUDE_CONFIG_DIR, or under ~/.claude. That file lists band mods from top to bottom. It is read once per session, so restart to apply a change.
  • Cost: no model call. The types say the plain $.session.usage() call costs nothing.

Limits

  • The types say AbovePrompt is raised on the terminal and desktop surfaces only.
  • The line hides while a survey holds the band.
  • The reset countdown moves once a minute (TICK_MS is 60,000 ms).
  • The figures are the ones the engine reports. The mod makes no request of its own.

Check yourself

Why does the AbovePrompt hook call next(e) before it draws anything?

rest holds what other mods and Claude Code draw in that slot. The hook returns it unchanged when a survey is open or there is no reading. Otherwise stackBands places this line above rest, so nothing beneath it is lost.

The 5h window passed 90% and showed a toast. The next reading says 93%, with the same reset time. Is there a second toast?

No. warned stores the reset time for that window. warn skips a window whose reset time is at most half an hour later than the stored one. A new toast needs a new period: a reset time more than 30 minutes later.
