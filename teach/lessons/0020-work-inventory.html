What it is

mission-control opens a pane with two views of the current turn. Who is a tree of the main loop, its subagents and every tool call they make, live. Code is a drawn map of the files Claude reads and edits, with arrows for the imports between them, a glow on the file it touches now, and one line on each change. A band line above the prompt sums it up while Claude works.

It serves your mission because it shows how four events, turn.start, agent.spawn, tool.call and turn.complete, build one shared picture, and where a mod calls a model and runs a process.

How it was built

hooks/hooks.json names one module, register.tsx. It holds the hooks. tree.ts turns the nodes into tree lines, map.ts draws the code map as SVG, and bands.ts stacks the band with other mods' bands. The steps follow one turn.

1. Keep the picture in atoms

An atom is a named value with a starting value. nodes is the tree, files the code map, view the open view, frame the last drawn picture, turn the turn number, and now the clock. The comment says the host holds them, so a hot reload keeps the picture.

// Held by the host, so a hot reload keeps the picture.
const nodes = atom({ plugin: 'mission-control', key: 'nodes' } as const, [] as MissionNode[])
const files = atom({ plugin: 'mission-control', key: 'files' } as const, [] as MapFile[])
const view = atom({ plugin: 'mission-control', key: 'view' } as const, 'who' as 'who' | 'code')
const frame = atom({ plugin: 'mission-control', key: 'frame' } as const, null as { file: string; n: number } | null)
const turn = atom({ plugin: 'mission-control', key: 'turn' } as const, 0)
const now = atom({ plugin: 'mission-control', key: 'now' } as const, 0)

2. Register /mission and a clock

On session.start the module notes whether it runs on Windows, registers /mission with the argument hint [who|code], and starts a one-second timer. The timer moves now only while a node is running, so the pane's times tick and then rest.

  on('session.start', async ($, e, next) => {
    const r = await next(e)
    isWindows = (await $.env.get('OS')) === 'Windows_NT'
    await $.command.register({ name: 'mission', description: 'Open the live map of agents and tool calls; /mission code opens the code map', argumentHint: '[who|code]' }).catch(() => {})
    timer?.cancel()
    timer = $.clock.every(1000, () => {
      void (async () => {
        const busy = (await read($, nodes)).some(n => n.status === 'running')
        if (busy) await update($, now, () => Date.now())
      })().catch(() => {})
    })
    return r
  })

3. Start a fresh tree each turn

turn.start counts the turn and clears last turn's changes. The tree restarts with a main node named after the prompt, cut at a word to about 50 characters. A background agent still running from the last turn carries over, with its open calls.

  on('turn.start', async ($, e, next) => {
    const t = (await read($, turn)) + 1
    await update($, turn, () => t)
    changes.clear()
    const main: MissionNode = { id: 'main', parent: null, kind: 'main', label: `main · ${words(e.text, 50)}`, family: 'main', status: 'running', start: Date.now() }
    // A background agent still running from the last turn carries over, with its open calls.
    await update($, nodes, list => {
      const agents = list.filter(n => n.kind === 'agent' && n.status === 'running').map(a => ({ ...a, parent: 'main' }))
      const ids = new Set(agents.map(a => a.id))
      const open = list.filter(n => n.kind === 'tool' && n.status === 'running' && ids.has(n.parent ?? ''))
      return [main, ...agents, ...open]
    })
    return next(e)
  })

4. Hang each subagent on its parent

agent.spawn calls next(e) first, so the subagent starts. The answer carries its agentId. The new node hangs under parentAgentId, or under main. cap keeps at most 300 nodes, and drops the oldest tool calls first.

  on('agent.spawn', async ($, e, next) => {
    const r = await next(e)
    if (r.agentId) {
      const id = r.agentId
      const agent: MissionNode = { id, parent: e.parentAgentId ?? 'main', kind: 'agent', label: e.description || e.subagentType, family: 'agent', status: 'running', start: Date.now() }
      await update($, nodes, list => cap([...list, agent]))
    }
    return r
  })

5. Add each tool call, then mark how it ended

The hook skips the Agent tool, because its subagent shows up through agent.spawn. It also skips Claude Code's own bookkeeping tools, such as ToolSearch and TaskCreate. Each other call becomes a running node, and a call with a file_path is noted on the code map. After next(e), the node is marked failed when the result has deny or isError, and done otherwise. A successful Edit or Write keeps a short copy of the change for step 6.

  on('tool.call', async ($, e, next) => {
    if (e.tool === 'Agent') return next(e) // its subagent shows up through agent.spawn
    if (INTERNAL.has(e.tool)) return next(e) // bookkeeping, not work a person would follow
    const args = e as unknown as Record<string, unknown>
    const { label: text, family } = label(args)
    const id = e.tool_use_id
    await update($, nodes, list => {
      // A call from an agent this tree does not know hangs off main rather than nowhere.
      const parent = e.agentId && list.some(n => n.id === e.agentId) ? e.agentId : 'main'
      return cap([...list, { id, parent, kind: 'tool', label: text, family, status: 'running', start: Date.now() }])
    })
    const raw = typeof args.file_path === 'string' ? args.file_path : undefined
    const path = raw && isWindows ? raw.replace(/\\/g, '/') : raw // one separator, so names and imports resolve
    if (path) await touch($, path, e.tool === 'Read' ? 'read' : e.tool === 'Write' ? 'write' : e.tool === 'Edit' ? 'edit' : 'search', false)

    let failed = true
    let r: Awaited<ReturnType<typeof next>>
    try {
      r = await next(e)
      failed = r.deny !== undefined || r.isError === true
    } finally {
      await update($, nodes, list => list.map(n => (n.id === id ? { ...n, status: failed ? 'failed' : 'done', end: Date.now() } : n)))
    }
    if (path && !failed && (e.tool === 'Edit' || e.tool === 'Write')) {
      const what = e.tool === 'Edit' ? `- ${String(args.old_string ?? '').slice(0, 300)}\n+ ${String(args.new_string ?? '').slice(0, 300)}` : `wrote ${String(args.content ?? '').slice(0, 400)}`
      const list = [...(changes.get(path) ?? []), what]
      changes.set(path, list.length > MAX_CHANGES ? [list[0]!, ...list.slice(1 - MAX_CHANGES)] : list) // the first edit and the latest few
      await touch($, path, e.tool === 'Edit' ? 'edit' : 'write', true)
    }
    return r
  })

6. Write one line per changed file with Haiku

When the main turn ends, turn.complete starts explain in the background, so the turn ends at once. explain makes one $.model.complete call to Haiku, with at most 400 tokens out. It sends the last two parts of each changed file's path and the text of its changes, and asks for a JSON array of short lines. The answers are matched by position. An answer that arrives after the next turn started is dropped.

async function explain($: EngineInterface, forTurn: number, edits: Map<string, string[]>) {
  if (edits.size === 0) return
  const paths = [...edits.keys()]
  const plain = (t: string) => t.replace(/[<>"]/g, ' ')
  const body = paths.map((p, i) => `<file n="${i + 1}" name="${plain(p.split('/').slice(-2).join('/'))}">\n${plain((edits.get(p) ?? []).join('\n').slice(0, 1500))}\n</file>`).join('\n')
  const r = await $.model.complete({
    model: 'haiku',
    maxTokens: 400,
    system: 'For each file, say in plain words what changed, at most 60 characters, no em dashes. Reply with a JSON array of strings only, one per file, in the same order.',
    prompt: `${body}\n\nReply with the JSON array only: ${paths.length} strings.`,
  })
  if (!r.isAnswered) return
  let whys: unknown
  try {
    whys = JSON.parse(r.text.slice(r.text.indexOf('['), r.text.lastIndexOf(']') + 1))
  } catch {
    return
  }
  if (!Array.isArray(whys)) return
  // By position, so nothing has to match a path the model may have rewritten.
  const byPath = new Map(paths.map((p, i) => [p, typeof whys[i] === 'string' ? (whys[i] as string).replace(/\s*—\s*/g, ', ').slice(0, 80) : undefined]))
  // A slow answer from an earlier turn must not label this turn's changes.
  if ((await read($, turn)) !== forTurn) return
  await update($, files, list => list.map(f => (byPath.get(f.path) && f.changedTurn === forTurn ? { ...f, why: byPath.get(f.path) } : f)))
  await renderSoon($)
}

7. Draw the code map with headless Chrome

renderMap writes the map as an SVG file, then runs Chrome or Chromium headless to take a PNG screenshot of it. The comment says Chrome uses its own throwaway profile, never your browser. The two PNG files take turns, so the one on screen is never half written. The pane shows the PNG with an Image. renderSoon draws only while the code view is open in a placed pane, after a short wait.

  const tmp = ((await $.env.get('TMPDIR').catch(() => undefined)) ?? '/tmp').replace(/\/$/, '')
  const dir = `${tmp}/mission-control`
  const n = ++draw.n
  const width = Math.round(draw.size.columns * 9)
  const height = Math.round(draw.size.rows * 19)
  const svgPath = `${dir}/map.svg`
  const png = `${dir}/map-${n % 2}.png` // two files in turn, so the shown one is never half written
  await $.fs.write(svgPath, svg(await read($, files), { width, height, at: Date.now(), turn: await read($, turn) }))
  // Headless Chrome writes the screenshot but does not always exit: wait for the file,
  // then close that Chrome (its own throwaway profile, never the person's browser).
  const script =
    'mkdir -p "$(dirname "$2")"; rm -f "$2"; "$1" --headless=new --disable-gpu --hide-scrollbars --force-device-scale-factor=2 --no-first-run --no-default-browser-check ' +
    '--user-data-dir="$3" --window-size="$4" --screenshot="$2" "$5" >/dev/null 2>&1 & pid=$!; ' +
    'i=0; while [ ! -s "$2" ] && [ $i -lt 150 ]; do sleep 0.1; i=$((i+1)); done; sleep 0.2; pkill -P $pid 2>/dev/null; kill $pid 2>/dev/null; [ -s "$2" ]'
  const r = await $.process.run(['sh', '-c', script, 'mission-control', chrome, png, `${dir}/chrome`, `${width},${height}`, `file://${encodeURI(svgPath)}`], { timeoutMs: 20_000 })
  if (r.exitCode === 0) {
    await update($, frame, () => ({ file: png, n }))
    return
  }
  draw.error = `${chrome} could not draw the code map.`
  await update($, now, () => Date.now()) // redraw the pane with the message
}

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install mission-control@waraxe-claude-mods

The marketplace README says to run /reload-plugins or start a new session after the install.

The plugin folder has no README of its own. The notes below come from the upstream repository's README and docs/mods.md, checked against the source.

  • Type /mission to open the pane. /mission code opens straight to the code map, and /mission who to the agents.
  • In the pane, press w for Who, c for Code and q to close.
  • On the code map, a file glows blue while Claude reads it, orange while it edits it, and turns green with a check once changed.
  • While Claude works, and for 30 seconds after, a band above the prompt reads ◈ mission: with the agents, tool calls, failures and files changed.
  • Commands: /mission only. Settings: none. The manifest declares no userConfig.
  • Cost: one Haiku call after each main turn that changed files, with at most 400 output tokens. The Who view and the band call no model.

Limits

  • The Code view runs on macOS and Linux. It needs Google Chrome or Chromium, and a terminal that shows images. The upstream notes name Ghostty, kitty and iTerm2.
  • On Windows, the Code view lists the map as lines, and b opens the drawn map in your browser. The Who view works everywhere.
  • On the desktop surface, the Code view says only "The code map draws in the terminal."
  • The code map keeps the 14 newest files, and only code, config and docs files. Images and binaries are left out.
  • The text of each change goes to Haiku: up to 300 characters of the old and new text of an edit, or 400 of a written file, and at most 1,500 characters per file.
  • The map files are written under $TMPDIR/mission-control, or /tmp/mission-control. On Windows the page is mission-control-map.html in TEMP.

Check yourself

Why does the tool.call hook pass the Agent tool straight to next(e)?

The comment says its subagent shows up through agent.spawn. That hook adds the agent as its own node, with its agentId. The subagent's own tool calls carry that id, so they hang under its node.

Haiku's answer for turn 4 arrives after turn 5 has started. What happens to it?

It is dropped. explain reads turn again and returns when it is no longer forTurn. The comment says a slow answer from an earlier turn must not label this turn's changes.
