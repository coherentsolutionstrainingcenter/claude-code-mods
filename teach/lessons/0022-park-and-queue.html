Park and queue

Park and queue holds a message you type while Claude is busy, and sends it once the current turn ends, so the running turn is not changed.

What it is

Park and queue catches a message typed while Claude is working. The best version, claude-queue, does this with a /q command and a band above the prompt box that lists the held messages. You can reorder, edit or drop them while the turn runs.

For your mission, which asks you to name the hook events and calls a mod uses, this mod is a good full read: it uses nine events and nine calls, all in one file.

How it was built

The plugin is one hooks module, hooks/register.ts, which hooks/hooks.json names as its only module. The steps below follow one message from the moment you type it to the moment it is sent. Each snippet is copied from the file, and the line numbers tell you where it sits.

1. Register /q as an immediate command (lines 387 to 399)

On session.start, the mod registers a command named q. The immediate: true flag lets it run while a turn is going. The source comment says the queue only fills while a turn runs, which is why the flag is set. The .catch logs a failed registration and lets the session continue.

  on('session.start', async ($, e, next) => {
    const r = await next(e)
    await $.command
      .register({
        name: COMMAND,
        description: 'Hold a prompt until the turn ends: /q <text>; list, up/down/mv, now, rm, edit, clear, send, status (prompt-queue)',
        argumentHint: '[<text> | up <n> | down <n> | mv <n> <m> | now <n> | rm <n> | edit <n> | clear | send | status]',
        // the queue is worked on while a turn runs, which is the only time it fills
        immediate: true,
      })
      .catch(err => $.ui.log(`queue: /${COMMAND} not registered: ${err}`))
    return r
  })

2. Hold the text on a stack (lines 531 to 537)

Any text after /q that is not a subcommand, such as up, rm or send, is pushed onto stack. Each entry is an object with an id and its text. If a turn is running, or background work is still going, the entry waits. Otherwise the mod calls send.

    // anything else is the prompt to hold
    stack.push({ id: `e${++counter}`, text: e.args.trim() })
    $.ui.invalidate('ui.render')
    if (turnId) return { text: `queue: held · ${stack.length} waiting · sent when the turn ends` }
    if (inFlight > 0) return { text: `queue: held · ${stack.length} waiting · sent when the background work ends` }
    send($)
    return { text: `queue: nothing is running · sending${stack.length > 1 ? ` · ${stack.length} waiting` : ''}` }

3. Drain the stack when the turn ends (lines 409 to 427)

turn.complete clears the running turn id. Entries still in the steer list go back to the front of the stack. If background work is still running, the drain waits. The count comes from classic.Stop (lines 432 to 435), which reads the engine's background_tasks list. The drainedTurn check allows one drain per turn, even if more than one ending event fires for it.

  on('turn.complete', async ($, e, next) => {
    const r = await next(e)
    // a subagent's turn ends inside the session's own: not a moment to send
    if (e.agentId) return r
    turnId = undefined
    if (drainedTurn === e.turnId) return r
    drainedTurn = e.turnId
    // the turn called no tool after all: what was pushed into it leads the drain
    if (steer.length > 0) stack.unshift(...steer.splice(0))
    // a turn that left work running in the background is a pause, not an end:
    // the notification that wakes it starts the turn whose end drains
    if (inFlight > 0) {
      $.ui.invalidate('ui.render')
      return r
    }
    // every ending drains, an Esc included: what was typed was asked for
    send($)
    return r
  })

4. Wait out the gap, then submit (lines 121 to 141)

The engine refuses a plugin's prompt that comes within 5 seconds of the last one. GAP_MS is 5200 milliseconds. When the gap has not passed, flush schedules itself with $.clock.after. Otherwise it takes the next entry, or the stack up to a slash command when the joined option is on. The submit itself is on lines 154 and 155.

// Synchronous up to the submit itself, so two sends landing together (a
// turn's end and a press) cannot both take an entry: the second one sees
// sentAt and waits the gap out. The submit is not awaited: it resolves only
// once the prompt entered, which is after the hook that asked for it answered.
const flush = ($: EngineInterface) => {
  pending = null
  if (stack.length === 0) return
  // a turn started under the timer: nothing is sent into one, and its own end
  // arms the next drain
  if (turnId) return
  const wait = GAP_MS - (Date.now() - sentAt)
  if (wait > 0) {
    pending = $.clock.after(wait, () => flush($))
    $.ui.invalidate('ui.render')
    return
  }
  const going = takeDue()
  sentAt = Date.now()
  if (editing && indexOfId(editing.id) < 0) editing = null
  $.ui.invalidate('ui.render')
  const run = slash(going[0]!.text)

5. Steer a message into the running turn (lines 437 to 460)

The [ ▶ ] button and /q now move an entry into a list called steer. On the next tool.call from the main loop, the hook adds the framed text to the tool result's context. It returns the same object it was given, so the tool's own messages are kept. The user sees only a one-line log from $.ui.log. An entry that would take the result past 32,000 characters (CONTEXT_MAX) stays in steer for later.

  // The steer route: a mid-turn message rides the next tool result's context,
  // which is how the engine delivers one. The object `next` gave us goes back
  // whole, `ref` and all, so the tool's own messages are used verbatim.
  on('tool.call', async ($, e, next) => {
    const r = await next(e)
    // a subagent's call runs inside the turn but is not it
    if (steer.length === 0 || e.agentId || r.deny !== undefined) return r
    const context = [...(r.context ?? [])]
    let used = context.reduce((n, text) => n + text.length, 0)
    const going = steer.splice(0)
    for (const entry of going) {
      const framed = frame(entry)
      if (used + framed.length > CONTEXT_MAX) {
        steer.push(entry)
        continue
      }
      used += framed.length
      context.push(framed)
      $.ui.log(`pushed into the turn · ${fit(firstLine(entry.text), 72)}`)
    }
    if (steer.length > 0) $.ui.log(`queue: ${steer.length} too long for a tool result · goes when the turn ends`)
    $.ui.invalidate('ui.render')
    return context.length === (r.context?.length ?? 0) ? r : { ...r, context }
  })

6. Draw the band and keep a backstop (lines 540 to 548)

The ui.render hook for AbovePrompt draws the band through bandOf. The same hook is a backstop. If entries are held, no turn is running, nothing is in flight, and no drain is pending, it schedules a drain with $.clock.after(0, ...). The band's buttons call $.ui.invalidate('ui.render') so the band redraws after each press.

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    if (e.surface !== 'terminal' || e.props.hasSurvey || stack.length + steer.length === 0) return next(e)
    // The backstop: a stack found idle goes out rather than sitting here. By
    // our own count of the turn alone: `isWorking` reads false while a tool
    // runs under the fullscreen renderer, so it cannot clear `turnId`. Deferred
    // past this dispatch, from which a submit would be refused.
    if (!turnId && inFlight === 0 && !e.props.isWorking && !pending && failures < RETRIES) pending = $.clock.after(0, () => flush($))
    return bandOf($, e)
  })

How to use it

The README names a marketplace called gal-mods. The clone has no marketplace file, so I could not confirm that name on disk.

claude plugin marketplace add galElmalah/claude-mods
claude plugin install prompt-queue@gal-mods
  • Turn on function hooks in ~/.claude/settings.json: { "env": { "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1" } }.
  • Ask Claude for something slow. While it works, type /q and your next message, then press Enter.
  • Type /q alone to list what is held. Then use /q up 2, /q rm 1, /q now 1 or /q send.
  • In fullscreen (/tui fullscreen), click the band's buttons. On the classic renderer, press ctrl+x tab, then Tab to a button and Enter.
  • Optional: turn on the joined option with /plugin configure prompt-queue to send the whole stack as one prompt.

What it costs. The code makes no model calls. Each held message that goes out is one ordinary turn, so it costs what that turn costs.

Limits.

  • The engine spaces a plugin's prompts 5 seconds apart. The README says it allows 50 a session.
  • The engine frames a held prompt as sent by the prompt-queue plugin. The text is yours, but the framing is the engine's.
  • Mouse clicks need the fullscreen renderer. Text only: an image goes into the turn as it always did.
  • An Esc does not hold the stack back, so anything typed behind an interrupt goes out.
  • Function hooks are early access, so the API can change between releases. A hot reload of the module empties the stack.

Check yourself

You type a line without /q while Claude is working. Does the mod hold it?

No. The source leaves Enter to the engine, so the line goes into the running turn as it always did. Only a line that starts with /q is held.

Why does a held prompt wait 5.2 seconds after the last one?

The engine refuses a plugin prompt that comes within 5 seconds of the previous one. The mod keeps a gap of 5200 milliseconds (GAP_MS) before it submits the next entry.
