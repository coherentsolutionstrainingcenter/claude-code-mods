spend-guard

What it is

This family stops a costly or public step until you approve it. The two best variants were video only: credit saver (28a) asked before a paid generation, and publish lock (31) showed a checklist before a publish. spend-guard is our own build of both ideas in one hook. It holds publish and deploy commands in Bash (npm publish, docker push, git push to main, and others) and MCP tools whose names say they publish, post, send, charge or generate images and video. It asks once, counts your approvals for the day, and refuses the call on anything but Proceed.

For your mission, this is the plainest example of a guard: one event, five calls on $, and a refusal you can explain line by line before you publish the marketplace.

How it was built

1. Declare the module and one setting

hooks/hooks.json names the one hooks module. The manifest declares one userConfig field, so you can add your own patterns without editing code. The engine hands its value to register as options.extraPatterns.

{ "modules": ["./register.ts"] }
  "userConfig": {
    "extraPatterns": {
      "type": "string",
      "title": "Your own patterns",
      "description": "Comma-separated text to hold as well. Each is matched, ignoring case, inside a Bash command and inside every tool name. Example: fly deploy, stripe, mcp__replicate",
      "default": ""
    }
  }

2. Name what counts as a spend or a publish

Bash commands are matched with regular expressions anywhere in the command, so a publish after cd is still caught. MCP tools are matched by whole words in the tool's own name (the part after mcp__server__), so send_message is held and mcp__postgres__query is not.

// Shell commands that publish or deploy. Each is matched anywhere in a Bash
// command, so `cd app && npm publish` is held too.
const PUBLISH_COMMANDS = [
  /\b(npm|pnpm|yarn)(\s+npm)?\s+publish\b/,
  /\btwine\s+upload\b/,
  /\bdocker\s+(image\s+)?push\b/,
  /\bgh\s+release\s+create\b/,
  /\bvercel\b[^;&|\n]*\s--prod\b/,
]

// A word in an MCP tool's own name that means the call spends or publishes.
const PAID_TOOL = /(^|_)(publish|deploy|post|send|charge|generate_image|generate_video)(_|$)/

3. Read your own patterns once, at load

register receives options with the manifest's defaults filled in. The patterns are split and lowercased once, when the module loads. A change in /config reloads the module, so the list is read again.

export const register: Register = (on, options) => {
  const extra = String(options.extraPatterns ?? '')
    .toLowerCase()
    .split(',')
    .map(p => p.trim())
    .filter(p => p !== '')

4. Decide, then ask

The hook runs for every tool call. A call that is not a spend or a publish goes straight to next(e), unchanged. For one that is, the hook reads today's count from $.store and asks with $.ui.ask. The question carries the command or tool, the checklist and the count. $.ui.ask rejects when the dialog is dismissed and in a -p run, so the .catch turns both into Cancel.

  on('tool.call', async ($, e, next) => {
    const what = await describeRisk($, e, extra)
    if (what === undefined) {
      return next(e)
    }

    const day = localDay(await $.clock.now())
    const tally = (await $.store.get('approvals')) as Tally | undefined
    const count = tally?.day === day ? tally.count : 0

    // A dismissed dialog, or a run with no one to ask, rejects: that counts as Cancel.
    const choice = await $.ui
      .ask(
        [
          'This call may cost money or publish something.',
          what,
          'Check: right account? right file? right destination?',
          `Approved today: ${count}. Proceed?`,
        ].join('\n'),
        { options: ['Proceed', 'Cancel'], header: 'Spend guard' },
      )
      .catch(() => 'Cancel')
Why the checklist is in the question. $.ui.ask takes option labels only, so the dialog's options carry no descriptions. Everything you need to check has to be in the question text.

5. Refuse on anything but Proceed, count on Proceed

Cancel, a dismissed dialog, or any other answer returns { deny }: the tool never runs, and the model reads the text as an error result. Proceed writes the new count and calls next(e), which runs Claude Code's own permission check and then the tool. The registration's .catch makes the guard fail closed: if the hook throws before next, the call is held, not let through.

    if (choice !== 'Proceed') {
      return {
        deny: `spend-guard held this call: the person did not approve it. Do not retry unless they ask. (${what})`,
      }
    }

    const approved: Tally = { day, count: count + 1 }
    await $.store.set('approvals', approved).catch(() => undefined)

    return next(e)
  }).catch(($, e, next) =>
    // A guard that fails holds the call rather than letting it through.
    next.called
      ? next(e)
      : { deny: 'spend-guard could not check this call, so it held it. Ask the person before you try again.' },
  )
Why the store, not state. $.store is kept across sessions, so the count covers every chat you ran today on this machine. The record holds the day, so the first call after midnight reads a count of 0.

6. Tell a Bash call from an MCP call

e.tool === 'Bash' narrows e, so e.command is typed. Any other tool is matched by its name. Your own patterns are tested against both.

async function describeRisk($: EngineInterface, e: ToolCallInput, extra: string[]): Promise<string | undefined> {
  if (e.tool === 'Bash') {
    const command = e.command.toLowerCase()
    const isHeld =
      PUBLISH_COMMANDS.some(re => re.test(command)) ||
      extra.some(p => command.includes(p)) ||
      (await pushesToMain($, e.command))

    return isHeld ? `Bash: ${clip(e.command)}` : undefined
  }

  const name = e.tool.toLowerCase()
  const ownName = e.tool.startsWith('mcp__') ? e.tool.split('__').slice(2).join('_') : undefined
  const isHeld = (ownName !== undefined && PAID_TOOL.test(words(ownName))) || extra.some(p => name.includes(p))

7. Find a push to main, even a bare one

A refspec that names main or master is held at once. A bare git push, or one that pushes HEAD, goes wherever the checked-out branch goes, so the hook asks git with $.process.run. A failed or slow git answers '', which is no branch, and the push passes.

    if (refspecs.length === 0 || targets.includes('HEAD')) {
      const dir = push[1]?.match(/-C\s+(\S+)/)?.[1]
      if (MAIN_BRANCHES.includes(await currentBranch($, dir))) {
        return true
      }
    }
async function currentBranch($: EngineInterface, dir: string | undefined): Promise<string> {
  const run = await $.process
    .run(['git', 'branch', '--show-current'], { cwd: dir, timeoutMs: 5000 })
    .catch(() => undefined)

  return run?.exitCode === 0 ? run.stdout.trim() : ''
}

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install spend-guard@waraxe-claude-mods
  • There is no command. The guard runs on every tool call and asks only for the calls it holds.
  • When the question appears, check the account, the file and the destination, then choose Proceed or Cancel. Closing the question counts as Cancel.
  • Add your own patterns with /plugin configure spend-guard or /config, for example fly deploy, stripe, mcp__replicate.
  • Cost: no model calls and no tokens. A held call does one store read, an approval one store write, and a bare git push one git branch --show-current.

Limits

  • It matches text. A command that only mentions a pattern, such as a commit message about npm publish, asks too. A publish hidden in a script, such as npm run release, is not seen unless you add a pattern.
  • For a bare git push it reads the branch in the session's folder, or the folder git -C names. After cd other && git push it still reads the session's folder.
  • An option that takes a separate value, such as git push -o ci.skip origin, can be read as the remote, so that push may pass.
  • There is no balance check. Credit saver checked the balance first, but no API reaches an arbitrary service's balance, so the mod does not pretend to.
  • The count is today's Proceed presses on this machine, across sessions. It counts approvals, not successful runs.
  • A -p run has no one to ask, so every held call is refused there.
  • After Proceed, Claude Code's own permission prompt still appears for a tool you have not already allowed.

Check yourself

The question is on screen and you press Esc. What happens to the call, and which line makes that so?

The call is refused. $.ui.ask rejects when the dialog is dismissed, .catch(() => 'Cancel') turns the rejection into 'Cancel', and any answer other than 'Proceed' returns { deny }, so next(e) never runs.

Claude runs a plain git push while main is checked out. Does spend-guard ask? How does it know the branch?

Yes. The push names no refspec, so refspecs is empty, and the hook runs git branch --show-current through $.process.run. It answers main, which is in MAIN_BRANCHES, so the call is held and the question appears.
