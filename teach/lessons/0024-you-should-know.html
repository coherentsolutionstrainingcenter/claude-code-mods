What it is

You Should Know (mod 19) is a side agent built into Claude Code. It watches your back while Claude works on a longer task and shows what you might miss above the prompt. It ships inside Claude Code as cc-plugin-you-should-know@builtin, its code is not on disk, and so it cannot go into this marketplace. heads-up is a small version we can ship and read: when a main-loop turn ends with a long reply, it asks Haiku once about four kinds of missed fact or skipped step, and shows at most two.

  • The built-in You Should Know watches while a longer task runs. Its code cannot be read here; claude plugin details reports no hooks and about 0 tokens added to every session. You turn it on with /plugin enable cc-plugin-you-should-know@builtin.
  • heads-up looks once, after the turn ends, and only at four things: a failed tool result the reply did not mention, files changed beyond what was asked, tests not run after code changes, and a risky step taken. Every line of it is in one file.
  • assumption-check (lesson 0007) lists the guesses Claude made in the reply: a reading of what you meant, a default, a name picked without asking. heads-up does not list guesses; its prompt tells Haiku to leave them out. It reports facts in the tool results and steps that were skipped.

For your mission, this mod shows how several events work together: a counter, a log, a model call and a band, each in its own hook, so you can name every event it uses and say why.

How it was built

1. Declare the values the band reads

What a drawing reads lives in $.state, which outlives a hot reload, unlike a module variable. The contract declares two values under the plugin's name, and plugin.json names the file as "types". claude plugin validate holds every state key the module uses to this contract.

declare module 'claude-code' {
  interface PluginState {
    'heads-up': {
      /** What the band shows: at most two short lines, [] when there is nothing to flag. */
      flags: string[]
      /** How many prompts the person has sent in this session. */
      prompts: number
    }
  }
}
const flags = atom({ plugin: 'heads-up', key: 'flags' } as const, [] as string[])
const prompts = atom({ plugin: 'heads-up', key: 'prompts' } as const, 0)

2. Register the switch

session.start reads the switch from $.store, which is kept across sessions, and registers /heads-up. The command.run hook answers the command itself, so nothing beneath it runs. A missing value is not true, so the mod starts off.

  on('session.start', async ($, e, next) => {
    isOn = (await $.store.get('isOn')) === true
    await $.command.register({
      name: 'heads-up',
      description: 'Turn heads-up on or off: up to two things you might miss after a long turn',
      argumentHint: 'on|off',
    })

    return next(e)
  })

  on('command.run', { command: 'heads-up' }, async ($, e) => {
    const arg = e.args.trim().toLowerCase()
    if (arg === 'on' || arg === 'off') {
      isOn = arg === 'on'
      await $.store.set('isOn', isOn)
      await update($, flags, () => [])
    }

3. Count the person's prompts

prompt.submit also fires for slash commands, hidden prompts and task notifications. Only a prompt the person sent counts, and its text is kept as the request the check compares against.

  on('prompt.submit', async ($, e, next) => {
    if (e.command === undefined && e.isMeta !== true && isPerson(e.origin)) {
      asked = e.text
      await update($, prompts, n => n + 1)
    }

    return next(e)
  })

4. Log the turn's tool calls

turn.complete carries the reply but not the tool results, so the mod keeps its own log. turn.start on the main loop starts a fresh one and clears old flags. The tool.call hook awaits next(e), which runs the tool, then records what came back. Calls inside a subagent carry agentId and are left out.

  on('tool.call', async ($, e, next) => {
    const ran = await next(e)
    if (isOn && e.agentId === undefined && steps.length < MAX_STEPS) {
      steps.push(toStep(e, ran))
    }

    return ran
  })
  const isFailed = ran.deny !== undefined || ran.isError === true
  const said = ran.deny ?? ran.text ?? ''

5. Decide whether the turn is worth a call

The hook calls next(e) first, so the turn ends normally whatever happens below. Then every condition from the spec is a plain check: on, main loop, ended with an answer (which leaves out an interrupted turn), a reply of 300 characters or more, past the third prompt. A turn with no tool calls has nothing in the four categories, so it skips the call too.

  on('turn.complete', async ($, e, next) => {
    const done = await next(e)
    // reason 'answer' leaves out an interrupted turn, a refusal and an API error.
    if (!isOn || e.agentId !== undefined || e.reason !== 'answer' || e.answer.length < MIN_REPLY) {
      return done
    }
    if (steps.length === 0 || (await read($, prompts)) <= QUIET_PROMPTS) {
      return done
    }

6. Ask Haiku in the background

The model call is not awaited, so the prompt comes back at once and the band appears a few seconds later. latest remembers which turn asked: if a new turn started meanwhile, the old answer is dropped. $.model.complete never rejects over what the provider did; it resolves isAnswered: false, which reads as no flags.

    const turnId = e.turnId
    latest = turnId
    // In the background, so the prompt comes back at once (the approach of
    // next-steps by Hamza Zafar, MIT, in this repository; this code is new).
    void (async () => {
      const found = await findFlags($, asked, e.answer, steps)
      if (found.length > 0 && latest === turnId) {
        await update($, flags, () => found)
      }
    })().catch(() => undefined)

The prompt names the four categories and keeps heads-up apart from assumption-check by telling the model to leave guesses out.

    'Claude just finished a turn of work. Name at most two facts the person might miss. Only these count:',
    '- a tool call that failed, was not fixed by a later call, and the reply does not mention it',
    '- files changed beyond what the request asked for',
    '- code changed, and no test or build ran after the change',
    '- a risky step taken: a force push, a hard reset, deleted files, a migration, a publish or deploy, a change outside the project',
    'Do not list guesses or assumptions the reply made, style advice, or anything the reply already tells the person.',
Why a module-level function. findFlags takes $ as an argument, and the validator follows $ only into functions declared at the top of the file. A helper declared inside register and handed $ fails validation.

7. Draw the band with Dismiss

The render hook calls next(e) first, so whatever other mods draw above the prompt stays, below the flags. With no flags, or while a survey holds the band, it returns that alone. read subscribes the band to flags, so the background update redraws it, and the Dismiss press empties it.

    return (
      <Box flexDirection="column">
        <Box flexDirection="column" paddingX={1}>
          {list.map(flag => (
            <Text>
              <Text color="warning" bold>
                heads-up{' '}
              </Text>
              {flag}
            </Text>
          ))}
          <Button key="dismiss" label="Dismiss" role="dismiss" onPress={() => update($, flags, () => [])} />
        </Box>
        {rest}
      </Box>
    )

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install heads-up@waraxe-claude-mods
  • Type /heads-up on in the Claude Code prompt. It stays on in later sessions until you type /heads-up off. /heads-up alone says whether it is on.
  • From the fourth prompt of a session, after a reply of 300 characters or more in which Claude used a tool, the band may show one or two lines. Read them, check what they name, then press Dismiss. The band also clears when the next turn starts.
  • To compare with the built-in, turn that on with /plugin enable cc-plugin-you-should-know@builtin.
  • Cost: one Haiku call per checked turn, up to about 17,000 characters in (about 4,500 tokens) and at most 250 tokens out. Nothing is sent while it is off, in the first three prompts, or for a turn with no tool calls.

Limits

  • Haiku can miss something or flag something harmless. A flag is a hint to check, not a verdict.
  • It sees only the main conversation's tool calls, the first 60 of a turn. Inside a subagent it sees only the Agent call and its answer.
  • Outputs are cut: a failure's first 300 characters, a Bash run's last 200. The request is cut at 2,000 characters and the reply at 6,000.
  • The prompt count starts with the session, so a resumed session counts from zero.
  • The band is the AbovePrompt site, which the types say is drawn on the terminal and the desktop app only. VS Code and mobile show nothing.
  • It looks once, after the turn. It cannot warn you while the work is still running, as the built-in does.

Check yourself

It is the second prompt of a new session. Claude ran npm test, the test failed, and the 900-character reply does not say so. Does heads-up call Haiku?

No. The prompt count is 2, and the turn.complete hook returns early while read($, prompts) is at most QUIET_PROMPTS (3). From the fourth prompt the same turn would be checked.

Which mod reports "you assumed I wanted TypeScript", and which reports "npm test failed and the reply does not say so"?

assumption-check reports the first: it is a guess Claude made about what you meant. heads-up reports the second: it is a fact in the tool results that the reply left out. heads-up's prompt tells Haiku not to list guesses, so the two do not overlap.
