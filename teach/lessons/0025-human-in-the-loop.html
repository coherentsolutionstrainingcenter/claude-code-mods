What it is

Human in the loop gives Claude a tool called assign_task. When Claude needs something only you can do, it files a task. The task waits in a My tasks pane under the prompt, and your answer goes back to Claude as a message.

For your mission, which asks you to name the hook events and calls a mod uses, this mod is a clear example of a function-hook mod that adds its own tools, a pane and a turn-end hook, all in its main module, register.tsx.

How it was built

The mod is one hooks module, hooks/register.tsx, which hooks/hooks.json names. The other files hold the logic. tasks.ts reads a task from Claude's call and sets what Claude is told. project.ts keeps each session's tasks in the project's store. text.ts holds the label helpers. The steps below use the main module, with line numbers.

1. Register the tools and the command (lines 327 to 336)

On session.start, the mod registers its tools with $.tool.register, which are assign_task, list_tasks and withdraw_task. It registers /my-tasks with $.command.register. Then join takes on the project's open tasks, which is how they carry over to a new session.

  on('session.start', async ($, e, next) => {
    for (const tool of TOOLS) {
      await $.tool.register(tool)
    }

    await $.command.register({ name: 'my-tasks', description: 'Show the tasks Claude gave you' })
    await join($)

    return next(e)
  })

2. Guard the assign call (lines 389 to 398)

When Claude calls assign_task, the tool.call hook refuses a call from a subagent. Only the main agent may assign tasks. Then it parses the input, and a bad input gets a deny with the parser's reason. A cap also applies. MAX_OPEN is 5, set in tasks.ts, and the check on lines 423 to 427 refuses a sixth open task.

  on('tool.call', { tool: ASSIGN }, async ($, e) => {
    if (e.agentId !== undefined) {
      return { deny: 'Only the main agent assigns tasks to the user. Say what you need from the user in your result instead.' }
    }

    const ask = parseAsk(e as unknown as Record<string, unknown>)

    if ('error' in ask) {
      return { deny: ask.error }
    }

3. Hold answers until Claude is free (lines 549 to 573)

On turn.complete, for the main loop only, the hook checks whether answers are waiting. It sends them when no task is still open, or when you pressed Send now. The send is send($, true), and its message wakes Claude. Answers that arrive during a turn wait, so Claude is not interrupted. The rest of the handler, from line 574, handles one more case and is left out here.

  on('turn.complete', async ($, e, next) => {
    const result = await next(e)

    // Main's turn ending ends every turn; another loop's ends its own.
    if (e.agentId === undefined) {
      live.turns.clear()
      live.engineWorking = false
    } else {
      live.turns.delete(e.turnId)
    }

    await syncWorking($)

    if (e.agentId === undefined) {
      // Answers saved while Claude worked go now that it's free, unless a
      // task is still open: then they go with that last answer, together.
      // One a prompt entered without goes with them, but sends nothing alone.
      const all = await read($, tasks)
      const isAllAnswered = all.some(task => task.update === 'pending' && !live.held.has(updateKeyOf(task))) && !all.some(isActive)

      if (live.isSendingAtEnd || isAllAnswered) {
        live.isSendingAtEnd = false
        // This message wakes Claude, which reads any row it missed above it.
        live.isUnread = false
        void send($, true)

4. Draw the pane (lines 746 to 753)

The ui.render hook for the Pane component draws the My tasks pane. It calls $.ui.resolve(e) to get the drawing parts, such as Box, Text and Button. It adds an Input only when the surface is not mobile, because the mobile app draws no answer field yet. A separate ui.focus hook (line 735) handles keyboard focus for the same pane.

  on('ui.render', { component: 'Pane', requestId: PANE }, async ($, e) => {
    const emptied = live.emptied.get(e.surface)
    const elements = $.ui.resolve(e)
    const { Box, Text, Button } = elements
    // The mobile app draws no field yet: answers and reasons wait for a surface
    // that does. The engine fills an element a surface lacks with one that draws
    // nothing, so the surface says, not the table.
    const Input = e.surface !== 'mobile' && 'Input' in elements ? elements.Input : undefined

How to use it

The marketplace and the plugin share the name human-in-the-loop. Run these in the shell:

claude plugin marketplace add tzafrir/human-in-the-loop
claude plugin install human-in-the-loop@human-in-the-loop

Then start a new session, or run /reload-plugins.

  • Make sure function hooks are on. The README says the mod loads only where they are enabled. It does not name the setting.
  • Let Claude work. When it needs you, a task appears in My tasks, and the status line shows the count, such as ☐ 3 tasks for you · /my-tasks.
  • Open the pane with /my-tasks, or press ctrl+x tab to give it the keyboard.
  • Answer with d (done), a number for an option, r (an answer) or x (reject, with a reason).
  • For a long answer, such as a log, use the Long answer button. It starts the prompt box, and you paste the text and press Enter.

What it costs. The README says the mod makes no network calls and runs no processes. The code makes no model calls. It adds three tools and a few lines to the system prompt. At the start of a conversation, or after a compaction, it also adds a short list of open tasks.

Limits.

  • At most 5 open tasks at a time. The same ask twice counts as one task.
  • Only the main agent assigns tasks. A subagent says what it needs in its result.
  • An answer that looks like a secret, such as an API key or a private key, is held with a warning before it is sent.
  • Function hooks are early access, so the API can change between releases.

Check yourself

You answer a task while Claude is still working. When does Claude get the answer?

When Claude finishes its turn, unless another task is still open. In that case the answer waits and arrives with that task's answer. Send now sends it straight away.

Claude tries to assign a sixth open task. What happens?

The call is refused. MAX_OPEN is 5 in tasks.ts, and the refusal tells Claude to withdraw a task you no longer need, or wait for you to act.
