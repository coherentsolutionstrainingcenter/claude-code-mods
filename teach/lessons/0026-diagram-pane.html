What it is

Diagram pane is a side pane that pins each mermaid chart or ASCII box diagram in Claude's replies. It also keeps a small map of the files and steps in the work, and a cheap check decides when to redraw it.

For your mission, which asks you to say why each hook and call is used, this mod is the clearest example here of one that calls the model and keeps state, so it shows where a call goes and where the saved state lives.

How it was built

The mod is one hooks module, hooks/register.js. hooks/hooks.json names it. draw.js lays out the charts and the map, and graph.js holds the tree of boxes. The six steps below follow the main module from start to finish. Each snippet is copied from register.js, and the line numbers tell you where it sits.

1. Open the pane and register the command and tools (lines 70 to 90)

On session.start, the mod opens the pane with $.ui.open. It registers /diagram with $.command.register, and registers the two tools for Claude with $.tool.register. In a headless session, the handler returns at once and draws nothing.

  on('session.start', async ($, e, next) => {
    // Set at each session.start. In -p / SDK sessions there is no pane to draw into
    headless = e.isInteractive === false
    if (headless) return next(e)
    // Open the pane right away. Unasked, it is placed on a wide terminal (144+ columns);
    // /diagram opens it at any width.
    await $.ui.open({ id: PANE, title: 'Diagrams' })
    try {
      await $.command.register({ name: 'diagram', description: 'Redraw the live work map in the diagram pane', argumentHint: '[force|open]' })
    } catch (err) {
      $.ui.log('could not add /diagram: ' + err.message)
    }
    for (const tool of TOOLS) {
      try {
        await $.tool.register(tool)
      } catch (err) {
        $.ui.log(`could not add ${tool.name}: ` + err.message)
      }
    }
    return next(e)
  })

2. Pin diagrams and count turns (lines 93 to 109)

On turn.complete, the mod skips subagent turns and aborted turns. Then it reads the transcript through sync. The README says new diagrams are pinned at this point. The mod counts turns in S.sinceMap. When the count reaches everyTurns (3 by default), it runs the gate. The environment variable DIAGRAM_PANE_EVERY overrides the count for one session.

  on('turn.complete', async ($, e, next) => {
    const result = await next(e)
    // Headless: no pane, so skip, unless DIAGRAM_PANE_SYNC or DIAGRAM_PANE_DUMP asks for the work
    const asked = (await $.env.get('DIAGRAM_PANE_SYNC')) || (await $.env.get('DIAGRAM_PANE_DUMP'))
    if ((headless && !asked) || e.agentId || e.isAborted) return result
    const messages = await sync($)
    S.sinceMap += 1
    if (!headless && S.pins.length && !(await $.ui.panes()).some(p => p.id === PANE)) await $.ui.open({ id: PANE, title: 'Diagrams' })
    S.every = Number(await $.env.get('DIAGRAM_PANE_EVERY')) || every
    if (S.sinceMap >= S.every || overdue()) {
      const work = overdue() ? catchUp($, messages) : refreshMap($, messages, false)
      // Headless runs exit when the hook returns, so tests can ask us to wait
      if (await $.env.get('DIAGRAM_PANE_SYNC')) await work
    }
    await redraw($)
    return result
  })

3. Ask Haiku whether the work changed shape (lines 249 to 263)

Before a redraw, the mod asks a cheap question. $.model.complete is sent to haiku with the current map, the files touched since, and a digest of the activity. It sets maxTokens: 5, so only a short answer comes back. The gate runs only when a map already exists and /diagram force was not used.

    // 1. The cheap gate: skipped only when there is no map yet, or on /diagram force
    if (S.map && !force) {
      S.note = 'gate: checking if the work changed shape...'
      await redraw($)
      const activity = messages.slice(S.mapAt)
      const gate = await $.model.complete({
        model: 'haiku',
        system: GATE_SYSTEM,
        prompt: `CURRENT MAP: ${mapSummary()}\n\nFILES TOUCHED SINCE, NOT ON THE MAP: ${newFiles(activity).join(', ') || 'none'}\n\n` +
          `ACTIVITY SINCE THE MAP WAS DRAWN:\n${digest(activity)}\n\n` +
          'Answer YES if the map is now out of date: the work touched files or components the map lacks, added a step ' +
          '(such as tests, a new feature, a fix), or moved to a different task. Answer NO only if the map still shows the work. YES or NO?',
        maxTokens: 5,
        timeoutMs: 20000,
      })

4. Fork the session to draw the map (lines 271 to 278)

After a yes from the gate, the mod forks the session. The gate is skipped for the first map and for /diagram force, so the fork runs then too. $.model.fork asks the session itself for the map as JSON. A fork sees the whole conversation, but it cannot call tools, so the map holds only what the session has seen. If /clear ran while the fork was working, the generation check on line 278 drops the result.

    // 2. The fork: the session's own context, asked for JSON. It cannot call tools.
    // /diagram force draws from scratch; otherwise the fork builds on the current map.
    const base = force ? null : S.map
    const edits = S.mapEdits
    S.note = 'fork: drawing the work map...'
    await redraw($)
    const r = await $.model.fork({ prompt: FORK_PROMPT + (base ? basePrompt(base) : '') })
    if (gen !== S.gen) return // /clear ran meanwhile: this map is the old session's

5. Save the map in the store (lines 339 to 347)

The map, the edited pins and the view are saved per session, under the key maps, in $.store. The mod keeps only the 20 newest sessions. That is how the map survives a hot reload or --resume. The matching reader, loadSaved, is on lines 329 to 337.

async function saveSaved($) {
  if (S.sessionId === null) return
  const maps = (await $.store.get('maps')) || {}
  // Edits of pins that fell off the pane are no longer needed
  const edits = Object.fromEntries(Object.entries(S.edits).filter(([code]) => pinOf(code)))
  maps[S.sessionId] = { map: S.map, mapAt: S.mapAt, edits, view: S.view, at: await $.clock.now() }
  // Keep the 20 newest sessions only
  const keep = Object.entries(maps).sort((a, b) => b[1].at - a[1].at).slice(0, 20)
  await $.store.set('maps', Object.fromEntries(keep))

6. Let Claude read and change the pane (lines 135 to 146)

Claude has two tools. diagram_get returns the current map as mermaid. diagram_set changes one level of the map, or a pinned diagram. Each call syncs the transcript first. If diagram_set fails, the mod returns a deny message, and the pane is left as it was.

  on('tool.call', { tool: TOOL_SET }, async ($, e) => {
    try {
      await sync($)
      const text = setDiagram(resolveTarget(String(e.target || 'view')), e)
      await saveSaved($)
      if (!(await $.ui.panes()).some(p => p.id === PANE)) await $.ui.open({ id: PANE, title: 'Diagrams' })
      await redraw($)
      return { result: text }
    } catch (err) {
      return { deny: 'diagram_set: ' + err.message }
    }
  }).catch(() => ({ deny: 'diagram_set failed; the pane is unchanged.' }))

How to use it

The marketplace is named claude-code-mods, which is the name in its marketplace.json. Run these in the shell:

claude plugin marketplace add ray-amjad/claude-code-mods
claude plugin install diagram-pane@claude-code-mods
  • Start Claude in a terminal. The pane opens by itself in a terminal 144 columns or wider. Narrower than that, type /diagram once.
  • Ask for a diagram, such as "explain the checkout flow with a mermaid flowchart". It is pinned when the turn ends.
  • /diagram runs the gate now and redraws the map if the work changed. /diagram force redraws the map from scratch and drops your edits. /diagram open gives the pane the keyboard.
  • Press a number to open a box, b to go back, and t to go to the top. Press c to type a change into the field under a diagram.
  • Settings: everyTurns (default 3) and maxPins (default 5). Change them with /plugin configure diagram-pane@claude-code-mods.

What it costs. Every few turns, one Haiku call with a five-token limit. A fork of the session runs when the gate says yes, and for the first map or /diagram force, which skip the gate. The README says a fork is mostly served from the prompt cache.

Limits.

  • Only mermaid graph and flowchart charts are redrawn. Other chart types are pinned as raw code.
  • Number keys reach the first nine boxes of a level. Tab or a click reaches the rest.
  • A fork cannot call tools, so a box's detail holds only what the session has already seen.
  • The map check runs after a turn ends, not while Claude is working.
  • The map is saved per install. Reinstalling the plugin, or moving it to another marketplace, starts with no saved maps.

Check yourself

When does diagram-pane call the model, and which call is the bigger one?

After every few turns (everyTurns, default 3), it makes a short Haiku gate call with $.model.complete. A yes from the gate leads to $.model.fork. So do the first map and /diagram force, which skip the gate. The fork is the bigger call, because it sees the whole conversation.

Where does the map go when you come back with --resume?

It is saved under the key maps in $.store, keyed by session id. The mod keeps the 20 newest sessions, and the mod reads it back with loadSaved.
