What it is

Decision tree is one hook module, hooks/register.jsx. After each reply, a regex and a small model call check whether Claude is asking you to choose. If it is, a model fork explains each option in a side pane, and you can explore any option in a forked session.

It matters for your mission because this one file uses several hook events and API calls, so it is a good test of whether you can name each call and say why it is there.

How it was built

The mod is one file with one register function. That function declares each hook with on(...). The steps below follow the order in which the code runs.

1. Check the end of the reply with a regex

This check costs nothing, so it runs first. It looks at the last paragraph for a question mark. It also accepts two or more numbered or lettered options with a word such as which or choose. Most replies stop here.

// Cheap check, no model: does the end of the reply ask something?
// A question mark in the last paragraph, or a numbered / lettered / bulleted list of options.
function looksLikeQuestion(answer) {
  const tail = answer.trim().slice(-1500)
  const paragraphs = tail.split(/\n\s*\n/)
  const last = paragraphs[paragraphs.length - 1] || ''
  if (/\?\s*(\*\*|_|`)?\s*$/.test(last) || /\?\s*$/m.test(last)) return true
  const options = tail.match(/^\s*(\d+[.)]|[A-D][.):]|[-*]\s+\*\*Option|Option [A-D1-9])/gm) || []
  return options.length >= 2 && /\b(which|prefer|choose|pick|want|should I|let me know)\b/i.test(tail)
}

2. Ask a small model to confirm the question

needsDecision sends the last 2000 characters of the reply to the gate model with $.model.complete. It allows at most 5 output tokens and waits up to 20 seconds. Only an answer that starts with yes counts. The caller passes options.gateModel, which defaults to haiku.

// The gate: a small model confirms the question needs a real decision from the user
async function needsDecision($, answer, model) {
  const r = await $.model.complete({
    model,
    system: 'You read the end of an AI coding assistant reply. Answer YES if it ends by asking ' +
      'the user to decide, choose, or supply something before work can go on. Answer NO for ' +
      'rhetorical questions, pleasantries such as "anything else?", or a reply that just reports. ' +
      'Reply with YES or NO only.',
    prompt: answer.trim().slice(-2000),
    maxTokens: 5,
    timeoutMs: 20000,
  })
  return r.isAnswered && /^\s*yes/i.test(r.text)
}

3. Explain the choice with a fork

explainRoot makes the reply the root of the tree, and opens the pane with a reading message. Then $.model.fork asks for JSON with the question, the options, what each leads to, pros and cons, and a recommendation. The call passes only a prompt. The prompt asks the fork not to use tools. The call itself sets no tool list.

async function explainRoot($, answer) {
  const node = { sid: await $.session.id(), answer, status: 'thinking', children: [] }
  root = node
  path = []
  view = 'node'
  await openPane($, false)
  $.ui.invalidate('ui.render')

  const r = await $.model.fork({
    prompt: 'Your last reply ended by asking me a question. Do not answer it and do not use tools. ' +
      'Help me answer it. Reply with JSON only, no code fence, in this shape: ' + SHAPE + '. ' +
      'Use the options you offered; if you offered none, give the 2 to 4 answers I would most ' +
      'likely pick. At most 2 pros and 2 cons each. No em or en dashes.',
  })
  settle(node, r.isAnswered ? r.text : '', r.isAnswered ? 'the fork did not return JSON' : r.reason)
  if (root !== node) return
  $.ui.invalidate('ui.render')
}

4. Run the check when a turn ends

The turn.complete hook calls next(e) first, so Claude Code finishes its own work. Then it skips headless runs, unless DECISION_TREE_WAIT is set. It also skips subagent replies, branch runs, and any turn that did not end with an answer. The fork runs in the background, so the prompt is not held up. A -p run waits for it only when the wait flag is set.

  on('turn.complete', async ($, e, next) => {
    const result = await next(e)
    // Headless: nothing would be shown, so skip the gate and the fork, unless DECISION_TREE_WAIT asks for it
    const wait = (await $.env.get('DECISION_TREE_WAIT')) === '1'
    if (headless && !wait) return result
    // A branch's own claude -p run never explains its own replies
    if ((await $.env.get('DECISION_TREE_CHILD')) === '1') return result
    if (e.agentId || e.reason !== 'answer' || !looksLikeQuestion(e.answer)) return result
    if (!(await needsDecision($, e.answer, options.gateModel || 'haiku'))) return result
    // Run the fork without holding up the prompt; in a -p run, wait so the process lives on
    const work = explainRoot($, e.answer).catch(err => $.ui.log('decision-tree failed: ' + err))
    if (wait) await work
    return result
  })

5. Explore an option by forking at that question

explore starts claude -p with --resume and --fork-session. It cuts the fork at the message that asked the question, using --resume-session-at. The branch may use Read, Grep and Glob only. Bash, Edit, Write and NotebookEdit are disallowed. If the message cannot be found, the branch forks from the latest point, and the code logs that.

  const args = ['claude', '-p', whatIf(option),
    '--resume', node.sid, '--fork-session', '--output-format', 'json',
    '--permission-mode', 'default', '--allowedTools=Read,Grep,Glob',
    '--disallowedTools=Bash,Edit,Write,NotebookEdit']
  if (node.msgId) args.push('--resume-session-at', node.msgId)

  let out = null
  try {
    const run = await $.process.run(args, {
      cwd: await $.session.cwd(),
      env: { DECISION_TREE_CHILD: '1' },
      timeoutMs: 300000,
    })
    out = resultOf(run.stdout)

6. Draw one box per option

The pane is a ui.render hook for the Pane component, with the request id question. For each option it draws a box. The box shows the detail, what the option leads to, its pros and cons, and an Explore button. The recommended option gets a green border.

        {data.options.map((o, i) => {
          const isPick = o.label === pick && !o.mine
          const child = node.children[i]
          const color = isPick ? 'green' : o.mine ? 'yellow' : 'gray'
          return (
            <Box key={'opt' + i} flexDirection="column">
              <Text dimColor>{'  │'}</Text>
              <Box borderStyle={isPick ? 'bold' : 'round'} borderColor={color} paddingX={1} flexDirection="column">
                <Text bold color={color === 'gray' ? 'white' : color}>{String.fromCharCode(65 + i) + '  ' + o.label + (isPick ? '   ★ recommended' : '') + (o.mine ? '   ✎ your answer' : '')}</Text>
                {o.detail ? <Text>{o.detail}</Text> : null}
                {o.leadsTo ? <Text color="blue">{'→ ' + o.leadsTo}</Text> : null}
                {(o.pros || []).map((p, j) => <Text key={'p' + j} color="green">{'+ ' + p}</Text>)}
                {(o.cons || []).map((c, j) => <Text key={'c' + j} color="red">{'- ' + c}</Text>)}
                <Button key={'x' + i} label={child ? (child.status === 'exploring' ? 'Exploring...' : 'Open branch ▸') : 'Explore ▸'}
                  onPress={() => explore($, i)} />
              </Box>
            </Box>
          )
        })}

7. Add the /explain command

session.start registers /explain in an interactive session. The command.run hook reads its argument. A letter from A to H explores that option. The word other, followed by text, explores your own answer. map, back, top and continue move around the tree.

  on('command.run', { command: 'explain' }, async ($, e) => {
    if (!root) return { text: 'No question to explain yet.' }
    const raw = (e.args || '').trim()
    const arg = raw.toLowerCase()
    view = arg === 'map' ? 'map' : 'node'
    if (arg === 'back') path = path.slice(0, -1)
    else if (arg === 'top') path = []
    else if (arg === 'continue') await continueBranch($, nodeAt(path))
    else if (/^[a-h]$/.test(arg) || /^other\s+\S/.test(arg)) {
      const own = /^other\s/.test(arg) ? raw.replace(/^other\s+/i, '') : undefined
      const work = explore($, own ? -1 : arg.charCodeAt(0) - 97, own).catch(err => $.ui.log('explore failed: ' + err))
      if ((await $.env.get('DECISION_TREE_WAIT')) === '1') await work
    }
    $.ui.invalidate('ui.render')
    await openPane($, true)
    return {}
  })
Where the README and the source differ.
  • The README says an Explore branch takes 12 to 20 seconds. The pane says "about 20 to 60s". Each branch run may take up to five minutes.
  • The README says the fork "has no tools". The call passes no tool list. Only the prompt asks the fork not to use tools.
  • The README shows the branch command in a short form. The code also passes --output-format json, --permission-mode default and the allow and deny lists.

How to use it

claude plugin marketplace add ray-amjad/claude-code-mods
claude plugin install decision-tree@claude-code-mods

The marketplace name is claude-code-mods, from .claude-plugin/marketplace.json.

  • Ask Claude something that needs a choice, such as "Which storage should I use?" If the reply ends with that question, the pane opens.
  • Press Explore on an option, or type /explain b to explore option B. The pane shows what that branch would do, its steps, and the next question.
  • Type your own answer in the Other box, or run /explain other <answer>.
  • Run /explain map to see the whole tree. Run /explain back or /explain top to move up.
  • Run /explain continue to get a command that opens the branch as a live session. Inside Herdr, the command runs in a new pane. Elsewhere, it is copied to your clipboard.

Nothing you pick in the pane goes back to Claude. You still answer in the prompt.

Cost. Each reply that passes the regex makes one call to the gate model. Each explanation makes one fork, which replays the whole session. The README says that replay is served from the prompt cache. Each Explore runs a full claude -p process, and the README says a branch costs a full turn.

Limits.

  • In -p and SDK runs the pane is never drawn. Nothing runs unless DECISION_TREE_WAIT=1 is set.
  • If Claude Code cannot place the pane, a toast says to run /explain. The README says Claude Code places the pane only in a terminal at least 144 columns wide.
  • The tree lives in the mod's memory. A new question, a restart or a reload clears it. Branch sessions stay on disk, and you can resume them by id.
  • --resume-session-at is an undocumented Claude Code flag. The README says it was tested on version 2.1.296.

Check yourself

Why does the mod run a regex before it calls any model?

The regex costs nothing, and most replies do not end with a question. The gate model runs only when looksLikeQuestion returns true. So most turns make no model call.

Why can an Explore branch read files but not change them?

The code allows only Read,Grep,Glob with --allowedTools. It blocks Bash,Edit,Write,NotebookEdit with --disallowedTools. The branch can look at the code and plan, but it cannot edit files or run commands.
