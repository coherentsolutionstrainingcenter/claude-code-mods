What it is

jev-skill-suggestion is one hook module of 456 lines. After you stop typing for 600 ms, it asks TypeSafe's Jev API to rank your skills against the draft, in two requests at most. Then it applies one of three modes: observe, block or steer. In block and steer mode, it refuses Skill tool calls that do not fit the mode.

It matters for your mission because it sends your draft text to an outside service, and you must be able to point to the hook that does that.

How it was built

The module is one file. It reads your settings at start, scores drafts while you type, and checks each skill load. The steps follow the order in which the code runs.

1. Read the key and the saved settings at start

The register function takes the apiKey option. At session.start, the hook falls back to the TYPESAFE_API_KEY variable if that option is empty. It restores the mode, the on and off switch, and the list of skills you turned off. Then it scans the skill folders and registers /jev.

  on('session.start', async ($, e, next) => {
    runtime.apiKey ||= (await $.env.get('TYPESAFE_API_KEY')) ?? ''
    const storedMode = await $.store.get('mode')
    if (typeof storedMode === 'string' && MODES.includes(storedMode as Mode)) {
      await update($, mode, () => storedMode as Mode)
    }
    if ((await $.store.get('enabled')) === false) await update($, enabled, () => false)
    const storedDisabled = await $.store.get('disabled')
    if (Array.isArray(storedDisabled)) await update($, disabled, () => storedDisabled.map(String))
    runtime.disk = await scanDisk($, e.cwd)
    await update($, roster, () => mergeRoster(runtime.disk, runtime.listed))
    await $.command.register({
      name: 'jev',
      description: 'Jev skill scores: open the skills pane, `/jev observe|block|steer`, or `/jev off|on`',
    })
    return next(e)
  })

2. Score the draft after a pause

The prompt.edit hook runs as you type. It cancels the last timer and starts a new 600 ms timer. Drafts shorter than 8 characters, and drafts that start with a slash, are not scored. For those, the last verdict stays on show.

  // Live scoring as the person types, once the draft has been still a moment.
  on('prompt.edit', async ($, e, next) => {
    const box = await next(e)
    if (box.text === e.text || !(await read($, enabled))) return box
    runtime.timer?.cancel()
    const draft = box.text.trim()
    // Short drafts and slash commands keep the last verdict on show.
    if (draft.length < MIN_CHARS || draft.startsWith('/')) {
      runtime.asked++
      await update($, status, () => '')
      return box
    }
    runtime.timer = $.clock.after(DEBOUNCE_MS, () => void score($, draft))
    return box
  })

3. Ask Jev one question per skill

The ask function sends one POST to the API address set on line 9, with the model jev-latest. The key goes in a bearer header. The reply holds one answer per question. If the response is not OK, the function throws.

async function ask($: Engine, state: unknown, questions: Record<string, unknown>) {
  const response = await $.http.fetch(API, {
    method: 'POST',
    headers: { Authorization: `Bearer ${runtime.apiKey}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ state, model: MODEL, questions }),
  })
  if (!response.ok) throw new Error(`Jev ${response.status}: ${response.text.slice(0, 160)}`)
  return JSON.parse(response.text).answers as Record<
    string,
    { choice?: string; probabilities?: Record<string, number>; noul?: number }
  >
}

4. Rank every skill and check the gate

The first request asks which skill fits. Each skill's description is cut to 250 characters. It also asks three yes-or-no gate questions. gateOf averages the three answers. It flips prose_suffices, so a high value means a skill is needed. If the average is under 0.30, no skill is picked, and the second request is never sent.

  const wideQuestions: Record<string, unknown> = {
    which: {
      type: 'choice',
      instructions: "Which of these skills, if any, is the right one to load to help with the user's latest request?",
      criteria: Object.fromEntries(skills.map(skill => [skill.name, skill.description.slice(0, 250) || skill.name])),
    },
  }
  for (const [key, instructions] of Object.entries(GATE_QUESTIONS)) {
    wideQuestions[`gate::${key}`] = { type: 'noul', instructions }
  }
  const wide = await ask($, state, wideQuestions)
  const ranked: Ranked[] = Object.entries(wide.which?.probabilities ?? {})
    .map(([name, probability]) => ({ name, probability }))
    .sort((a, b) => b.probability - a.probability)
  const gate = gateOf(
    Object.fromEntries(
      Object.entries(wide)
        .filter(([key]) => key.startsWith('gate::'))
        .map(([key, answer]) => [key.slice('gate::'.length), answer.noul ?? 0]),
    ),
  )

5. Re-read the top three

If the gate passes, the top three skills go to a second request. Each one gets its full description and the first 700 characters of its SKILL.md body. Each one also gets a fits question. A skill is picked only when its best fit score is 0.30 or more.

  const shortlist = ranked.slice(0, SHORTLIST).map(entry => skills.find(skill => skill.name === entry.name)!)
  const rerankQuestions: Record<string, unknown> = {
    which: {
      type: 'choice',
      instructions:
        "Exactly one of these skills is the right one to load for the user's latest request. Which one? Read what each actually does, not just its name.",
      criteria: Object.fromEntries(
        shortlist.map(skill => [skill.name, `${skill.description}${skill.body ? ` — ${skill.body}` : ''}`]),
      ),
    },
  }
  for (const skill of shortlist) {
    rerankQuestions[`fits::${skill.name}`] = {
      type: 'noul',
      instructions: `Does the skill '${skill.name}' do the specific thing the user's request asks for? It is described as: ${skill.description}`,
    }
  }
  const narrow = await ask($, state, rerankQuestions)
  const fits = Object.fromEntries(
    shortlist.map(skill => [skill.name, narrow[`fits::${skill.name}`]?.noul ?? 0]),
  )
  const best = Math.max(...Object.values(fits))
  return done(fits, best < FITS_THRESHOLD ? null : (narrow.which?.choice ?? null))

6. Hide the skill list in block and steer

The prompt.attachment hook catches the skill listing that the model would read. It stores the skills it sees. In block and steer it drops the whole listing by returning { text: null }. In observe it removes only the skills you turned off.

  on('prompt.attachment', { type: 'skill_listing' }, async ($, e, next) => {
    runtime.listed = parseListing(e.text)
    await update($, roster, () => mergeRoster(runtime.disk, runtime.listed))
    if (!(await read($, enabled))) return next(e)
    const current = await read($, mode)
    if (current !== 'observe') return { text: null }
    const off = new Set(await read($, disabled))
    if (off.size === 0) return next(e)
    const kept = e.text
      .split('\n')
      .filter(line => {
        const entry = line.match(/^- (\S+?)(?::|$)/)
        return !entry?.[1] || !off.has(entry[1])
      })
      .join('\n')
    return next({ ...e, text: kept })
  })

7. Refuse Skill calls that break the mode

The tool.call hook for the Skill tool checks the on and off switch, then the disabled list, then the mode. In block, every Skill call is refused. In steer, only a call for Jev's pick is allowed.

  on('tool.call', { tool: 'Skill' }, async ($, e, next) => {
    const name = e.skill
    if (!(await read($, enabled))) return next(e)
    const current = await read($, mode)
    if ((await read($, disabled)).includes(name)) {
      return { deny: `jev-skill-suggestion: the skill '${name}' is turned off. Carry on without it.` }
    }
    if (current === 'block') {
      return { deny: 'jev-skill-suggestion: skill loading is blocked in this session. Carry on without a skill.' }
    }
    if (current === 'steer') {
      const pick = (await read($, verdict))?.winner
      if (pick !== name) {
        return { deny: `jev-skill-suggestion: only the skill Jev picked for this request may load${pick ? ` (${pick})` : ' (none)'}.` }
      }
    }
    return next(e)
  }).catch(($, e, next) => (next.called ? next(e) : { deny: 'jev-skill-suggestion: its guard failed.' }))
Where the README and the source differ.
  • The README says "each prompt you type" is sent to the service. The code scores a draft after each 600 ms pause, once it has 8 or more characters and does not start with a slash. So drafts you never send are sent too.
  • In steer mode, submitting a prompt also sends it, unless a fresh verdict for the same text is already held.

How to use it

claude plugin marketplace add ray-amjad/claude-code-mods
claude plugin install jev-skill-suggestion@claude-code-mods

The marketplace name is claude-code-mods, from .claude-plugin/marketplace.json.

  • Get a key from the TypeSafe console. Set it as the apiKey plugin option, or as the TYPESAFE_API_KEY variable. Without a key, the band says so, and nothing is scored.
  • Type at least 8 characters, then pause. The band above the prompt shows the gate, the top skills with their scores, and the pick.
  • Run /jev observe, /jev block or /jev steer. You can also press the mode button in the band.
  • Run /jev off to stop all scoring and sending. Run /jev on to turn it back on. Run /jev alone to open the pane, where you untick skills to leave them out of the ranking and the listing.

Cost. Each scored draft makes one request to Jev. It makes a second one only when the gate reaches 0.30. The source shows no prices, so this page gives no money figure. Each request sends your draft. The first also sends each enabled skill's name and description, cut to 250 characters. The second sends the full descriptions of the top three, and up to 700 characters of each body.

Limits.

  • The guard watches only calls to the Skill tool, through its tool.call hook.
  • Only the newest draft's answer is shown. An older answer that arrives late is dropped.
  • Without a key, nothing is scored. The band shows the reason instead.

Check yourself

How does the gate turn three answers into one number, and what happens below 0.30?

gateOf averages the three values, after it flips prose_suffices to one minus its value. If the average is under GATE_THRESHOLD, which is 0.30, the mod picks no skill and sends no second request.

In steer mode, what happens when Claude asks for a skill that Jev did not pick?

The tool.call hook denies the call. The message says that only the skill Jev picked may load. If Jev picked none, the message says "(none)".
