What it is

terminal-browser is a plugin with one hook module, hooks/register.tsx. It starts a local bridge with the terminal-browser program, reads new frames from it, and draws them in a side pane named browser. It also adds the /browser command, and an open and close tool for Claude when you turn on the agentTool option. Other plugins can use the pane through $.browser.open and $.browser.close.

It matters for your mission because it calls a local program, talks to it over HTTP with a token, and offers an API to other plugins, so you must be able to name each call and say why it is there.

How it was built

The plugin has one hook module. The steps follow the order in which its main parts appear in the file. A comment in the file calls one part of it "a hack", because the plugin API does not let $ or the result of next be passed to functions. Step 1 shows that part.

1. Expose browser.open and browser.close

engine.create adds a browser object. Its open and close functions throw if they run, with a message that the noun is served by its hooks. The browser.open and browser.close hooks do the work, and return their result as value. Those two event names are not in the engine's type file, so they belong to this plugin.

  on('engine.create', async ($, e, next) => {
    const built = await next(e)
    const servedByHooks = () => { throw new Error('the browser noun is served by its hooks') }
    const browser: Browser = { open: servedByHooks, close: servedByHooks }
    return { ...built, browser }
  })

  on('browser.open', async ($, e) => {
    const opened = await openBrowser($, e.url ?? null)
    return { value: opened }
  })

  on('browser.close', async ($) => {
    return { value: await closeBrowser($) }
  })

2. Check the program and start the bridge

startBridge first runs the program's capabilities command. The program must report embedding and image-frames. If not, the function returns an install or upgrade message. Then it runs claude-bridge launch, reads the port and token from its output, and starts the watch loop.

async function startBridge($: EngineInterface): Promise<{ ok: true } | { ok: false; error: string }> {
  const command = await terminalBrowserCommand($)
  const check = await checkCapabilities($, command)
  if (!check.ok) {
    return {
      ok: false,
      error: check.installed
        ? 'Newer terminal-browser version required, run terminal-browser upgrade'
        : `Please install terminal-browser first - ${INSTALL_URL}`,
    }
  }
  let report: unknown = null
  try {
    const { stdout, stderr, exitCode } = await $.process.run([...command, 'claude-bridge', 'launch'], { timeoutMs: 20_000 })
    const line = stdout.split('\n').find((text: string) => text.startsWith('{'))
    report = line ? JSON.parse(line) : { error: stderr.trim() || `exit ${exitCode}`, code: 'start' }
  } catch (err) {
    report = { error: String(err), code: 'start' }
  }
  if (!isLaunchReport(report) || !('port' in report)) {
    const detail = isLaunchReport(report) && 'error' in report ? report.error : 'terminal-browser could not start'
    return { ok: false, error: `${detail}` }
  }
  state.port = report.port
  state.token = report.token
  void watchBridge($)
  return { ok: true }
}

3. Talk to the bridge over localhost with a token

post sends a JSON body to the bridge's port on 127.0.0.1. bridgeUrl and authHeaders, on lines 45 and 46, build the address and the bearer header. The function returns null on any failure. This file has no model call: nothing in it uses $.model.

async function post($: EngineInterface, path: string, body: unknown): Promise<unknown> {
  if (state.port === null) return null
  try {
    const response = await $.http.fetch(bridgeUrl(path), {
      method: 'POST',
      headers: { 'content-type': 'application/json', ...authHeaders() },
      body: JSON.stringify(body),
    })
    return response.ok ? JSON.parse(response.text || '{}') : null
  } catch {
    return null
  }
}

4. Watch for new frames and draw them

watchBridge asks the bridge for its state, sending the last version number it saw. When there is a new frame, it hands the frame to $.ui.blit. If the frame does not fit the pane, it redraws the pane instead. When the blit is refused, the code counts refusals and logs the reason on the third one.

    const frame = fresh.frame
    if (!frame || frame.generation === state.frame?.generation) continue
    state.frame = frame
    if (!fitsMounted(frame)) {
      $.ui.invalidate('ui.render')
      continue
    }
    const result = await $.ui.blit({ requestId: PANE, key: IMAGE_KEY, source: imageSource(frame) })
    if (!result.deny) {
      denials = 0
      continue
    }
    denials += 1
    if (denials === DENIALS_BEFORE_LOGGING) $.ui.log(`terminal-browser: frame blit refused: ${result.deny}`)
    const now = Date.now()
    if (now - lastDeniedRedraw >= DENIED_REDRAW_MS) {
      lastDeniedRedraw = now
      $.ui.invalidate('ui.render')
    }

5. Open the pane and point it at a page

openBrowser starts the bridge if it is not running. It uses the address you gave, or the last page, or a start page. Then it opens the browser pane with focus. If the pane has not reported its size yet, the address waits in pendingUrl until it does.

async function openBrowser($: EngineInterface, raw: string | null): Promise<{ ok: true; url: string } | { ok: false; error: string }> {
  if (state.port === null) {
    const started = await startBridge($)
    if (!started.ok) return started
  }
  const alive = state.last?.alive === true
  const url = raw ? normalizeUrl(raw) : (alive && state.last?.url ? state.last.url : START_URL)
  state.pendingUrl = url
  state.open = true
  await $.ui.open({ id: PANE, title: 'browser', focus: true, rows: 24 })
  $.ui.invalidate('ui.render')
  if (state.region) {
    state.pendingUrl = null
    await post($, '/open', { url, ...state.region })
  }
  return { ok: true, url }
}

6. Register /browser and the optional tools

The command.run hook reads the arguments. close, or a bare /browser while the pane is open, closes it. Any other text is an address to open. session.start registers the command only in a terminal session. It registers the open and close tools only when agentTool is true.

  on('command.run', { command: 'browser' }, async ($, e) => {
    const arg = e.args.trim()
    if (arg === 'close' || (!arg && state.open)) {
      await closeBrowser($)
      return { text: 'Closed terminal-browser' }
    }
    const opened = await openBrowser($, arg || null)
    return { text: opened.ok ? 'Opened terminal-browser' : opened.error }
  })

7. Draw the pane and forward keys and scrolling

The ui.render hook for the Pane component draws the picture at the size of the pane, with a transparent Client placed over it. The ui.message hook sends size reports and key input to the bridge. The ui.scroll hook turns scrolling into mouse events.

  on('ui.render', { component: 'Pane', requestId: PANE }, async ($, e) => {
    if (e.surface !== 'terminal') {
      const { Box } = await $.ui.resolve(e)
      return <Box />
    }
    const { Box, Client, Image } = await $.ui.resolve(e)
    const rows = e.props.scroll.bodyRows > 0 ? e.props.scroll.bodyRows : Math.max(8, (e.viewport?.rows ?? 30) - 8)
    const cols = Math.max(1, e.props.bodyColumns > 0 ? e.props.bodyColumns : (e.viewport?.columns ?? 80))
    const frame = state.frame
    const grid = frame ? imageGrid(frame, cols, rows) : null
    state.mounted = grid
    return (
      <Box flexDirection="column" width={cols} height={rows}>
        {frame && grid ? (
          <Image key={IMAGE_KEY} source={imageSource(frame)} columns={grid.cols} rows={grid.rows} alt={IMAGE_ALT} />
        ) : null}
        <Box position="absolute" top={0} left={0} width={cols} height={rows}>
          <Client key={viewKey()} module="./surface.tsx" width={cols} height={rows} />
        </Box>
      </Box>
    )
  })

How to use it

claude plugin marketplace add zenbu-labs/terminal-browser
claude plugin install terminal-browser@terminal-browser

The marketplace name is terminal-browser, from the repository's .claude-plugin/marketplace.json.

  • Install the terminal-browser program first. The README gives a curl script and a Homebrew command. This page does not run them.
  • Add "env": { "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1" } to ~/.claude/settings.json. The README says the plugin needs it. Then run claude update.
  • Type /browser to open the last page, or a start page. Type /browser followed by an address to open that page. Type /browser close, or /browser again with no address, to close it.
  • If you want Claude to open and close the pane itself, set the agentTool option under pluginConfigs. It is off by default.
  • To update, run claude plugin update terminal-browser@terminal-browser. For the program, run terminal-browser upgrade.

Cost. The hook module makes no model call. It runs the terminal-browser program to check capabilities and to start the bridge. It talks to that bridge on 127.0.0.1. The source gives no figures for CPU or memory use.

Limits. The README and the code list these.

  • It needs a terminal with the kitty graphics protocol and unicode placeholders. The README names ghostty and kitty.
  • The mouse position can be slightly off. Claude Code's minimum chat width can stop you making the pane as large as you want.
  • Multiplexers can break the picture. The README says tmux does not work through this plugin yet, and that herdr performance is very bad.
  • It depends on the experimental function hooks API, which may change between releases.
  • /browser is registered only in a terminal session, as the session.start hook shows.

Check yourself

Why does the plugin check capabilities before it starts the bridge?

startBridge runs the program's capabilities command first. It needs both embedding and image-frames. If either is missing, the plugin does not start the bridge, and it tells you to install or upgrade the program.

How does the bridge know that a request comes from this plugin?

The launch report gives a token. post and fetchState send it as a bearer token in the authorization header, on every request to 127.0.0.1.
