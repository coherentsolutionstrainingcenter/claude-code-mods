What it is

today-report is a Claude Code mod with one slash command, /today-report. It opens a pane that totals your past work from the session logs in ~/.claude/projects: tasks, estimated hours saved, value at your hourly rate, and tokens.

Your mission in MISSION.md says you must be able to name the hook events and API calls each mod uses, and this mod is a small, complete example to study.

How it was built

1. Read the logs with a script

The totals come from every ~/.claude/projects/**/*.jsonl file. A plugin file read through $.fs rejects anything over 4 MiB, so reading a large log from the mod would fail. The author's logs are about 8 GB in total. So scripts/aggregate.py reads each file itself, one line at a time, and prints one JSON report to stdout. The report holds counts only. It prints no prompt or reply text.

def scan(path):
    """Returns the per-day totals of one log file."""
    days = {}
    seen_requests = set()
    task = None  # the prompt being answered, until the next prompt

    with open(path, "rb") as handle:
        for raw in handle:
            if not any(marker in raw for marker in MARKERS):
                continue
            try:
                record = json.loads(raw)
            except ValueError:
                continue
Byte check before parsing. Each line is first checked for two byte markers, "type":"user" and "type":"assistant". Lines without them are skipped before any JSON parsing, which saves work on large logs.

2. Stream the records and count tasks

A task starts at a typed prompt and runs until the next one. A record counts as a prompt when it is not marked isMeta and its text does not start with a command tag. Tool results are not prompts. A message made of content blocks counts only when one of the blocks is an image.

A task's category is the first entry in this list that matches any tool the task used: code changes, commands, research, then delegated. A task with no matching tool is "conversation". Its model is the model of its first reply that carries usage data.

Each reply adds its token counts. A streamed reply writes several records with the same request id, so the script counts each request id once.

            message = record.get("message") or {}
            kind = record.get("type")

            if kind == "user" and is_prompt(record, message):
                close_task(days, task)
                task = {"day": local_day(record["timestamp"]), "tools": set(), "model": None}
            elif kind == "assistant":
                usage = message.get("usage")
                if task is not None:
                    for block in message.get("content") or []:
                        if isinstance(block, dict) and block.get("type") == "tool_use":
                            task["tools"].add(block.get("name", ""))
                    if task["model"] is None and isinstance(usage, dict):
                        task["model"] = message.get("model")
                # A reply streams as several records that repeat one usage: count it once.
                request = record.get("requestId")
                if not isinstance(usage, dict) or (request is not None and request in seen_requests):
                    continue
                if request is not None:
                    seen_requests.add(request)
                day = days.setdefault(local_day(record["timestamp"]), empty_day())
                for name, field in TOKEN_FIELDS.items():
                    day["tokens"][name] += usage.get(field) or 0
Dedupe is per file. The set of seen request ids is created inside scan(), so it resets for each file. If one request id appeared in two files, its tokens would count twice. The source does not say whether that happens.

3. Cache each log by path, size and mtime

Each log file has one cache entry, keyed by its path. The entry holds the file's size, its modification time and its per-day totals. A file whose size and modification time match its entry is not read again. A change to either one makes the script read it again.

The script stops starting new scans after 420 seconds. A file it does not reach gets a fallback. If it has an old entry, the old totals are kept and the file is counted as stale. If it has no entry, the file is left out and counted as pending. The pane shows a warning when either count is above zero. The cache is written to a .tmp file, which then replaces the old cache.

    for path in sorted(glob.glob(os.path.join(args.root, "**", "*.jsonl"), recursive=True)):
        counts["files"] += 1
        try:
            info = os.stat(path)
        except OSError:
            counts["failed"] += 1
            continue
        known = cache.get(path)
        if known and known["size"] == info.st_size and known["mtime"] == info.st_mtime:
            fresh[path] = known
            continue
        if time.monotonic() - started > args.budget:
            if known:
                fresh[path] = known
                counts["stale"] += 1
            else:
                counts["pending"] += 1
            continue
Budget below the timeout. The mod passes no --budget, so the 420-second default applies. The mod's process call allows 600000 ms, which is ten minutes, the most the engine allows. The script stops starting scans at 420 seconds, inside that limit.

4. Hold the state in an atom and refresh through a process call

The pane's state lives in one atom, view, under the plugin name today-report. Its value holds the status (idle, reading, ready or failed), the chosen period, the report, any error, and the two settings. types/index.d.ts declares that shape, so read and update know it. read returns the starting value until something is written. update applies a change and retries if another write lands first.

The ui.render hook draws the pane from that atom. Because it reads the atom while drawing, the pane redraws when the atom changes. The period buttons call update. The Refresh button calls refresh.

refresh reads the two settings with $.config.list(), sets the status to reading, and runs python3 on the script with $.process.run. It parses stdout as JSON. A non-zero exit code becomes the failed state, with the first 300 characters of stderr as the message. The engine keeps only the first 4 MiB of each output stream, and the report holds one entry per day, so it stays small.

/** Runs the aggregator and stores what it prints. One run at a time. */
async function refresh($: EngineInterface): Promise<void> {
  const current = await read($, view)
  if (current.status === 'reading') {
    return
  }

  const settings = await $.config.list()
  const minutesPerTask = setting(settings, 'today-report.minutesPerTask', 10)
  const hourlyRate = setting(settings, 'today-report.hourlyRate', 50)
  await update($, view, v => ({ ...v, status: 'reading', error: '', minutesPerTask, hourlyRate }))

  try {
    const run = await $.process.run(['python3', `${$.plugin.root}/scripts/aggregate.py`], { timeoutMs: 600000 })
    if (run.exitCode !== 0) {
      throw new Error(run.stderr.trim().slice(0, 300) || `exit code ${run.exitCode}`)
    }

    const report = JSON.parse(run.stdout) as Report
    await update($, view, v => ({ ...v, status: 'ready', report }))
  } catch (error) {
    const message = error instanceof Error ? error.message : String(error)
    await update($, view, v => ({ ...v, status: 'failed', error: message }))
  }
}
Two details. The guard at the top of refresh reads the status, then waits for the settings, then writes reading. Two presses close together could both pass the guard, even though the comment says one run at a time. Also, the settings are read only when a run starts, so press Refresh after you change them.

5. Group days into periods, with weeks starting on Monday

totalsFor puts each day into a bucket for the chosen period. The bucket key is the day for day, YYYY-MM for month, YYYY for year, and the Monday on or before the day for week. Buckets sort newest first and are cut to the latest rows: 14 days, 12 weeks, 12 months or 5 years. Week rows are labelled "week of" and the date.

  // A week starts on Monday, so step back to the Monday on or before the day.
  const start = new Date(`${day}T00:00:00`)
  start.setDate(start.getDate() - ((start.getDay() + 6) % 7))
  return [start.getFullYear(), start.getMonth() + 1, start.getDate()]
    .map(part => String(part).padStart(2, '0'))
    .join('-')

getDay() returns 0 for Sunday. The formula steps Sunday back six days to Monday, and steps Monday back zero.

The Total covers shown rows only. The Total line adds up only the rows the chosen period shows. On the day view, that is the latest 14 days, not your full history. The in figure adds cache reads and cache writes to input tokens.

How to use it

claude plugin marketplace add <owner>/<repo>
claude plugin install today-report@waraxe-claude-mods

The <owner>/<repo> part is a placeholder. The source does not give the marketplace's GitHub path.

  • Open it. Run /today-report. The pane opens and a read starts at once.
  • Pick a period. Choose day, week, month or year. The chosen period shows in brackets.
  • Refresh. Press Refresh to read the logs again. Later runs read only the logs that changed.
  • Settings. minutesPerTask is the time a task would have taken you by hand. hourlyRate turns hours into dollars. Change them in the /config menu, where the engine lists each plugin's fields as today-report.minutesPerTask and today-report.hourlyRate. The README and the pane footer name /plugin configure today-report instead. The engine types do not mention that command, so test it before you rely on it.
  • Cost. No model calls. The mod runs python3 on your machine. The first read scans every log and can take a while. The script stops starting new files after 420 seconds, so a very large first read may take more than one run.
  • Time saved is an estimate. Hours are tasks times minutes per task. The number comes from your setting, not from measured time.
  • Tokens are real. They are summed from the usage fields in your logs.
  • Not yet tested live. The figures and the pane have not been checked in a live session.

Check yourself

Why does the mod run a Python script instead of reading the logs in TypeScript?

A plugin file read through $.fs rejects anything over 4 MiB, and the author's logs total about 8 GB. The script reads each log one line at a time. The mod runs it through $.process.run and gets back a JSON report.

What starts a new task, and what makes a message count as a prompt?

A typed prompt starts a task, and the next typed prompt ends it. A record counts as a prompt when it is not marked isMeta and its text does not start with a command tag. Tool results do not count. A message made of content blocks counts only when one of the blocks is an image.

Does the Total line cover all of your history?

No. It adds up only the rows the chosen period shows: the latest 14 days, 12 weeks, 12 months or 5 years.
