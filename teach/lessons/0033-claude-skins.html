What it is

Claude Skins is a plugin named skins. It changes how Claude Code draws the transcript. Tool calls become rows with icons and timings, and edits become diff cards. Code, tables and Mermaid charts become cards too, and /skin switches between the 16 built-in skins while a session runs.

It matters for your mission because it draws over Claude Code's own rows, so it shows which hook events and API calls a large mod depends on, and why.

How it was built

The entry point is hooks/hooks.json. It names one module, hooks/register.tsx. That file exports register, which receives on, and every handler is subscribed through it. Across the file, the mod subscribes to 13 engine events and adds one event of its own, skins.markdown.

1. Declare the plugin and its one module

plugin.json gives the name, version, author and license. hooks.json lists the module the engine loads.

2. Add a markdown service for other mods

The engine.create handler adds a skins object to $. Its markdown method is only a placeholder. The real work happens on the skins.markdown event, and the handler below answers it.

export const register: Register = on => {
  // Adds `$.skins` for other mods. A call is the `skins.markdown` event, which the hook
  // below answers with this session's `$`; the method itself is the chain's floor.
  on('engine.create', async ($, e, next) => {
    const built = await next(e)

    return { ...built, skins: { markdown: async () => undefined } }
  })

  on('skins.markdown', async ($, e) => ({ value: await drawMarkdown($, e) }))

3. Register the /skin command and the design tool

On session.start, the mod registers the /skin command. It then registers a tool named design. The code waits at most DESIGN_TOOL_WAIT_MS, which is 1000 milliseconds, for that registration to finish.

    await $.command.register({
      name: 'skin',
      description: 'Open the skin settings, or /skin <name | list | help | off>',
      argumentHint: '[help | gallery | copy | copy code | name | list | off | calm | pin | unpin | share | rail | tables | shimmer | band | countdown | clip | markdown | quiet | charts | math | commands | shell | highlight | hints | links | fold | expand | compact | icons | prompt | words]',
      immediate: true,
    })
    const designTool = $.tool
      .register({
        name: DESIGN_TOOL.name,
        description: DESIGN_TOOL.description,
        inputSchema: DESIGN_TOOL.inputSchema,
      })
      .catch((error: unknown) => {
        $.ui.log(`design tool: ${error instanceof Error ? error.message : String(error)}`, { to: 'debug' })
      })

4. Answer the design tool in a tool.call hook

A tool.call hook filtered by { tool: DESIGN_MATCH } handles the design tool. If the outcome is an error, the hook returns deny. Otherwise it saves the new state and returns result. A first tool.call hook, which runs for every tool, records how long each call took. For write calls, it also records which files changed.

  on('tool.call', { tool: DESIGN_MATCH }, async ($, e) => {
    const outcome = runDesign(e, await designState($))

    if (outcome.isError) {
      return { deny: outcome.text }
    }

    await commit($, outcome.state)

    return { result: outcome.text }
  })

5. Draw the tool rows with ui.render

The ToolUse component draws each tool row. The mod draws its own row only when kindOf knows the tool. Otherwise it calls next(e), and Claude Code's own row stays. The row reads its time from a stored atom, and it reads the changed-line counts from the tool's output.

  on('ui.render', { component: 'ToolUse' }, async ($, e, next) => {
    const kind = kindOf(e.props.tool)
    const active = await activeSkin($)

    if (kind === null || active === null) {
      return next(e)
    }

    const cwd = await cwdOf($)
    const ms = e.props.isRunning ? -1 : await read($, memberOf(durationAtom, e))
    const diff = diffstat(e.props.output)
    const target = summarize(e.props.tool, e.props.input, cwd)

    const meta = {
      ...(ms >= 0 && !e.props.isRunning ? { ms } : {}),
      ...(diff === null ? {} : diff),
    }

6. Draw the usage band above the prompt

The AbovePrompt component draws the usage meters. It returns next(e) when the band is off, when a survey is showing, or when there are no meters. Otherwise it draws the band.

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const active = await activeSkin($)
    const usage = await read($, usageAtom)
    // Drawn from the clock so a countdown switched on shows at once; reading the atom
    // redraws the band when the minute tick changes one.
    const countdowns = active?.prefs.countdown === true ? (await read($, countdownsAtom), countdownsOf(usage, await $.clock.now())) : {}
    const meters = metersOf(usage, countdowns)

    if (active === null || !active.prefs.band || e.props.hasSurvey || meters.length === 0) {
      return next(e)
    }

How to use it

claude plugin marketplace add hellosverre/claude-skins
claude plugin install skins@hellosverre-mods

The README shows the same two commands typed inside Claude Code, with a slash in front. Restart Claude Code after the install.

  • Start. The noir skin is on after the restart. Type /skin to open the settings pane, or /skin tokyo-night to switch by name. /skin list shows every skin and setting.
  • Turn it off or calm it. /skin off returns Claude Code's own drawing. /skin calm removes motion and folds read-only output to one line. /skin calm off puts back what you had.
  • Design your own. Ask for a skin in plain words. Claude calls the design tool, which builds the skin and applies it. Repainting a built-in skin saves a copy named my-<skin>.
  • What it costs. The drawing is local. The README says the stored conversation and what the model reads stay untouched. When charts are on, Claude gets a short model-only note, which the README estimates at about 130 tokens. That note is never sent in headless claude -p runs.
  • Update check. The mod asks for the latest release over HTTP, once a day. The check starts off the session's critical path, so a slow or offline network does not hold the session up.
  • Limits. The README says it was checked by hand on Windows and run on Linux. macOS, VS Code and mobile have not been checked by hand. Agents, plan mode, todos and the permission prompt keep Claude Code's own rows. File paths are coloured but not clickable. Code cards past 80 lines are cut, and Copy takes the full text.

Check yourself

Which event answers the design tool, and what does the hook return when the design is invalid?

It is tool.call, filtered to the design tool with { tool: DESIGN_MATCH }. When the outcome has an error, it returns { deny: outcome.text }. Otherwise it saves the state and returns { result: outcome.text }.

Why does the session start wait for the design tool, and for how long at most?

It waits for the design tool to register. The wait is capped at DESIGN_TOOL_WAIT_MS, which is 1000 milliseconds. It also ends early when the registration finishes or fails, because the catch still resolves it.
