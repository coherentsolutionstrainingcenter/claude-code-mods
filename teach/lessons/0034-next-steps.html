What it is

Next Steps asks Claude's small model, Haiku, for follow-up prompts after each finished answer. The prompts appear as a band above the prompt box. In an empty box, a digit puts the chosen prompt in as a draft, and nothing is sent until you press Enter.

It matters for your mission because a short entry file shows the whole loop: an event, a model call, and a band drawn above the prompt.

How it was built

The entry point is hooks/hooks.json, which loads hooks/register.tsx. The file's register function receives on. The mod subscribes to five events: prompt.submit, turn.start, turn.complete, prompt.edit and ui.render. It calls seven engine APIs through $: $.env.get, $.ui.resolve, $.session.messages, $.model.complete, $.fs.read, $.fs.exists and $.agent.list.

1. Declare the plugin and its two settings

plugin.json declares two options under userConfig: language and layout. The register function reads them from its options argument. When a setting is missing, the code falls back to an empty language and the auto layout.

  },
  "types": "./types/index.d.ts",

      "title": "Language",

2. Keep the list in two atoms

steps holds the list and the turn it belongs to, or null. The atoms are held by the host, so the list survives a hot reload of the file. active is true while the list is on screen. The comment says the where-am-i mod reads it. The constants set the limits: three items, a 60-character request, a 120-character cap per line, and a 20-character minimum answer.

const MODEL = 'haiku'
const MAX_ITEMS = 3
const MAX_CHARS = 60 // what the model is asked for
const MAX_KEPT = 120 // a longer line is dropped, never cut: a cut draft would send half a prompt
const MIN_ANSWER = 20 // a reply shorter than this is not worth a model call

// Held by the host, so the list survives a hot reload of this file.
const steps = atom({ plugin: 'next-steps', key: 'steps' } as const, null as NextSteps | null)
// True while the list is on screen. where-am-i reads it and leaves out its own "next" meanwhile.
const active = atom({ plugin: 'next-steps', key: 'active' } as const, false)

3. Clear the list when a new prompt or turn starts

prompt.submit and turn.start both clear the list. A submit also changes latest, so a suggestion still on its way for an older turn is dropped when it arrives.

  on('prompt.submit', async ($, e, next) => {
    latest = `submit-${++submits}`
    await setSteps($, () => null)
    return next(e)
  })

  on('turn.start', async ($, e, next) => {
    latest = e.turnId
    await setSteps($, () => null)
    return next(e)
  })

4. Ask the model after a finished answer

When a main turn ends with an answer of at least 20 characters, the mod starts suggest in the background, so the turn ends at once. Subagent turns are skipped, because e.agentId is set for them. A failure is caught and ignored. A failed call shows no list and raises no error.

  on('turn.complete', async ($, e, next) => {
    const r = await next(e)
    if (e.agentId) return r // a subagent's turn, not the person's
    latest = e.turnId // also for a turn that raised no turn.start, and after a hot reload
    if (e.reason !== 'answer' || e.answer.trim().length < MIN_ANSWER) return r
    void suggest($, e.turnId, e.answer, () => latest).catch(() => {}) // in the background, so the turn ends at once
    return r
  })

5. Call Haiku with the recent transcript

suggest returns early when any agent is still running. Otherwise it reads the session's messages and keeps the last six. It drops the latest reply from that list, because the reply goes in on its own. Each message is cut to 800 characters, and the latest reply is cut to 2,000 characters. The call uses Haiku, with at most 200 output tokens and a 20-second timeout.

  const r = await $.model.complete({
    model: MODEL,
    maxTokens: 200,
    timeoutMs: 20_000,
    system:
      'You predict what a person will type next to their coding assistant, after reading a transcript of their session. ' +
      `Give 2 or 3 short, concrete follow-up prompts, each an instruction in the imperative, under ${MAX_CHARS} characters, ` +
      'specific to what just happened (name the file, test or feature). Plain words, no em dashes, no numbering, no quotes. ' +
      'One per line and nothing else. If nothing sensible follows, reply with the single word NONE.\n' +
      'Example reply:\nRun the login tests again\nAdd the same check to signup.ts\nOpen a draft PR' +
      (language
        ? `\nWrite every line in ${language}. Keep file names, commands and code identifiers as they are.`
        : ''),
    prompt: [
      `<transcript>\n${messages.map(m => `[${m.role === 'user' ? 'person' : 'assistant'}] ${m.text.slice(0, 800)}`).join('\n')}\n</transcript>`,
      `<latest_reply>\n${answer.slice(0, 2000)}\n</latest_reply>`,
      'Write the follow-up prompts the person is likely to send next: the lines only, not a reply to the transcript.',
    ].join('\n\n'),
  })

6. Clean the reply into at most three lines

parseSteps accepts a JSON array or plain lines. It removes bullets, numbers and quotes, and it turns em dashes into commas. It drops preambles such as "Here are", drops lines that end in a colon, and drops lines over 120 characters. It removes duplicates and keeps at most three.

export function parseSteps(text: string): string[] {
  const body = text.replace(/```[a-z]*\n?/gi, '').trim()
  let lines = body.split('\n')
  if (body.startsWith('[') || body.startsWith('{')) {
    try {
      const o = JSON.parse(body) as unknown
      const arr = Array.isArray(o) ? o : Object.values(o as Record<string, unknown>).find(Array.isArray)
      lines = Array.isArray(arr) ? arr.filter((x): x is string => typeof x === 'string') : []
    } catch {
      // not JSON after all: read it as lines
    }
  }
  const out: string[] = []
  for (const line of lines) {
    const clean = line
      .replace(/\*\*/g, '')
      .replace(/^\s*(?:[-*•]|\d+[.):])\s*/, '')
      .replace(/^["'`]+|["'`,]+$/g, '')
      .replace(/\s*\u2014\s*/g, ', ')
      .replace(/\.$/, '')
      .trim()
    if (clean === '' || clean.endsWith(':') || clean.length > MAX_KEPT) continue
    if (/^(none|no |nothing|here are|here's|sure)/i.test(clean) || /^[[\]{}]$/.test(clean)) continue
    if (!out.some(o => o.toLowerCase() === clean.toLowerCase())) out.push(clean)
    if (out.length === MAX_ITEMS) break
  }
  return out
}

7. Fill the box when a digit is typed

The prompt.edit hook runs on each edit to the box. It acts only when the box is empty and the cursor is at the start. Then 1 to 3 put the matching suggestion in the box as a draft. 0 clears the list and leaves the box empty. A pasted digit has no key, so it lands as typed text.

  // A digit typed into an empty prompt picks a suggestion instead of landing as text.
  // A paste carries no key, so a pasted "1" lands as typed.
  on('prompt.edit', async ($, e, next) => {
    if (hasSurvey || !e.key || e.key.ctrl || e.key.meta || e.text !== '' || e.start !== 0 || e.end !== 0 || !/^[0-9]$/.test(e.inputText)) return next(e)
    const s = await read($, steps)
    if (!s) return next(e)
    if (e.inputText === '0') {
      await setSteps($, () => null)
      return { text: '', cursor: 0 } // consumed: the box stays empty
    }
    const pick = s.items[Number(e.inputText) - 1]
    if (!pick) return next(e)
    return next({ ...e, inputText: pick }) // a draft: the person edits it or presses Enter
  })

8. Draw the band above the prompt

The AbovePrompt render draws nothing while a survey or work in progress is showing, or when the list is empty. Otherwise it defines the numbered items and the dismiss key. The code then puts the items on one line when they fit the band's width, or on one row each. It stacks the band above other mods' bands, unless a band-order file says otherwise.

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const rest = await next(e) // what other mods and Claude Code draw here stays
    hasSurvey = e.props.hasSurvey
    const s = await read($, steps)
    if (e.props.hasSurvey || e.props.isWorking || !s || s.items.length === 0) return rest

    const { Box, Text } = $.ui.resolve(e)
    const sep = <Text dimColor>{'  ·  '}</Text>
    const item = (text: string, i: number) => [
      <Text color="cyan" bold>{`${i + 1} `}</Text>,
      <Text>{text}</Text>,
    ]
    const dismiss = [<Text color="cyan" bold>{'0 '}</Text>, <Text dimColor>dismiss</Text>]

How to use it

claude plugin marketplace add hamzafer/claude-code-mods
claude plugin install next-steps@claude-code-mods

The marketplace is named claude-code-mods, and the same marketplace holds the other mods in that repo.

  • Settings. language writes the suggestions in another language. Empty keeps English. layout is auto (one row when the list fits) or rows (one suggestion per row). Both are plugin options.
  • Use. After an answer of 20 characters or more, the list shows above the prompt. In an empty prompt, press 1, 2 or 3 to put a suggestion in the box. Edit it, then press Enter to send. Press 0 to dismiss.
  • Cost. One Haiku call per finished main turn that passes the length check. It is capped at 200 output tokens and 20 seconds. Each call sends up to six recent messages and the latest reply. No call is made while a background agent is running.
  • Limits. The list holds at most three items. A submit or a new turn clears it. It is hidden while Claude works or a survey shows. The band order is read once per session, so a restart is needed to change it. The code does not retry when an agent is running, so that turn shows no list. The mod never sends a message on its own.

Check yourself

What does pressing 1 do in an empty prompt, and does it send the message?

The prompt.edit hook replaces the typed digit with the suggestion with that number, so the text lands in the box as a draft. It is not sent. The person edits the draft or presses Enter.

Why does suggest return early while an agent runs, and does it try again later?

It checks $.agent.list() for an agent with status running, and returns without a model call. The comment says the main agent picks up again once its agents finish. The code does not retry, so that turn shows no list.
