What it is

/heatmap runs git ls-files in the session's folder, groups the tracked files by top-level folder and by kind, and draws one colored bar per folder. The kinds are code, tests, docs, design (svg, png, jpg, fig, sketch), data (json, csv, sql, db, yaml), config and other. The biggest folders come first, up to 15 rows, with a legend of each kind's count above them and a total line below. Outside a git repository it says so and does not walk the disk. A Refresh button counts again. It makes no model calls.

Your mission asks you to say which hook events and API calls a mod uses and why, and this mod shows the plain pattern for running a host command from a pane: $.process.run, then a $.state atom the pane redraws from.

How it was built

The whole mod is one hooks module, hooks/register.tsx. Each snippet below is copied from it.

1. Open the pane, then count

session.start registers /heatmap. The command's hook opens the pane and starts the count without waiting for either, so the pane appears at once and shows "Running git ls-files…" until the count is in.

  on('command.run', { command: 'heatmap' }, async $ => {
    void $.ui.open({ id: PANE, title: 'Repo heatmap' })
    void refresh($)

    return { text: 'Repo heatmap opened.' }
  })

2. Ask git for the file list

$.process.run runs a command by its arguments, with no shell, and resolves with its exit code and output. The mod asks for the session's folder with $.session.cwd() and runs git there. A non-zero exit whose message says "not a git repository" becomes the not-repo status, and the pane says so.

  const folder = await $.session.cwd()
  await update($, view, (v): View => ({ ...v, status: 'reading', folder, error: '' }))

  try {
    // -z ends each path with a NUL byte and leaves odd names unquoted. LC_ALL=C keeps
    // git's messages in English, so "not a git repository" can be recognised.
    const run = await $.process.run(['git', 'ls-files', '-z'], { cwd: folder, env: { LC_ALL: 'C' }, timeoutMs: 60_000 })
    if (run.exitCode !== 0) {
      const isRepo = !/not a git repository/i.test(run.stderr)
      const error = run.stderr.trim().slice(0, 300)
      await update($, view, (v): View => ({ ...v, status: isRepo ? 'failed' : 'not-repo', error }))
      return
    }

3. Group the files by top-level folder

Everything before the first slash is the folder. Files with no slash go into one row named (top level). The rows are sorted biggest first, and only the first 15 are kept, with the full count of rows beside them for the total line.

/** Groups the paths by top-level folder and kind, biggest folder first, and keeps the first 15. */
function summarize(paths: readonly string[]): { rows: Row[]; totals: Counts; rowCount: number } {
  const byFolder = new Map<string, Counts>()
  const totals = emptyCounts()
  for (const path of paths) {
    const slash = path.indexOf('/')
    const folder = slash === -1 ? TOP_LEVEL : path.slice(0, slash + 1)
    const counts = byFolder.get(folder) ?? emptyCounts()
    const kind = kindOf(path)
    counts[kind] += 1
    totals[kind] += 1
    byFolder.set(folder, counts)
  }

  const rows = [...byFolder]
    .map(([folder, counts]) => ({ folder, counts, total: sumOf(counts) }))
    .sort((a, b) => b.total - a.total || a.folder.localeCompare(b.folder))

  return { rows: rows.slice(0, MAX_ROWS), totals, rowCount: rows.length }
}

4. Sort each file into a kind

The kind comes from the name and the folder, never from the file's content, so no file is opened. The rules run in order and the first match wins: a JSON file under tests/ is a test, and package.json is config, not data.

  if (
    parts.slice(0, -1).some(part => TEST_FOLDERS.has(part)) ||
    /[._-](test|spec)\.[a-z0-9]+$/.test(name) ||
    /^test_.+\.py$/.test(name)
  ) {
    return 'tests'
  }
  if (DESIGN.has(ext)) {
    return 'design'
  }
  if (
    parts.some(part => part.startsWith('.')) || // dotfiles and hidden folders: .github, .gitignore
    CONFIG.has(ext) ||
    CONFIG_NAMES.has(name) ||
    /^tsconfig\..+\.json$/.test(name) ||
    /\.config\.[cm]?[jt]s$/.test(name)
  ) {
    return 'config'
  }

5. Split each bar into colored runs

Each kind's run ends where the running total lands on the bar. Rounding the running total, instead of each kind on its own, keeps the runs from adding up to more than the bar. A folder with files always keeps at least one cell.

/**
 * Splits one bar into colored runs, a run per kind. Each run ends where the running total
 * lands, so the rounding never adds up to more than the bar. A folder with files always
 * shows at least one cell.
 */
function barCells(counts: Counts, max: number, width: number): { kind: Kind; cells: number }[] {
  let sum = 0
  let drawn = 0
  const segments = KINDS.map(kind => {
    sum += counts[kind]
    const end = Math.round((sum / max) * width)
    const cells = end - drawn
    drawn = end
    return { kind, cells }
  })

  if (drawn === 0 && sum > 0) {
    const biggest = KINDS.reduce((best, kind) => (counts[kind] > counts[best] ? kind : best))
    return [{ kind: biggest, cells: 1 }]
  }

  return segments.filter(segment => segment.cells > 0)
}

6. Draw one row per folder

The bar's width comes from e.props.bodyColumns, the pane's own width, less the name and count columns. Each row is one Text holding a colored Text per run, so the row stays on one line.

      {current.rows.map(row => (

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install repo-heatmap@waraxe-claude-mods
  • Run /heatmap in a session started inside a git repository.
  • Read the legend for each kind's count, then the rows: one bar per top-level folder, biggest first.
  • Press Refresh after you add or delete files. There are no settings.

What it costs. No model calls. Each count runs git ls-files once, on your machine.

Limits.

  • Only files git tracks are counted. Untracked and ignored files are left out, and a repository with nothing committed or staged shows no files.
  • Outside a git repository the pane says so. It does not walk the disk instead.
  • In a subfolder of a repository it counts that subfolder only, because git lists paths under the folder it runs in.
  • Kinds come from names, not content. A YAML file outside a hidden folder counts as data, even when it configures something.
  • A file list over 4 MiB is cut, and the pane then says the counts are partial. Folders past the 15th are not drawn; the total line says how many.

Check yourself

Why does the mod ask git for the list instead of listing the folder itself with $.fs?

git's list is the repository's own files: it already leaves out what .gitignore excludes, such as node_modules and build output, and it comes back in one fast call. Walking the disk would count those too and could take a long time on a big folder. Outside a repository there is no such list, so the mod says so instead.

The biggest folder has 2,000 files and another has 1. Why does the small folder's bar still show?

At that scale its share rounds to zero cells. barCells checks for a folder with files but no cells drawn, and gives one cell to its biggest kind, so every listed folder has a visible bar.
