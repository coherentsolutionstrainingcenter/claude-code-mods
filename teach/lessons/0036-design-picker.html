What it is

Claude asks you to choose with its question dialog, the AskUserQuestion tool. Choosing a style from a few words is hard. design-picker steps in just before that dialog opens. If the question or its options mention a design word (style, theme, palette, colour or color, font, typography, layout, look, design, UI), it makes one Haiku call for the styles. It writes one page with a card per option, side by side, to ~/.claude/design-picker/ and opens it in your browser. Each card shows the style's colours, its type, a sample heading and a sample button. Then the dialog appears, unchanged, and you choose there.

It fails open. If the call or the file write fails, no page opens and the dialog appears as normal.

For your mission, it is the clearest case in this set of a hook that sits in front of a tool call, waits on a model call, and still lets the call through unchanged, so it is a good place to practise saying what fails open and why.

How it was built

1. Spot a design question

One regular expression holds the design words. \b on both sides means a whole word only, so the "ui" in "build" does not count. wordsOf joins the question, its header, and every option's label and description, so a design word anywhere in them is found.

// A question or option with one of these words is a design choice.
const DESIGN_WORDS = /\b(?:styles?|themes?|palettes?|colou?rs?|fonts?|typography|layouts?|looks?|designs?|ui)\b/i
function wordsOf(q: { question: string; header: string; options: readonly Option[] }): string {
  return [q.question, q.header, ...q.options.flatMap(o => [o.label, o.description ?? ''])].join(' ')
}

2. Hook the dialog and let it through

The tool.call hook runs before the dialog opens, and its matcher narrows e to the AskUserQuestion input, so e.questions is typed. A plugin's own $.ui.ask raises this same call, so the hook acts only when next.origin.plugin is engine, which is how the types name the model's own call. It picks the first question with a design word, makes the page, and then returns next(e) with e unchanged. Two guards keep it failing open: the .catch(() => undefined) on preview, and the .catch handler on the hook itself, which also answers next(e) if the hook throws or runs out of time.

  on('tool.call', { tool: 'AskUserQuestion' }, async ($, e, next) => {
    // Only the model's own question: a plugin's $.ui.ask comes through here too.
    const asked =
      next.origin.plugin === 'engine'
        ? e.questions.find(q => q.options.length >= 2 && DESIGN_WORDS.test(wordsOf(q)))
        : undefined

    if (asked !== undefined) {
      // Fails open: whatever goes wrong here, the dialog below still appears.
      await preview($, asked.question, asked.options).catch(() => undefined)
    }

    // The call goes on unchanged, so the normal dialog appears.
    return next(e)
  }).catch(($, e, next) => next(e)) // a hook that fails or runs out of time still lets the dialog through

3. Make one Haiku call, then write and open the page

preview asks Haiku for the styles, with a 25-second limit. $.model.complete does not reject when the provider fails: it resolves with isAnswered: false, and the function simply returns. The file name comes from $.clock.now(), with the colons and the dot replaced, so names sort by time. $.fs.write creates the folder if it is missing.

/** One Haiku call for the styles, one page with a card per option, opened in the browser. */
async function preview($: EngineInterface, question: string, options: readonly Option[]): Promise<void> {
  const reply = await $.model.complete({
    model: 'haiku',
    prompt: stylePrompt(question, options),
    maxTokens: 1500,
    timeoutMs: 25000,
  })
  const cards = reply.isAnswered ? parseCards(reply.text, options.length) : undefined
  const folder = await folderOf($)
  if (cards === undefined || folder === undefined) {
    return
  }

  const stamp = new Date(await $.clock.now()).toISOString().replace(/[:.]/g, '-')
  const path = `${folder}/${stamp}.html`
  await $.fs.write(path, page(question, options, cards))
  await show($, path)
}

4. Ask for CSS only

The model writes no HTML. It returns a JSON array with CSS declarations for four parts of each card, and a few palette colours. The prompt asks for no url(), @import or web fonts, but the mod does not trust that: step 6 checks every declaration.

// The question and options are data here: the model only styles them.
function stylePrompt(question: string, options: readonly Option[]): string {
  return [
    'Someone is choosing between design styles. For each numbered option, write CSS declarations that show that style: its colours, its type and its shapes.',
    'Answer with only a JSON array, one object per option, in the same order. Each object has these keys:',
    '"card": declarations for the card itself (background, color, font-family, border, border-radius, padding, box-shadow)',
    '"heading": declarations for its heading',
    '"text": declarations for its paragraph',
    '"button": declarations for its sample button',
    '"swatches": three to five colours of the palette, as hex strings such as "#1a2b3c"',
    'Write declarations only, separated by semicolons: no selectors, no braces, no url(), no @import, no images and no web fonts. Name only fonts a Mac has, with a generic family last.',
    '',
    `Question: ${question.slice(0, 500)}`,
    ...options.map((o, i) => `${i + 1}. ${o.label.slice(0, 200)}: ${(o.description ?? '').slice(0, 300)}`),
  ].join('\n')
}

5. Read the answer as cards

parseCards takes the first array in the answer and returns one card per option. A missing or broken entry becomes a plain card, and an answer with no array gives undefined, so no page is made. toCard keeps only real hex colours for the swatches, and passes every CSS field through cleanCss.

/** The model's JSON array as one card per option; undefined when it holds none. */
function parseCards(text: string, count: number): Card[] | undefined {
  const json = text.match(/\[[\s\S]*\]/)?.[0]
  if (json === undefined) {
    return undefined
  }

  try {
    const list: unknown = JSON.parse(json)
    if (!Array.isArray(list) || list.length === 0) {
      return undefined
    }

    return Array.from({ length: count }, (_, i) => toCard(list[i]))
  } catch {
    return undefined
  }
}

function toCard(raw: unknown): Card {
  if (typeof raw !== 'object' || raw === null) {
    return PLAIN
  }

  const o = raw as Record<string, unknown>
  const swatches = Array.isArray(o.swatches)
    ? o.swatches
        .filter((c): c is string => typeof c === 'string' && HEX.test(c.trim()))
        .map(c => c.trim())
        .slice(0, 6)
    : []

  return { card: cleanCss(o.card), heading: cleanCss(o.heading), text: cleanCss(o.text), button: cleanCss(o.button), swatches }
}

6. Clean the CSS

Each card's CSS goes into a style attribute, so it can style only its own element. cleanCss removes comments, splits the text into declarations, and keeps only those shaped like property: value that match nothing in BANNED. That list covers url(, @import, expression( and the image functions that can load a file. It also covers braces, angle brackets and backslashes, so a declaration cannot close its rule, leave its attribute, or hide a word behind a CSS escape.

// A declaration with any of these could load a file, run code, or break out of its style attribute.
const BANNED = /url\s*\(|expression\s*\(|@import|image-set|image\s*\(|cross-fade|element\s*\(|javascript:|behavior|binding|[{}<>@\\]/i
const HEX = /^#(?:[0-9a-f]{3,4}|[0-9a-f]{6}|[0-9a-f]{8})$/i
/** Keeps plain "property: value" declarations, and drops any that could load or run something. */
function cleanCss(raw: unknown): string {
  if (typeof raw !== 'string') {
    return ''
  }

  return raw
    .replace(/\/\*[\s\S]*?\*\//g, ' ')
    .split(';')
    .map(d => d.trim())
    .filter(d => /^-?[a-z][a-z-]*\s*:/i.test(d) && !BANNED.test(d))
    .slice(0, 24)
    .join('; ')
}

7. Escape every option text and lock the page down

esc turns &, <, > and both quotes into entities. It is applied to every option label and description, to the question, and to each style attribute. Escaping & also matters for the CSS, because it stops an entity such as &#117; from spelling out url( after the sanitiser has run. The page also carries a Content Security Policy that lets it load nothing and run nothing, so even a missed declaration could not fetch a file.

/** Escapes text for HTML, in an element or inside a quoted attribute. */
function esc(text: string): string {
  return text.replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;').replace(/"/g, '&quot;').replace(/'/g, '&#39;')
}

function page(question: string, options: readonly Option[], cards: readonly Card[]): string {
  const figures = options.map((o, i) => {
    const c = cards[i] ?? PLAIN
    const swatches = c.swatches.map(s => `<span style="background:${s}"></span>`).join('')

    return [
      '<figure>',
      `<div class="card" style="${esc(c.card)}">`,
      `<h2 style="${esc(c.heading)}">${esc(o.label)}</h2>`,
      `<p style="${esc(c.text)}">${esc(o.description ?? '')}</p>`,
      `<button type="button" style="${esc(c.button)}">Get started</button>`,
      `<div class="swatches">${swatches}</div>`,
      '</div>',
      `<figcaption>Option ${i + 1}: ${esc(o.label)}</figcaption>`,
      '</figure>',
    ].join('\n')
  })
    // The page loads nothing and runs nothing, whatever the cards hold.
    `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'">`,

8. Open the page, and reopen the newest

The folder comes from $.env.get("HOME"). The page is opened with the macOS open command through $.process.run, which takes an argument list and no shell, so the path needs no quoting. /design-picker last lists the folder, picks the last name in sorted order, which is the newest page, and opens it.

async function folderOf($: EngineInterface): Promise<string | undefined> {
  const home = await $.env.get('HOME')

  return home === undefined || home === '' ? undefined : `${home}/${FOLDER}`
}

/** macOS's open hands the page to the default browser. */
async function show($: EngineInterface, path: string): Promise<boolean> {
  const run = await $.process.run(['open', path], { timeoutMs: 10000 }).catch(() => undefined)

  return run?.exitCode === 0
}
  on('command.run', { command: 'design-picker' }, async ($, e) => {
    if (e.args.trim() !== 'last') {
      return { text: 'Use /design-picker last to reopen the newest page.' }
    }

    const folder = await folderOf($)
    const entries = folder === undefined ? [] : await $.fs.list(folder).catch(() => [])
    // Names are times, so the last name in order is the newest page.
    const newest = entries
      .filter(entry => entry.kind === 'file' && entry.name.endsWith('.html'))
      .map(entry => entry.name)
      .sort()
      .at(-1)
    if (folder === undefined || newest === undefined) {
      return { text: 'No design picker page yet.' }
    }

    const path = `${folder}/${newest}`
    return (await show($, path)) ? { text: `Opened ${path}` } : { text: `Could not open ${path}. Open it in a browser yourself.` }
  })

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install design-picker@waraxe-claude-mods
  • Nothing to switch on. When Claude asks a design question, the page opens in your browser, and then the dialog appears in Claude Code. Pick there.
  • /design-picker last opens the newest page again. Pages are kept in ~/.claude/design-picker/, one file per question.
  • Cost: one Haiku call for each design question Claude asks. The call sends the question and options plus about 250 tokens of instructions, can return up to 1,500 tokens, and stops after 25 seconds. Other questions make no call.

Limits

  • The page opens with the macOS open command. On another system it is written, but you open it yourself.
  • The dialog waits for the page: it appears after the call and the write finish, usually a few seconds and at most about 25.
  • Only the first question in the dialog that mentions a design word gets cards.
  • The word match is simple: "Does this look right?" counts as a design question too.
  • The page is a static file. It cannot answer the dialog for you.
  • Cards use only fonts installed on your Mac, because the page loads no web fonts.
  • Old pages are not deleted.

Check yourself

The Haiku call comes back with an overloaded error. What does the person see?

Just the normal dialog. $.model.complete resolves with isAnswered: false instead of rejecting, so cards is undefined and preview returns before writing anything. The hook then returns next(e). If something did throw, the .catch on preview, or the hook's own .catch handler, would still pass the call through.

An option is labelled <img src=x onerror=alert(1)>, and the model answers background: url(https://tracker.example/p.png). What reaches the page?

The label appears as plain text, because esc turns its angle brackets into &lt; and &gt;. The declaration is dropped, because it matches url\s*\( in BANNED. Even if a declaration slipped through, the page's Content Security Policy, default-src 'none', would block the image.
