What it is

/challenge opens a pane with today's challenge. The mod picks it by the date from a built-in list of 30 short, practical exercises, such as "Explain a file you have never read" or "Search three folders at once". The pane shows your streak and has three buttons: Coach me asks Claude to walk you through the challenge step by step, Done marks today complete, and Skip moves to tomorrow's challenge. The mod itself makes no model calls.

Your mission asks you to name the hook events and API calls each mod uses, and this one is a small pane mod that uses a store, a session atom and a prompt call, so you can trace each one from start to end.

How it was built

The whole mod is one hooks module, hooks/register.tsx. Each snippet below is copied from it, or from its type contract.

1. Declare the pane's state

The pane draws from one value, view: today's date and the progress read with it. A value in $.state must be declared in the mod's contract, types/index.d.ts, which plugin.json names under "types". claude plugin validate checks every state key the module uses against it.

declare module 'claude-code' {
  interface PluginState {
    'daily-challenge': { view: View }
  }
}

2. Register /challenge when the session starts

A slash command exists only after $.command.register declares it, so the session.start hook does that first and then calls next(e) to let the session go on.

  on('session.start', async ($, e, next) => {
    await $.command.register({
      name: 'challenge',
      description: "Open today's Claude Code challenge, with a coach and a streak",
    })

    return next(e)
  })

3. Pick today's challenge by the date

The date becomes a day number, counted in UTC so that a daylight saving change cannot skip or repeat a day. The day number plus the number of skips, wrapped around the list, gives today's place. That is why Skip moves to tomorrow's challenge: it adds one to the same sum that tomorrow's date would.

/** Today's place in the list and its challenge: the day number plus the skips, wrapped around. */
function pick(current: View): [number, Challenge] {
  const count = CHALLENGES.length
  const index = (((dayNumber(current.today) + current.progress.shift) % count) + count) % count

  return [index, CHALLENGES[index]!]
}

4. Keep the progress in the store

$.store keeps JSON values between sessions, and every session shares them. So each change reads the store again, applies one edit, writes it back, and only then updates the atom that the pane draws from. Done passes markDone as the edit, and Skip passes skip.

/**
 * Reads the progress from the store, applies one change, writes it back, and hands the
 * pane the result. The store is read each time, so two open sessions do not undo each other.
 */
async function change($: EngineInterface, edit: (progress: Progress, today: string) => Progress): Promise<View> {
  const today = dayKey(await $.clock.now())
  const progress = edit(parseProgress(await $.store.get(STORE_KEY)), today)
  await $.store.set(STORE_KEY, progress)
  const current = { today, progress }
  await update($, view, () => current)

  return current
}

5. Draw the three buttons

The ui.render hook for the pane takes its elements from $.ui.resolve(e), so the same tree draws on the terminal, the desktop app, VS Code and mobile. Each Button has its own key, so the surface can find it again after a redraw.

        <Box gap={1}>
          <Button key="coach" label="Coach me" variant="primary" onPress={() => coach($, challenge)} />
          <Button key="done" label={isDone ? 'Done ✓' : 'Done'} onPress={() => change($, markDone)} />
          <Button key="skip" label="Skip" onPress={() => change($, skip)} />
        </Box>

6. Coach me sends a prompt

$.prompt.submit queues an ordinary prompt, which starts its own turn once the session is idle. The mod does not call the model itself. The prompt asks for one step at a time and tells Claude to wait for your reply.

/** Sends a prompt that asks Claude to walk the person through the challenge. */
function coach($: EngineInterface, challenge: Challenge): void {
  void $.prompt.submit({
    text: [
      "Coach me through today's Claude Code challenge, step by step.",
      '',
      `Challenge: ${challenge.title}`,
      challenge.how,
      '',
      'Give me one short step at a time: say exactly what to type or do, and why it helps.',
      'Use this project for the example. Wait for my reply before you give the next step.',
      'When I finish, tell me in one line what I practised.',
    ].join('\n'),
  })
}

7. Count the streak

The streak counts the days marked done in a row. While today is still open, it counts back from yesterday, so a streak does not drop to zero in the morning before you have had a chance to do the challenge.

/** Days done in a row, ending today, or ending yesterday while today is still open. */
function streakOf(doneDays: readonly string[], today: string): number {
  const done = new Set(doneDays)
  let day = done.has(today) ? dayNumber(today) : dayNumber(today) - 1
  let streak = 0
  while (done.has(dayKeyOf(day))) {
    streak += 1
    day -= 1
  }

  return streak
}

How to use it

claude plugin marketplace add <org>/waraxe-claude-mods
claude plugin install daily-challenge@waraxe-claude-mods
  • Run /challenge. The pane opens, and the transcript shows the title of today's challenge.
  • Press Coach me for a step-by-step walkthrough, Done when you have finished, or Skip for the next challenge in the list.
  • There are no settings. The skips and the done days are kept in the plugin store under the key progress.

What it costs. The mod makes no model calls. Coach me sends one ordinary prompt, so it costs one normal turn, the same as typing the prompt yourself. Done and Skip write a small JSON value to the plugin store.

Limits.

  • A day is your computer's local calendar day. An open pane does not roll over at midnight by itself: run /challenge again or press a button.
  • Skip moves the whole list on by one. It does not count as done, and it does not break the streak.
  • Nothing checks that you did the challenge. Done is your own word.
  • The 30 challenges are fixed in the CHALLENGES list in hooks/register.tsx.
  • The progress lives in the plugin store on this machine only.

Check yourself

Why does each press read $.store again, instead of using the view atom it already holds?

The atom belongs to one session, but the store is shared by every session on the machine. If you press Done in one session and Skip in another, each change reads the latest progress from the store first, so neither undoes the other.

The mod makes no model calls. Why does Coach me still cost tokens?

Coach me calls $.prompt.submit, which queues an ordinary prompt. That prompt starts a normal turn, and the model answers it as if you had typed it.
