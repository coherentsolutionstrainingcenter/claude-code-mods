What it is

When Claude hands work to a subagent, it calls the Agent tool, and it often names no model. The subagent then runs on its type's model or the main chat's. model-router steps in at that moment. It sends the task's short description to Haiku, which sorts it as simple, standard or hard, and that one subagent runs on haiku, sonnet or opus. A dim line in the transcript names the label and the model. The main chat keeps its model, so nothing is reread.

The router is off until you type /model-router on.

It serves your mission because a router decides where your task text goes, and you must be able to name that host before you publish: here it is one $.model.classify call through the session's own client, to Anthropic only.

How it was built

The mod is one file, hooks/register.ts. The types offer two places to catch a spawn. A tool.call hook on Agent sees the tool's input, whose model is "sonnet" | "opus" | "haiku" | "fable" or absent. The agent.spawn event fires when the Agent tool is about to start an agent, before its model is resolved, and also says whether the spawn is a fork, a resume, a teammate or a workflow agent. The mod uses agent.spawn, and next({ ...e, model }) sets the model for that one subagent.

1. Map three labels to three models

The labels are what the classifier may answer. modelFor turns a label into a model and returns undefined for anything else, including no answer.

const LABELS = ['simple', 'standard', 'hard'] as const
type Label = (typeof LABELS)[number]
type Choice = 'haiku' | 'sonnet' | 'opus'

const MODEL_FOR: Record<Label, Choice> = { simple: 'haiku', standard: 'sonnet', hard: 'opus' }

/** The model for a label the classifier named; undefined for anything else. */
export function modelFor(label: string | undefined): Choice | undefined {
  const known = LABELS.find(one => one === label)

  return known === undefined ? undefined : MODEL_FOR[known]
}

2. Route only plain spawns

A model Claude named stays. A fork always inherits the parent's model, so a pick would be ignored. A resume cannot change its model. A teammate is a long-lived member of the session's team, and a workflow agent comes from a workflow script, not from Claude's Agent call. An empty description gives the classifier nothing to read.

/** A spawn the router may pick for: no model named, not a fork, a resume, a workflow agent or a teammate. */
export function isRoutable(e: Pick<AgentSpawnInput, 'model' | 'fork' | 'resume' | 'workflow' | 'isTeammate' | 'description'>): boolean {
  return (
    e.model === undefined &&
    !e.fork &&
    e.resume === undefined &&
    e.workflow === undefined &&
    e.isTeammate !== true &&
    e.description.trim() !== ''
  )
}

3. Ask Haiku once

The hook reads the on or off switch first, so an off router makes no call. $.model.classify runs one completion with a fixed classifier prompt and treats the text as data. It resolves one of the labels, or undefined when the answer named none, and it rejects when the request fails. The .catch turns a failure into undefined and writes the reason to the debug log only.

  on('agent.spawn', async ($, e, next) => {
    if (!isRoutable(e) || !(await isOn($))) return next(e)

    const text = `Task given to a coding subagent: ${e.description}`
    // A failed or empty answer leaves the call as Claude made it.
    const label = await $.model.classify(text, LABELS, { model: 'haiku' }).catch((error: unknown) => {
      $.ui.log(`model-router: the classifier failed (${String(error)})`, { to: 'debug' })

      return undefined
    })

4. Set the model for this subagent only

No usable label means no change: the hook counts it and passes the spawn on as Claude made it. Otherwise it writes one line with $.ui.log and passes on a copy with the model. The input describes the subagent alone, and its parentModel is pinned, so the main chat's model cannot change here.

    const model = modelFor(label)
    if (model === undefined) {
      tally.unchanged += 1

      return next(e)
    }

    tally[model] += 1
    $.ui.log(`Model router: "${e.description}" is ${label}, so this subagent runs on ${model}.`)

    // Only this spawn's model changes; the main chat keeps its own.
    return next({ ...e, model })
  })

5. Off by default, with on, off and status

The switch lives in $.store, the mod's own store, and only the value on turns routing on, so a fresh install routes nothing. status reports the switch and a tally kept in the module since it loaded.

async function isOn($: EngineInterface): Promise<boolean> {
  return (await $.store.get('mode')) === 'on'
}

  on('command.run', { command: 'model-router' }, async ($, e) => {
    const asked = e.args.trim().toLowerCase()
    if (asked === 'on' || asked === 'off') {
      await $.store.set('mode', asked)

      return {
        text:
          asked === 'on'
            ? 'Model router is on: each subagent started without a model gets haiku, sonnet or opus.'
            : 'Model router is off: subagents run on the model Claude or their type names.',
      }
    }
    if (asked === 'status' || asked === '') {
      const counts = `${tally.haiku} haiku, ${tally.sonnet} sonnet, ${tally.opus} opus, ${tally.unchanged} left unchanged`

      return { text: `Model router is ${(await isOn($)) ? 'on' : 'off'}. Since it loaded: ${counts}.` }
    }

    return { text: 'Use /model-router on, off or status.' }
  })

How to use it

claude plugin marketplace add <org>/waraxe-claude-mods
claude plugin install model-router@waraxe-claude-mods
  • Type /model-router on. The router is off until you do.
  • Work as usual. Each subagent Claude starts without a model gets a line such as Model router: "Refactor auth module" is hard, so this subagent runs on opus.
  • Type /model-router status to see whether it is on and how many subagents went to each model.
  • Type /model-router off to stop it.

Cost. Each routed subagent costs one Haiku call: the fixed classifier prompt, the few words of the description, and a one-word answer. The types do not give a token count. The model it picks matters more: a simple task on haiku costs less than on opus, and a hard task sent to opus from a Sonnet chat costs more than Sonnet would.

Limits.

  • The classifier sees only the short description (3 to 5 words), not the full prompt, so it can misjudge a task.
  • The pick also replaces an agent type's own model, the model in its definition, because the hook cannot read a type's own model.
  • A setting that forces one model on every subagent outranks the pick.
  • A failed call or an answer outside the three labels leaves the spawn unchanged.
  • A plugin's own $.agent.spawn with no model is routed too.
  • Each routed spawn waits for the Haiku call before the subagent starts.

Check yourself

Why does the router hook agent.spawn and not change the session's model?

A change to the main chat's model makes Claude reread the whole chat, which is why Auto Model (12a) was paused. agent.spawn describes one subagent about to start, and next({ ...e, model }) sets that subagent's model alone. The parent's model is parentModel, which is pinned, and the mod hooks nothing that touches the main chat's requests.

The Haiku call fails, or Haiku answers "medium". What happens to the spawn?

A failed call rejects, and the .catch logs the reason to the debug log and returns undefined. An answer outside the labels makes $.model.classify resolve undefined. Either way modelFor returns undefined, the hook adds one to the "left unchanged" count, and it returns next(e), so the subagent starts as Claude asked.
