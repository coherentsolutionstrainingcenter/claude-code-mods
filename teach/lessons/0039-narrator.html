What it is

Narrator adds a /narrator command with three arguments: on, off and status. When a reply finishes and narrator is on, it takes the reply's final text, strips the Markdown, keeps the last 240 characters, and starts macOS say. It does not wait for say to finish, and it makes no model calls.

This matters for your mission because it is the smaller of the two mods and uses no model call, so it is a clear first example of a hook that reacts to the end of a turn and starts an outside program.

How it was built

The mod is one file, hooks/register.ts, and it uses three hooks. session.start registers the command. command.run handles its arguments. turn.complete reads the reply.

1. Register the command when the session starts

The hook runs once per session. It declares /narrator to the command menu with a short description and an argument hint, then passes the event on.

export const register: Register = on => {
  on('session.start', async ($, e, next) => {
    await $.command.register({
      name: 'narrator',
      description: 'Read the end of each finished reply aloud (off by default)',
      argumentHint: 'on | off | status',
    })

    return next(e)
  })

2. Handle on, off and status

The matcher { command: 'narrator' } limits this hook to the narrator command. The argument is trimmed. on and off write the flag to the mod's store. Any other argument prints the current state, so an unknown argument does not fail.

  on('command.run', { command: 'narrator' }, async ($, e) => {
    const arg = e.args.trim()
    if (arg === 'on' || arg === 'off') {
      await $.store.set('enabled', arg === 'on')
      return { text: `Narrator is ${arg}.` }
    }

    const state = (await $.store.get('enabled')) === true ? 'on' : 'off'
    return { text: `Narrator is ${state}. Use /narrator on, /narrator off or /narrator status.` }
  })
The flag lives in the mod's own store. The engine's type notes say that store is kept between sessions. So /narrator on stays in effect after you restart Claude Code.

3. Read the final reply when the turn ends

turn.complete fires when a turn ends. e.answer is the final visible text. The hook skips subagent replies (e.agentId is set), interrupted turns (e.isAborted), and any turn while the flag is off. It then cleans the text and keeps its tail.

  on('turn.complete', async ($, e, next) => {
    // Subagent replies, interrupted turns and replies with no words are not read.
    if (e.agentId !== undefined || e.isAborted || (await $.store.get('enabled')) !== true) {
      return next(e)
    }

    const words = tail(speakable(e.answer))
    if (words !== '') {
      speak($, words)
    }

    return next(e)
  })

4. Start say and do not wait for it

speak starts say with the words as one argument. The -- ends option parsing, so a reply that starts with a dash is still read. The void and the missing await mean the hook returns at once. Failures are handled later, in .then and .catch.

/** Starts say without waiting: the turn goes on while the voice reads. */
function speak($: EngineInterface, words: string): void {
  // Two minutes: a long enough read that the default 30 s never cuts speech short.
  void $.process
    .run(['say', '--', words], { timeoutMs: 120000 })
    .then(run => {
      if (run.exitCode !== 0) {
        warn($)
      }
    })
    .catch(() => warn($))
}
The missing await is deliberate. The turn does not wait for the voice, so a reply that ends while the last one is still being read starts a second voice. The source does not queue them. The warned flag makes the failure toast appear once per loaded copy of the mod, not once per reply.

5. Turn Markdown into words

Each replace removes one kind of Markdown. Fenced code blocks become a space, so they are not read. For a link, the link text stays and the URL goes. Backticks go, but the text inside them stays.

/** The words of a Markdown reply: code, links, URLs and marks go, the text stays. */
function speakable(markdown: string): string {
  return markdown
    .replace(/```[\s\S]*?(```|$)/g, ' ')
    .replace(/!?\[([^\]]*)\]\([^)]*\)/g, '$1')
    .replace(/\[([^\]]*)\]\[[^\]]*\]/g, '$1')
    .replace(/^ *\[[^\]]+\]:.*$/gm, '')
    .replace(/https?:\/\/\S+/g, ' ')
    .replace(/<\/?[a-zA-Z][^>]*>/g, ' ')
    .replace(/`+/g, '')
    .replace(/^[ \t|:-]{3,}$/gm, ' ')
    .replace(/^[ \t]{0,3}#{1,6}[ \t]+/gm, '')
    .replace(/^[ \t]*>+[ \t]?/gm, '')
    .replace(/^[ \t]*(?:[-*+]|\d+[.)])[ \t]+/gm, '')
    .replace(/\*+|~~/g, '')
    .replace(/(^|\s)_+|_+(?=\s|$)/g, '$1')
    .replace(/\|/g, ' ')
    .replace(/\s+/g, ' ')
    .trim()
}

6. Keep the last 240 characters, from a whole word

Array.from splits the text by code point, so an emoji counts as one character. The function keeps the last 240 characters, then drops everything up to the first space, so the read starts at a word. If those characters hold no space, the whole cut is read, even a partial word.

/** The last characters of the words, from the first whole word: the part read aloud. */
function tail(words: string): string {
  const chars = Array.from(words)
  if (chars.length <= SPOKEN_CHARS) {
    return words
  }

  // The cut can start mid-word: drop that partial word.
  const cut = chars.slice(-SPOKEN_CHARS)
  const space = cut.indexOf(' ')

  return (space === -1 ? cut : cut.slice(space + 1)).join('').trim()
}
Where the README and the source differ.
  • The README says links are left out. The source keeps the link text and removes only the URL. Inline code keeps its text as well.
  • The README says that outside macOS one toast says say is missing. The source has no platform check. It shows its toast whenever say cannot start or exits with an error. The text is "Narrator could not run macOS say, so replies are not read aloud here."
  • The README says narrator is off until you turn it on. That is true at first, but the flag is kept between sessions, so once it is on it stays on after a restart. The README does not say so.
  • The README says a long reply may be read from its second or later sentence. The code cuts at a space, not at a sentence, so a read can start in the middle of a sentence.

How to use it

claude plugin marketplace add coherentsolutionstrainingcenter/claude-code-mods
claude plugin install narrator@waraxe-claude-mods
  • Type /narrator on. Narrator confirms that it is on.
  • Type /narrator status at any time to see the state.
  • Ask a question. When the reply finishes, its last part is read aloud.
  • Type /narrator off to stop. This stops the next reply. Speech that has already started keeps going, because the mod never stops the say process.

Cost. Narrator makes no model calls. The only cost is the local voice.

Limits.

  • In practice it works on macOS only. Elsewhere, the first failed attempt shows one toast, and nothing else changes.
  • Only the last 240 characters of a reply are read. Prompts and tool output are never read. Subagent replies and interrupted turns are skipped.
  • A reply that is only code is not read, because code blocks are left out.
  • Replies can overlap, as described in step 4.
  • The on or off setting is kept between sessions.

Check yourself

Why does turn.complete call speak with void and no await?

The hook returns next(e) at once, so the turn does not wait for the voice to finish reading. Errors are handled afterwards, in .then and .catch, when say exits or fails to start.

Which replies are never spoken, and which check skips each one?

Subagent replies are skipped by e.agentId !== undefined. Interrupted turns are skipped by e.isAborted. A reply with no words after cleaning is skipped because words !== '' is false. A turn is also skipped when the flag is off.

Where is the on or off setting kept, and why does it survive a restart?

It is kept in the mod's own store under the key enabled. The engine's type notes say that store is kept between sessions and hot reloads, so the setting survives a restart.
