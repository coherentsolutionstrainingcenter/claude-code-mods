What it is

time-lapse watches a Claude Code session as it runs and logs each prompt, each tool call and each finished turn. When you run /time-lapse, it turns that log into an animated page you can play and pause in a browser. The whole mod is one TypeScript file, hooks/register.ts, and it makes no model calls.

It matters for your mission in MISSION.md, which asks you to name the hook events and API calls a mod uses and say why, and this one uses five hooks and eight calls in one file.

How it was built

The code has four parts. The steps follow the path of the data: events go in, a log is kept, the log is cut into turns, and a page is drawn.

1. Record events through hooks

The mod registers its hooks with on(...). The session.start hook registers the /time-lapse command. Three other hooks record events, and each keeps only what it needs:

  • prompt.submit keeps the prompt's length. It never keeps the text.
  • tool.call keeps the tool's name. Its arguments are not read.
  • turn.complete keeps the names of the tools used since the main loop last closed a turn, and the turn's duration in milliseconds.

Each event also gets an at time from $.clock.now(). Every hook ends with return next(e), which passes the event on.

  on('prompt.submit', async ($, e, next) => {
    void record($, { at: await $.clock.now(), kind: 'prompt', length: e.text.length })

    return next(e)
  })

  on('tool.call', async ($, e, next) => {
    tools.push(e.tool)
    void record($, { at: await $.clock.now(), kind: 'tool', tool: e.tool })

    return next(e)
  })

  on('turn.complete', async ($, e, next) => {
    // A subagent's turn ends inside the main turn that spawned it, so only the main loop closes one.
    if (e.agentId === undefined) {
      const used = tools
      tools = []
      void record($, { at: await $.clock.now(), kind: 'turn', tools: used, durationMs: e.durationMs })
    }

    return next(e)
  })
README and source differ on prompt length. The README says the log keeps the length in characters. The code uses e.text.length, and JavaScript counts that in UTF-16 code units. For plain text the two match. An emoji, or any character outside the Basic Multilingual Plane, counts as 2.
Why record() is not awaited. The hook returns without waiting for the file write. The source gives no reason in a comment. The likely reason is that a hook should not wait on disk for every prompt. void marks the promise as ignored on purpose. That is safe, because record() ends with a catch, so the promise never rejects.

2. Keep one log file per session

Each session has one file, ~/.claude/time-lapse/<session id>.json, which holds one JSON array. An append reads the whole array, adds one event, and writes the whole array back. The engine's $.fs.write creates the folder if it is missing.

/** Adds one event to this session's log. A failed write drops that event and nothing else. */
function record($: EngineInterface, event: TimeEvent): Promise<void> {
  queue = queue
    .then(async () => {
      const id = await $.session.id()
      const events = await readLog($, id)
      events.push(event)
      await $.fs.write(await sessionFile($, id, 'json'), JSON.stringify(events))
    })
    .catch(() => {})

  return queue
}
Why a queue. Each append reads, then writes. Two appends that started together would both read the same array, and the second write would drop the first event. The queue variable runs each append after the one before it. Each append ends with a catch, so a failed write drops only its own event, and the queue carries on. A file that will not parse is not overwritten: readLog throws, the append fails, and the file stays as it was.

3. Split the log into turns

groupTurns closes a turn at each turn event. Events after the last one form an unfinished turn, and the page still shows it. slotOf gives each turn a playback slot: its real duration, kept between 400 ms and 2 s. An unfinished turn gets the full 2 s. The README says a turn plays in at most two seconds. It does not mention the 400 ms floor, which keeps a quick turn visible.

/** Splits the log into turns, each ending at its turn event. */
function groupTurns(events: TimeEvent[]): Turn[] {
  const turns: Turn[] = []
  let current: TimeEvent[] = []
  for (const event of events) {
    current.push(event)
    if (event.kind === 'turn') {
      turns.push({ events: current, durationMs: event.durationMs })
      current = []
    }
  }
  if (current.length > 0) {
    turns.push({ events: current })
  }

  return turns
}

/** How long a turn plays: its real length, kept between the floor and the cap. */
function slotOf(turn: Turn): number {
  if (turn.durationMs === undefined) {
    return MAX_TURN_MS
  }

  return Math.min(MAX_TURN_MS, Math.max(MIN_TURN_MS, turn.durationMs))
}
Why a subagent's turn does not close the main turn. turn.complete also fires for subagents. The API types say agentId is absent on the main loop, so a subagent's end carries one. A subagent's turn runs inside the main turn that started it. If it closed the main turn, that turn would end early and split in two. The check e.agentId === undefined lets only the main loop close a turn. A subagent's tool calls still count toward the main turn, because the tool.call hook does not check agentId.

4. Render one self-contained HTML page

renderPage builds one section per turn. Each event inside a turn becomes a chip, and the chips are spaced evenly across that turn's slot. Each section and chip gets an animation-delay inline, and the CSS fades it in when that delay ends.

function renderPage(id: string, events: TimeEvent[]): string {
  const turns = groupTurns(events)
  let clock = 0
  const sections = turns.map((turn, n) => {
    const start = clock
    const step = slotOf(turn) / turn.events.length
    clock += slotOf(turn)

    const chips = turn.events.map((event, i) => chip(event, start + i * step)).join('')
    const calls = turn.events.filter(event => event.kind === 'tool').length
    const title = turn.durationMs === undefined ? 'Unfinished turn' : `Turn ${n + 1}`

    return `<section class="turn" style="animation-delay:${Math.round(start)}ms"><h2>${title} · ${calls} tool ${calls === 1 ? 'call' : 'calls'}</h2><ol>${chips}</ol></section>`
  })

The CSS and the script are inline, so the file opens with no network access. The Pause button toggles a paused class on body. The rule body.paused * { animation-play-state: paused; } then freezes every animation.

Only two values in the page are text: the session id and the tool name. Both go through esc, which turns the five characters into numeric entities such as &#38;. Prompt text never reaches the page, because only its length is stored. Every other value is a number.

function esc(text: string): string {
  return text.replace(/[&<>"']/g, char => `&#${char.charCodeAt(0)};`)
}
The page never reads the timestamps. Each event carries an at time, and the README says each event has a timestamp. The page does not read at. Chips inside a turn are spaced by count, not by real time. Only each turn's real duration shapes the page, through its slot.

How to use it

Install the mod from its marketplace. Replace <owner>/<repo> with the GitHub repository that hosts the marketplace. The marketplace folder has no git remote, so that value is not known yet.

claude plugin marketplace add <owner>/<repo>
claude plugin install time-lapse@waraxe-claude-mods
  • Start a session. Recording begins when the plugin loads.
  • Send a prompt or two, and let some tools run.
  • Run /time-lapse. If nothing is recorded yet, it says so and writes no page.
  • Otherwise it writes the replay to ~/.claude/time-lapse/<session id>.html and opens it with open. If open fails, the command shows the path, and you open the file yourself. The folder is created on the first write.
  • The log sits beside it in ~/.claude/time-lapse/<session id>.json. It holds lengths, tool names and durations only.

Cost. No model calls. Each event costs a read and a write of the whole session log.

README and source differ on cost. The README says the only cost is "a small file write per event". The code reads the whole log before each write, so the work per event grows as the session grows.

Limits.

  • Recording starts when the plugin loads, so earlier activity is missing.
  • Playback shows order and rhythm, not exact timing. Each turn is compressed into at most two seconds.
  • Past about 4 MB, the log cannot be read, and recording stops for that session.
Where the 4 MB limit comes from. The mod has no size check. The engine's $.fs.read rejects any file over 4 MiB, and that is what stops recording. Once the read fails, each later append fails too. /time-lapse should also fail at that point, because its read is not caught. The README's "tens of thousands of events" is an estimate, and nothing in the source checks it.

Check yourself

Why does prompt.submit store the prompt's length and not its text?

The mod keeps no prompt or reply text, as the README says. The event keeps only e.text.length, a number, so the log never holds what the user typed.

A subagent finishes a turn. Does that close the main turn?

No. The turn.complete hook checks e.agentId === undefined, and a subagent's end carries an agentId. Its tool calls still count toward the main turn, because the tool.call hook does not check agentId.

The header shows a "Replay runs" time. What does that figure measure?

The sum of the turn slots. Each slot is the turn's real duration, kept between 400 ms and 2 s, and an unfinished turn gets 2 s. It is not how long the session took, and the stored timestamps play no part in it.
