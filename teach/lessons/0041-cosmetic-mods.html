What it is

Each file Claude reads with the Read tool in this session is one meal. The pet has four moods, each with two frames drawn in plain characters on one line: eating (^O^) for a few seconds after each read, hungry (°o°) until it has eaten 8 files, full (^_^) after that, and sleepy (-_-) zZ after 10 idle minutes. Beside the face it says what it is doing, such as Pip is eating register.ts · 3 files eaten. /pet off, /pet on and /pet name <name> control it. It is a toy and makes no model calls.

Your mission asks you to point to the hook events and API calls each mod uses, and this small mod puts five events in one short file: a tool hook, a turn hook, a command, a timer and the band above the prompt.

How it was built

The whole mod is one hooks module, hooks/register.tsx. Each snippet below is copied from it.

1. Count the meals with a hook on Read

A tool.call hook with the matcher { tool: 'Read' } runs around every Read. It calls next(e) first, so the read runs unchanged, and counts a meal only when the result is neither a deny nor an error. The .catch handler replays the read's result if the counting itself fails, so a broken pet can never break a read.

  // Each Read that succeeds is one meal. The count is per session.
  on('tool.call', { tool: 'Read' }, async ($, e, next) => {
    const ran = await next(e)
    if (ran.deny === undefined && ran.isError !== true) {
      const now = await $.clock.now()
      const file = e.file_path.split(/[\\/]/).pop() || e.file_path
      await update($, pet, p => ({ meals: p.meals + 1, lastMealAt: now, lastFile: file, lastActiveAt: now }))
    }

    return ran
  }).catch(($, e, next) => next(e))

2. Work out the mood

The mood depends on the meal count and on time: how long since the last meal, and how long since anything happened. isWorking comes from the band's own props, so the pet stays awake while Claude runs a long turn without reading anything.

/** Eating right after a meal; sleepy when idle; full after enough meals; hungry otherwise. */
function moodOf(state: Pet, now: number, isWorking: boolean): Mood {
  if (now - state.lastMealAt < EAT_MS) {
    return 'eating'
  }
  if (!isWorking && now - state.lastActiveAt >= SLEEP_MS) {
    return 'sleepy'
  }
  if (state.meals >= FULL_AT && now - state.lastMealAt < DIGEST_MS) {
    return 'full'
  }

  return 'hungry'
}

3. Give each mood two frames

The frames are plain characters, one cell each, so they line up the same way in every terminal. The colors are theme keys, so they follow the person's light or dark theme.

// Two frames per mood, swapped on each beat. Plain characters, one cell each.
const FRAMES: Record<Mood, [string, string]> = {
  hungry: ['(°o°)', '(°O°)'],
  eating: ['(^O^)', '(^-^)'],
  full: ['(^_^)', '(-_^)'],
  sleepy: ['(-_-) z', '(-_-) zZ'],
}
// Theme keys, so the colors follow the person's theme.
const COLORS: Record<Mood, string> = { hungry: 'warning', eating: 'success', full: 'claude', sleepy: 'inactive' }

4. Move the frames with a clock

session.start starts $.clock.every(1000, ...). Each tick works out a "beat", a number that changes every second while the pet eats and every 3 seconds otherwise, and writes it to a $.state atom only when it changed. Each write redraws the band, which picks the frame from the beat and works out the mood again, so the pet falls asleep on time with no extra timer.

/** Runs each second. It writes the beat only when it changes, and each write redraws the band. */
async function tick($: EngineInterface): Promise<void> {
  if (!(await read($, settings)).isOn) {
    return
  }

  const value = beatAt(await read($, pet), await $.clock.now())
  if (value !== lastBeat) {
    lastBeat = value
    await update($, beat, () => value)
  }
}

5. Draw the band above the prompt

A ui.render hook on AbovePrompt returns one row: the face in its mood's color, then the caption, cut to fit. When the pet is off, or a survey holds the band, it returns next(e) and draws nothing of its own.

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const prefs = await read($, settings)
    if (!prefs.isOn || e.props.hasSurvey) {
      return next(e)
    }

    const state = await read($, pet)
    const frame = (await read($, beat)) % 2 === 0 ? 0 : 1
    const mood = moodOf(state, await $.clock.now(), e.props.isWorking)
    const { Box, Text } = $.ui.resolve(e)

    return (
      <Box>
        <Text color={COLORS[mood]}>{FRAMES[mood][frame].padEnd(10)}</Text>
        <Text dimColor wrap="truncate">
          {caption(mood, prefs.name, state)}
        </Text>
      </Box>
    )
  })

6. Keep the name and the setting in the store

The meal count lives in $.state, which lasts for the session. The name and the on/off setting must outlast it, so save writes them to $.store as well, and loadSettings reads them back at the next session's start.

async function loadSettings($: EngineInterface): Promise<PetSettings> {
  const isOn = await $.store.get('isOn')
  const stored = await $.store.get('name')
  const name = typeof stored === 'string' ? cleanName(stored) : ''

  return { isOn: isOn !== false, name: name || DEFAULT_NAME }
}

async function save($: EngineInterface, value: PetSettings): Promise<void> {
  await $.store.set('isOn', value.isOn)
  await $.store.set('name', value.name)
  await update($, settings, () => value)
}

7. Answer /pet

The command.run hook splits the arguments into a first word and the rest. on and off flip the setting, and name takes the rest as the new name, with control characters removed and cut to 20 characters.

  on('command.run', { command: 'pet' }, async ($, e) => {
    const [word = '', ...rest] = e.args.trim().split(/\s+/)
    const current = await read($, settings)

    if (word === 'on' || word === 'off') {
      await save($, { ...current, isOn: word === 'on' })
      return { text: word === 'on' ? `${current.name} is back above the prompt.` : `${current.name} is hidden. /pet on brings it back.` }
    }
    if (word === 'name') {
      const name = cleanName(rest.join(' '))
      if (name === '') {
        return { text: `Usage: /pet name <name>, up to ${MAX_NAME} characters.` }
      }
      await save($, { ...current, name })
      return { text: `Your pet is now called ${name}.` }
    }

How to use it

claude plugin marketplace add <org>/waraxe-claude-mods
claude plugin install terminal-pet@waraxe-claude-mods
  • The pet is on by default. Ask Claude to read a file and watch it eat.
  • /pet off hides it and /pet on brings it back.
  • /pet name <name> renames it; the default name is Pip. /pet on its own says how many files it has eaten this session.

What it costs. No model calls. A one-second timer runs while the pet is on, and the band redraws once a second while the pet eats and once every 3 seconds otherwise. The name and the setting are two small values in the plugin store.

Limits.

  • The band above the prompt exists only in the terminal and the desktop app, so the pet does not show in VS Code or on mobile.
  • Only the Read tool counts. Files Claude sees through Grep, Bash or an @-mention are not meals. Reads by subagents do count, and a failed or denied read does not.
  • The meal count starts at 0 in each session.
  • If another mod also draws the band above the prompt, only one of them shows.

Check yourself

Why does the Read hook call next(e) before it counts, and not after?

It needs the result. next(e) runs the read and resolves with what happened, so the hook can skip a read that was denied or failed. Calling it first also means the hook never changes or delays the read itself.

Why is the meal count kept in $.state, but the name in $.store?

$.state lasts for the session and survives a hot reload, which suits a count that should start at 0 in each session. $.store is a file the plugin keeps between sessions, which suits a name and a setting you chose once.
