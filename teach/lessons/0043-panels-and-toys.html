What it is

session-band draws one row above the prompt. It shows the turn number, the output speed of the last response in tokens per second, the cost of the last turn and of the session, how long the 1-hour prompt cache has left since the last answer, and how full the context is. The band gets an amber frame 20 minutes before the cache expires and a red one at 10. At 10 and 5 minutes left, it sends a warning.

It serves your mission because it reads the session's own figures from three turn events and draws them without any model call, so each hook has one clear job.

How it was built

hooks/hooks.json names one module, register.tsx, which holds every hook. The notifier folder is a small macOS app for the cache warning. The steps follow one turn, then the countdown after it.

1. Keep the figures in atoms

An atom is a named value with a starting value. stats holds the turn, speed and costs. cache holds the countdown. isHidden is set by the × button. isBusy is true while a turn runs. warned remembers the last warning. types/index.d.ts gives each key its type.

const stats = atom({ plugin: 'session-band', key: 'stats' } as const, {
  turn: 0,
  speed: null,
  turnCost: null,
  total: 0,
  context: 0,
  costAtStart: 0,
} as Stats)

const cache = atom({ plugin: 'session-band', key: 'cache' } as const, {
  expiresAt: null,
  secondsLeft: null,
} as Cache)

// Closed with ×: stays hidden for the rest of the session.
const isHidden = atom({ plugin: 'session-band', key: 'isHidden' } as const, false)

// A turn is running: the cache stays warm, so no countdown warnings.
const isBusy = atom({ plugin: 'session-band', key: 'isBusy' } as const, false)

// The smallest CACHE_NOTIFY_MINUTES already announced since the last answer; 0 none.
const warned = atom({ plugin: 'session-band', key: 'warned' } as const, 0)

2. Mark the start of each turn

turn.start adds one to the turn number and notes the session's cost so far, so the turn's own cost can be worked out later. It also sets isBusy, which holds back cache warnings while Claude works.

  on('turn.start', async ($, e, next) => {
    const total = (await $.session.usage()).cost?.usd ?? 0
    await update($, stats, s => ({ ...s, turn: s.turn + 1, costAtStart: total, total }))
    await update($, isBusy, () => true)

    return next(e)
  })

3. Time the output speed

turn.step fires for each model request, and it streams. The hook skips subagent requests. For the main thread it loops over the stream itself: the clock starts at the first chunk, and the stop chunk carries the output token count. A reading under 20 tokens, under half a second, or over 1,000 tokens a second is dropped. Every chunk is yielded on unchanged. After the stream, refresh reads the cost and context fill with $.session.usage().

  on('turn.step', async function* ($, e, next) {
    if (e.agentId !== undefined) return yield* next(e)

    // Measured from the response's first item (its envelope, message_start), so
    // time-to-first-token is excluded but thinking that streams hidden or in one
    // late burst is still timed: output_tokens counts it.
    let startedAt: number | null = null

    for await (const chunk of next(e)) {
      if (startedAt === null) {
        startedAt = await $.clock.now()
      }

      if (chunk.kind === 'stop' && chunk.usage !== null) {
        const tokens = chunk.usage.output_tokens
        const seconds = ((await $.clock.now()) - startedAt) / 1000
        const speed = tokens / seconds
        if (tokens >= MIN_TOKENS && seconds >= MIN_SECONDS && speed <= MAX_SPEED) {
          await update($, stats, s => ({ ...s, speed: Math.round(speed) }))
        }
      }

      yield chunk
    }

    await refresh($)
  })

4. Restart the cache countdown when the main turn ends

turn.complete refreshes the figures again. When the main thread's turn ends, the cache deadline is set one hour ahead (CACHE_TTL_MS). isBusy goes back to false, and the warnings re-arm.

  on('turn.complete', async ($, e, next) => {
    const result = await next(e)
    await refresh($)

    if (e.agentId === undefined) {
      const now = await $.clock.now()
      await update($, cache, () => ({ expiresAt: now + CACHE_TTL_MS, secondsLeft: CACHE_TTL_MS / 1000 }))
      await update($, isBusy, () => false)
      await update($, warned, () => 0)
    }

    return result
  })

5. Count down and warn at 10 and 5 minutes

session.start registers /session_data and starts a one-second timer. Each tick works out the seconds left. If this session has no deadline yet, it reads one from another mod's atom: the comment says the Cache mod's deadline seeds this one after a reload. At 10 and at 5 minutes left, each once per answer, it sends a warning. Nothing fires while a turn runs.

    $.clock.every(1000, async () => {
      const expiresAt = (await read($, cache)).expiresAt ?? (await read($, cacheModExpiresAt))
      if (expiresAt === null) return

      const left = Math.max(0, Math.floor((expiresAt - (await $.clock.now())) / 1000))
      if (left !== (await read($, cache)).secondsLeft) {
        await update($, cache, c => ({ expiresAt: c.expiresAt ?? expiresAt, secondsLeft: left }))
      }

      const due = CACHE_NOTIFY_MINUTES.filter(m => left > 0 && left <= m * 60)
      if (due.length === 0 || (await read($, isBusy))) return

      const minutes = Math.min(...due)
      const last = await read($, warned)
      if (last !== 0 && last <= minutes) return

      await update($, warned, () => minutes)
      await notifyCacheExpiry($, Math.ceil(left / 60))
    })

6. Send the warning

The warning text is "Prompt cache expires in N min". If the notifier app was built, the mod runs it with a title made of the project folder and, in the desktop app, the session title. In the desktop app, a click on it opens the session through a claude:// link. If the notifier is missing or fails, the mod calls Claude Code's own PushNotification tool with $.tool.call. If that is not delivered either, a toast shows the text for 30 seconds.

const notifyCacheExpiry = async ($: EngineInterface, minutes: number) => {
  const project = (await $.session.cwd()).split('/').filter(Boolean).pop() ?? 'session'
  const message = `Prompt cache expires in ${minutes} min`

  const notifier = `${$.plugin.root}/${NOTIFIER}`
  if (await $.fs.exists(notifier)) {
    const session = await desktopSession($)
    const argv = [
      notifier,
      '-title',
      session?.title ? `${project} — ${session.title}` : project,
      '-message',
      message,
      '-group',
      `session-band-${session?.id ?? (await $.session.id())}`,
      ...(session ? ['-open', `claude://code/continue?session=${session.id}`] : []),
    ]
    // The first run waits while macOS asks whether to allow its notifications.
    const ran = await $.process.run(argv, { timeoutMs: 60_000 }).catch(() => null)
    if (ran?.exitCode === 0) return
  }

7. Draw the band to fit the width

The AbovePrompt hook passes while a survey is open, before the first turn, or while the band is hidden. While Claude works, the cache shows … and has no frame. Otherwise the frame turns amber at 20 minutes left and red at 10. tierFor picks a density from bodyColumns: the comment says the row drops details as it narrows instead of wrapping. Icons are SVG where the surface has an Svg element, and plain glyphs elsewhere.

  on('ui.render', { component: 'AbovePrompt' }, async ($, e, next) => {
    const s = await read($, stats)
    if (e.props.hasSurvey || s.turn === 0 || (await read($, isHidden))) return next(e)

    const ui = $.ui.resolve(e)
    const { Box, Button, Text } = ui
    const Svg = 'Svg' in ui ? ui.Svg : null
    const speed = s.speed === null ? '—' : `${s.speed} tok/s`
    const turnCost = s.turnCost === null ? '—' : usd(s.turnCost)

    const { secondsLeft } = await read($, cache)
    const level =
      e.props.isWorking || secondsLeft === null
        ? null
        : secondsLeft <= CACHE_ALERT_S
          ? ALERT
          : secondsLeft <= CACHE_WARN_S
            ? WARN
            : null
    const cacheColor = level ?? CACHE
    const cacheText =
      e.props.isWorking ? '…'
      : secondsLeft === null ? '—'
      : secondsLeft === 0 ? 'expired'
      : `${pad(Math.floor(secondsLeft / 60))}:${pad(secondsLeft % 60)}`

    lastColumns = e.props.bodyColumns
    const tier = tierFor(e.props.bodyColumns)
    const icon = tier >= 3 ? 18 : 22

How to use it

claude plugin marketplace add <org>/waraxe-claude-mods
claude plugin install session-band@waraxe-claude-mods

Replace <org> with the GitHub owner of this marketplace. The marketplace README says to run /reload-plugins or start a new session after the install.

  • The band appears once the first turn starts.
  • /session_data shows or hides the band. The × on the band hides it for the rest of the session.
  • /session_data demo <minutes> pretends the cache has that many minutes left, to preview the colors and the warning. The next answer resets it.
  • The notifier (macOS) is built once, with Xcode's command line tools. The README gives this command: 
    plugins/session-band/notifier/build.sh
    It builds notifier/Session Band.app next to the script, with the icon taken from your installed Claude.app. Build it in the folder the mod is loaded from, or copy the built app there. On its first notification, macOS asks whether to allow notifications from "Session Band".
  • Without the notifier, or on another OS, the mod falls back to Claude Code's own notification. The README says it also reaches your phone over Remote Control, but has no title or click-through. When you are already at the session, that one is skipped and a toast says it instead.
  • Settings: none. The manifest declares no userConfig.
  • Cost: no model call. The band reads $.session.usage(), and the warning runs a local app or Claude Code's notification tool.

Limits

  • The countdown assumes a 1-hour cache from the last main answer. It is a timer kept by the mod, set one hour ahead after each main answer.
  • Speed counts only main-thread responses. Short or one-burst responses are not timed, so the speed can stay at the last good reading.
  • The notifier is macOS only. In the desktop app it reads the session title from a file under ~/Library/Application Support/Claude/claude-code-sessions.
  • The types say AbovePrompt is raised on the terminal and desktop surfaces only.

Check yourself

Why does the turn.step hook loop with for await and yield chunk, instead of returning next(e)?

It needs to see the stream. The first chunk starts the clock, and the stop chunk gives the output tokens. Yielding each chunk passes it on unchanged, so the response is the same as without the mod.

The cache has 8 minutes left and Claude is in the middle of a turn. Does a warning fire?

No. turn.start set isBusy, and the timer returns before warning while it is true. The band shows … for the cache. When the main turn ends, the countdown restarts at one hour and the warnings re-arm.
